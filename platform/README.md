# Commonplace U1: isolated access foundation

Status: implementation for review, **not deployed or enabled**. Baseline main: `0239b93` (U0 merged in PR #72). No existing application page imports these modules. There is no project URL, key, signup hook, deployed function, real account seed, automatic migration runner or hosting change here.

## Delivered

- Additive PostgreSQL migration: verified-UUID membership; active/suspended/revoked learners; one designated administrator; stable section hierarchy; explicit leaf allow/deny grants; isolated study records; server-written administration audit.
- RLS and least-privilege API grants. Learners cannot write membership, grants, catalogue or audit tables. Only the administrator can call the two mutation RPCs, with fresh database authorization. Definer functions use an empty search path and fully qualified references; private helpers avoid recursive membership policies. `cp_private` must never be exposed as a Data API schema.
- Controlled owner bootstrap: operator-only function, confirmed auth account required, one-time unique owner, no first-signup or metadata-based promotion. The admin API cannot demote, revoke, delete or replace the owner. Account deletion is restricted by foreign keys. Owner transfer/recovery requires a separately reviewed operator procedure; database owners and privileged service credentials are trusted and are not constrained like learners.
- New project/UUID-scoped local store, invalidated operation tickets, abort signals, validated same-owner backups, conservative fill-missing restore, no automatic adoption/deletion of legacy work.
- Opt-in `learner-context.mjs`: verifies with `auth.getUser()`, reads fresh membership and RLS-filtered catalogue, fails closed online, invalidates storage tickets on auth events and ignores late responses. Returns a single-section landing ID when applicable. No OAuth implementation replacement.
- Repeatable local security tests and a credential-free CI workflow. PGlite executes real PostgreSQL grants/RLS/functions in isolation; the tests provide a minimal `auth.users`/`auth.uid()` fixture and use `SET ROLE`.

## Run locally

From repository root, with Node 22:

```sh
npm ci --prefix platform --ignore-scripts
npm test --prefix platform
```

Tests create an ephemeral database, never connect to Supabase. The SQL migration filename was generated by `supabase migration new u1_access_foundation --workdir platform`. It is intentionally not in an existing application's migration directory. Do not apply it to General_apps automatically.

## API contract

| Interface | Intended caller / behavior |
| --- | --- |
| `cp_memberships` SELECT | Own membership (including inactive status), or administrator; no learner directory |
| `cp_sections` SELECT | Allowed leaves and their containing hubs; administrator can see full catalogue |
| `cp_section_grants` SELECT | Own decisions or administrator; inactive grants are not effective access |
| `cp_set_learner(target, new_status, new_name)` | Active administrator only; existing confirmed auth UUID; learner role fixed; no identity creation |
| `cp_set_section_grant(target, section, new_decision)` | Active administrator only; explicit existing study leaf; `allow` or `deny` |
| `cp_study_state` CRUD | Own records in currently permitted study sections only; administrator cannot read another user's notes |
| `cp_audit` SELECT | Administrator only; actor taken from `auth.uid()`; writes atomic with successful admin operations |
| `cp_private.bootstrap_owner(target)` | Trusted database operator only, never frontend or normal API role |

The catalogue is seeded from [U0 inventory](../docs/admin-platform/SECTION-INVENTORY.md). Catalogue changes are reviewed migrations in U1; future editing needs cycle validation and audit. Group/inherited permissions are not implemented yet. Parent selection in U2 must expand a reviewed snapshot into explicit leaf decisions; there is no wildcard, so new sections remain denied. Planned courses cannot be granted. A section grant does **not** authorize a material, file or code-execution request: publishing/assignment checks and private Storage belong to U4/U6. Existing public static lessons remain public.

`cp_study_state` is a new bounded record contract, not a migration of legacy progress or a complete synchronization engine. It has no conflict revision protocol yet. Adapters must add optimistic concurrency before cloud sync activation, preserve old IDs and validate section-specific payloads. Imported payloads remain untrusted and must never be rendered as raw HTML or executed in the application's origin.

## Account and offline boundary

Future adapters construct `createAccountStore(storage, projectNamespace)` using a fixed deployment namespace, then `createLearnerContext({enabled: true, client, store})` only after the deployment is approved. Use a fresh ticket for each operation; pass its `signal` to supported requests and check ownership before all writes. Do not expose a generic arbitrary-key storage importer.

The adapter deliberately requires online verification on refresh. It must **not** replace the existing offline gate. U8 must add explicitly owned offline leases, cross-tab account-change coordination, private cache/queue isolation, reconnect handling and physical iPad checks before activation. LocalStorage namespaces are accident prevention, not encryption or an XSS boundary. Users sharing a device can inspect saved bytes outside the app. Previously downloaded/exported materials cannot be recalled remotely.

Backup format: `{format: "commonplace-study", version: 1, project, owner, records}`. Records contain exactly `section`, `kind`, `id`, and an object `value`; allowed kinds are progress/bookmark/highlight/note. Exports only enumerate the current owned namespace, never global token/gate/role keys. Same-account/project imports validate the complete input before writing, reject duplicate IDs and retain existing records. Quota errors can leave a valid partial import; retry fills missing records. Cross-project migration requires a separately verified ownership mapping; editing the backup's identity is not a supported migration procedure. No legacy storage is adopted automatically.

## Deployment gates and next U1 work

This PR implements the isolated schema/contracts/storage portion of U1. **U1 release acceptance remains open**:

1. Choose and approve the isolated backend/origin, or remediate the existing shared project's exposed surface. No resources have been provisioned and no costs approved.
2. Verify recoverable database, auth and Storage backups of any backend to be modified, plus safe device progress exports. Record checksums and demonstrate restore. No backup evidence is asserted here.
3. Test this migration in a disposable full Supabase stack/staging target. Inspect effective default grants, exposed schemas, PostgreSQL version, API configuration and security advisors. Test real signed JWTs for anonymous, two learners, owner and revoked learner against REST/RPC; test concurrent admin mutations and transaction isolation. PGlite is not PostgREST, GoTrue or Storage and does not prove these integrations.
4. Confirm the designated owner's UUID and confirmed identity in that target. A privileged operator runs `cp_private.bootstrap_owner` with the verified UUID once; keep identity values out of public migrations. Failed/unauthorized operations need platform request/security logs in addition to the successful-action audit.
5. Configure and test existing Google login behavior against the target origin/callback allowlist, including iPad Home Screen returns. Never migrate token records across projects.
6. Implement private material/file delivery before inviting learners to restricted content. Test anonymous/direct URL/Storage requests, stale signed URLs, revoked assignments and published-state checks. No private bucket or signed URL endpoint is created here, and U1 does not retrofit confidentiality onto public GitHub files.
7. Complete CAS progress sync, cross-tab handling, offline ownership/lease integration and application adapter tests before enabling the boundary. Main Admin Studio is U2; profiles U3; Excel adapter U7.

Rollback: until activation, revert this code PR without touching live data. After an isolated pilot, disable the new route/adapters and retain its data, audit and offline queues; do not drop tables or clear devices. Restore/reconcile through a reviewed procedure. Existing Commonplace remains the legacy study environment during the pilot.

Excel coordination: #68/#69 are in the baseline; #70 was rechecked on 2026-11-24 and remains open against `feat/excel-study-phase-a`. This PR changes no Excel files, gate, service worker or offline manifests. Excel must consume central context later; it must not create another role system.
