Chapter 9 — Unsupervised Learning Techniques

In one line
Most real data has no labels. Clustering (K-Means, DBSCAN) groups similar points, and Gaussian mixtures model the data's density. Together they let you segment, compress, pre-label and spot anomalies without anyone labelling the data first.

The chapter opens with a factory example: thousands of product photos arrive daily, but labelling them "defective / OK" by hand is slow and has to be redone whenever the product changes. That is the motivation for learning from unlabelled data.

1 · Clustering book p. 236 ↗

Clustering assigns each instance to a group (a cluster) of similar instances. It looks like classification, but there are no target labels: the algorithm has to discover the groups itself.

What it's used for

  • Customer segmentation: group users by behaviour, tailor products, feed recommender systems.
  • Data analysis: cluster a new dataset first, then study each cluster separately.
  • Dimensionality reduction: replace each instance with its affinity to each of the k clusters, which gives a k-dimensional vector.
  • Anomaly (outlier) detection: an instance with low affinity to every cluster is suspicious (fraud, defects).
  • Semi-supervised learning: spread a few labels to the rest of their cluster.
  • Search engines: find the cluster of a query image and return its members.
  • Image segmentation: cluster pixel colours to simplify an image.
There is no single definition of a "cluster". Some algorithms look for points around a centroid, some for connected dense regions of any shape, and some for a hierarchy of clusters within clusters. The algorithm you pick decides what counts as a cluster.

K-Means book p. 238 ↗

K-Means finds k centroids and assigns every instance to the nearest one. It is simple, fast, and usually converges in a handful of iterations. You must choose k yourself.

from sklearn.cluster import KMeans
km = KMeans(n_clusters=5, random_state=42)
labels = km.fit_predict(X)     # same array as km.labels_
km.cluster_centers_            # (5, n_features) centroids
km.predict(X_new)              # nearest centroid for new points
km.transform(X_new)            # distance to every centroid, shape (m, 5)
  • In clustering, an instance's "label" is just the index of its cluster. It is not a class label.
  • The regions closest to each centroid form a Voronoi tessellation, so the decision boundaries between clusters are straight lines.
  • Hard clustering gives each point one cluster. Soft clustering gives each point a score per cluster, such as its distance from each centroid (transform()) or a similarity like a Gaussian RBF.
  • transform() turns n features into k distances. That makes it a cheap nonlinear dimensionality reduction.
  • K-Means only looks at the distance to each centroid, so it mislabels points when the blobs have very different diameters.
Stuart Lloyd devised the method at Bell Labs in 1957 but only published it in 1982. Edward Forgy published essentially the same algorithm in 1965, so it is sometimes called Lloyd–Forgy.

How the algorithm works book p. 241 ↗

If you knew the centroids, labelling would be easy. If you knew the labels, finding the centroids would be easy. K-Means starts with a guess and alternates between the two:

  1. Initialise k centroids (for example k random instances).
  2. Assign: give each instance the label of its nearest centroid.
  3. Update: move each centroid to the mean of the instances assigned to it.
  4. Repeat 2–3 until the centroids stop moving.

Each step lowers (or keeps) the inertia, the total squared distance from each point to its centroid:

$$\text{inertia}=\sum_{i=1}^{m}\big\|\mathbf x^{(i)}-\boldsymbol\mu_{c^{(i)}}\big\|^2\qquad c^{(i)}=\arg\min_j\big\|\mathbf x^{(i)}-\boldsymbol\mu_j\big\|$$
  • It is guaranteed to converge in a finite number of steps, because inertia can't increase and there are only finitely many labellings.
  • It can converge to a local optimum. The result depends on where the centroids started.
  • Complexity: roughly linear in m, k and n when the data really has cluster structure. In pathological cases it can be exponential in m, but this is rare in practice.

Centroid initialisation book p. 243 ↗

  • You know roughly where the centres are? Pass them as an array: KMeans(n_clusters=5, init=my_centres, n_init=1).
  • Multiple restarts: n_init runs the whole algorithm several times and keeps the run with the lowest inertia (km.inertia_).
  • km.score(X) returns minus the inertia, because scikit-learn's rule is "higher score = better".

k-means++ (Arthur & Vassilvitskii) picks starting centroids that are spread out:

  1. Choose the first centroid uniformly at random from the data.
  2. Choose each next centroid from the instances with probability proportional to $D(\mathbf x)^2$, the squared distance to the nearest centroid already chosen:
    $$P\big(\mathbf x^{(i)}\big)=\frac{D\big(\mathbf x^{(i)}\big)^2}{\sum_{j=1}^{m}D\big(\mathbf x^{(j)}\big)^2}$$
  3. Repeat until you have k centroids.
k-means++ is the default (init="k-means++"). The extra seeding work pays off because far fewer restarts are needed. Use init="random" only for comparison. scikit-learn actually runs a "greedy" version: it draws a few candidates at each step and keeps the one that lowers the total $D^2$ the most.

Accelerated and mini-batch K-Means book p. 244 ↗

  • Elkan's K-Means uses the triangle inequality and keeps upper and lower distance bounds, so it can skip many distance computations. Select it with algorithm="elkan".
  • Mini-batch K-Means (Sculley) moves the centroids a little using a small random batch at each step. It is often 3–4× faster and can handle data that doesn't fit in memory: MiniBatchKMeans(n_clusters=5).
  • Its inertia is slightly worse, and the gap matters more as k grows.
  • For out-of-memory data, use a NumPy memmap, or feed batches to partial_fit(). With partial_fit() you must handle multiple initialisations yourself.

Choosing k book p. 245 ↗

A bad k gives a bad model: too small merges real clusters, and too large chops real clusters into pieces.

You can't pick k by minimising inertia. Inertia always drops as k grows, and reaches 0 when k = m.
  • Elbow method: plot inertia against k and look for the "elbow" where the curve stops falling steeply. It is quick but coarse.
  • Silhouette score: the mean silhouette coefficient over all instances (sklearn.metrics.silhouette_score(X, labels)). It is more precise but costs $O(m^2)$.
$$s^{(i)}=\frac{b-a}{\max(a,b)}\in[-1,1]$$
  • a = mean distance to the other points in the same cluster
  • b = mean distance to the points of the nearest other cluster
  • ≈ +1: deep inside its cluster · ≈ 0: on a boundary · ≈ −1: probably in the wrong cluster

A silhouette diagram plots every instance's coefficient, sorted and grouped by cluster, so each cluster appears as a "knife" shape. The height of a knife shows the cluster's size and its width shows how good its members' coefficients are. A dashed line marks the mean score.

Reading a silhouette diagram: a cluster whose points mostly fall short of the mean line is weak. If two values of k have similar scores, prefer the one whose clusters are all good and of similar size. n_init now defaults to "auto" (scikit-learn ≥ 1.4). That means 1 run with k-means++ and 10 runs with init="random". The book assumes 10. Set n_init=10 yourself if you want several restarts.
algorithm is now "lloyd" (the default) or "elkan". The old "auto" and "full" options were removed ("full" is now called "lloyd"). Elkan is not the default any more.
HDBSCAN is now built in: sklearn.cluster.HDBSCAN (≥ 1.3), so you no longer need the contrib package. scikit-learn's inertia_ is the sum of squared distances, not their mean, so its value grows with the size of the dataset.

What to try
  • Run with random init and k = 5, pressing New init before each run. Some runs get stuck with two ✕ in one blob and one ✕ between two blobs: that's a local optimum.
  • Switch to k-means++. Bad starts become rare, because the starting ✕ are already spread out.
  • Look at the lower chart: inertia keeps falling as k grows, but the silhouette score peaks at the true k.
  • Choose uneven blobs: the big, spread-out blob gets split while two small, close blobs get merged. K-Means favours clusters of similar size.

Limits of K-Means book p. 248 ↗

  • It needs several runs to avoid bad local optima, and you must choose k.
  • It works poorly on clusters with different sizes, different densities, or non-spherical (elongated) shapes. A wrong solution can even have lower inertia than the right one.
  • Gaussian mixtures handle elliptical clusters much better (section 2).
Scale the features before running K-Means. Otherwise the clusters get stretched along the large-scale features. Scaling doesn't make clusters round, but it usually helps.

Clustering for image segmentation book p. 249 ↗

  • Image segmentation: split an image into segments.
    • Semantic segmentation: every pixel of the same object type (for example "pedestrian") goes into one segment.
    • Instance segmentation: each individual object gets its own segment.
    • The state of the art for both uses CNNs (ch 14).
  • Colour segmentation is much simpler: cluster the pixels by RGB value and paint each pixel with its cluster's mean colour. That is often enough for tasks like measuring forest area in satellite images.
pixels = img.reshape(-1, 3)                    # (H*W, 3) list of colours
km = KMeans(n_clusters=8, n_init=3).fit(pixels)
seg = km.cluster_centers_[km.labels_].reshape(img.shape)
A small but vivid object (like a red ladybug) may not get its own colour cluster when k is small. K-Means prefers clusters of similar size, so a small colour region gets merged into a bigger one.

Clustering for preprocessing book p. 251 ↗

Put KMeans inside a pipeline before a classifier. Its transform() replaces each 64-pixel digit image with its distances to k centroids.

pipe = Pipeline([("kmeans", KMeans(n_clusters=50)),
                 ("clf", LogisticRegression(max_iter=5000))])
grid = GridSearchCV(pipe, {"kmeans__n_clusters": range(2, 100)}, cv=3)
  • Here k is just a hyperparameter of the pipeline. Choose it by cross-validated accuracy, not by elbow or silhouette.
  • Use more clusters than classes (50 rather than 10), because each digit can be written in several different styles.
  • In the book this cut the logistic regression error on load_digits by roughly a third.

Clustering for semi-supervised learning book p. 253 ↗

Setting: plenty of unlabelled data, and a budget to label only about 50 instances.

  1. Label smartly: cluster the data into k = 50 clusters and label only the representative instance of each (the point closest to its centroid, np.argmin(km.fit_transform(X), axis=0)). In the book this beat 50 random labels by about 9 accuracy points.
  2. Label propagation: copy each representative's label to every member of its cluster.
  3. Partial propagation: copy it only to the members closest to the centroid (for example the nearest 20%). Points near cluster boundaries are the ones most likely to get a wrong label.
The labels propagated to the nearest 20% were about 99% correct, which is why training on them works so well. scikit-learn also provides graph-based propagation in sklearn.semi_supervised (LabelPropagation, LabelSpreading, SelfTrainingClassifier). Unlabelled points are marked with -1.

Active learning book p. 255 ↗

Active learning: the model asks a human to label the specific instances it would learn most from. The most common strategy is uncertainty sampling:

  1. Train on the labels you have, then predict the unlabelled pool.
  2. Send the instances with the lowest confidence (lowest top probability) to the expert.
  3. Repeat until the accuracy gain is no longer worth the labelling effort.

Other strategies: label the points that would change the model most, or reduce validation error most, or that several different models disagree on.

DBSCAN book p. 255 ↗

DBSCAN defines a cluster as a continuous region of high density, so clusters can have any shape.

  • ε-neighbourhood: all instances within distance eps of a point.
  • Core instance: has at least min_samples instances in its ε-neighbourhood, counting itself.
  • Every point in a core instance's neighbourhood joins that core's cluster. Chains of neighbouring cores merge into one cluster.
  • A border point is not a core but lies near one. A point with no core in its neighbourhood is an anomaly and gets label -1.
db = DBSCAN(eps=0.2, min_samples=5).fit(X)
db.labels_                # cluster index per point, -1 = noise
db.core_sample_indices_   # which rows are core instances
db.components_            # the core instances themselves
  • DBSCAN has no predict(), only fit_predict(). To assign new points, train a classifier (for example KNeighborsClassifier) on the core instances, and treat a point as an anomaly if its nearest core is farther than some distance (use knn.kneighbors()).
  • Strengths: it finds any number of clusters of any shape, it handles outliers, and it has only two hyperparameters.
  • Weakness: if density varies a lot between clusters, a single eps can't capture them all.
  • Cost: about $O(m\log m)$ time, but scikit-learn's version can use up to $O(m^2)$ memory when eps is large.
  • HDBSCAN (hierarchical DBSCAN) tries every density level and keeps the most stable clusters, so it copes with varying density and you don't have to set eps. It is now available as sklearn.cluster.HDBSCAN.

2 · Gaussian mixtures book p. 260 ↗

A Gaussian mixture model (GMM) assumes the data came from k Gaussian distributions with unknown parameters. Each Gaussian produces an ellipsoid-shaped cluster, and each cluster can have its own size, shape, density and orientation.

The generative story that GaussianMixture assumes:

$$z^{(i)}\sim\text{Categorical}(\boldsymbol\phi)\qquad \mathbf x^{(i)}\mid z^{(i)}=j\;\sim\;\mathcal N\big(\boldsymbol\mu^{(j)},\boldsymbol\Sigma^{(j)}\big) \qquad p(\mathbf x)=\sum_{j=1}^{k}\phi^{(j)}\,\mathcal N\big(\mathbf x;\boldsymbol\mu^{(j)},\boldsymbol\Sigma^{(j)}\big)$$
  • $\phi^{(j)}$ = cluster weight (the probability of choosing cluster j). The weights sum to 1.
  • $\mathbf x^{(i)}$ are observed variables. The cluster choices $z^{(i)}$ are hidden: they are latent variables.
  • The book draws this as a graphical model in plate notation: circles are random variables, squares are fixed parameters, plates show repetition, shaded nodes are observed, and a squiggly arrow is a "switch" chosen by $z$.

Expectation-Maximization (EM)

EM is like K-Means with soft assignments. It also learns each cluster's covariance (shape) and weight.

  • E-step: for every instance, compute the responsibility of each cluster, i.e. the probability that the instance belongs to it:
    $$\gamma_{ij}=\frac{\phi^{(j)}\,\mathcal N(\mathbf x^{(i)};\boldsymbol\mu^{(j)},\boldsymbol\Sigma^{(j)})}{\sum_{l}\phi^{(l)}\,\mathcal N(\mathbf x^{(i)};\boldsymbol\mu^{(l)},\boldsymbol\Sigma^{(l)})}$$
  • M-step: update each cluster using all instances, each weighted by its responsibility:
    $$\phi^{(j)}=\tfrac1m\textstyle\sum_i\gamma_{ij}\quad \boldsymbol\mu^{(j)}=\dfrac{\sum_i\gamma_{ij}\mathbf x^{(i)}}{\sum_i\gamma_{ij}}\quad \boldsymbol\Sigma^{(j)}=\dfrac{\sum_i\gamma_{ij}(\mathbf x^{(i)}-\boldsymbol\mu^{(j)})(\mathbf x^{(i)}-\boldsymbol\mu^{(j)})^\top}{\sum_i\gamma_{ij}}$$
from sklearn.mixture import GaussianMixture
gm = GaussianMixture(n_components=3, n_init=10, random_state=42).fit(X)
gm.weights_, gm.means_, gm.covariances_
gm.converged_, gm.n_iter_
gm.predict(X)          # hard clustering
gm.predict_proba(X)    # soft clustering (responsibilities)
X_new, y_new = gm.sample(6)   # generate new points (sorted by cluster)
gm.score_samples(X)    # log of the PDF at each point
EM can get stuck in poor solutions, just like K-Means, but GaussianMixture's n_init defaults to 1. Set it higher yourself.
  • A GMM is a generative model: you can sample new instances from it.
  • score_samples() returns a log density, not a probability. Densities can be greater than 1. To get a probability you integrate the density over a region; over the whole space the integral is 1.
  • With many dimensions, many clusters or few instances, EM struggles. You can help it by restricting the covariance matrices, which leaves fewer parameters to learn.
covariance_typeCluster shapes allowedTraining cost
"full" (default)any shape, size and orientation; each cluster has its own matrix$O(kmn^2+kn^3)$
"tied"all clusters share one covariance matrix (same shape, size and orientation)$O(kmn^2+kn^3)$
"diag"any ellipsoid, but its axes must be parallel to the feature axes$O(kmn)$
"spherical"round clusters, each with its own variance$O(kmn)$
With many features, "full" and "tied" become expensive (cubic in n). Use "diag" or "spherical", or reduce the dimensions first (ch 8).

Anomaly detection with a GMM book p. 266 ↗

Anomaly (outlier) detection: find instances that deviate strongly from the norm. The normal instances are the inliers. With a GMM, a point in a low-density region is an anomaly.

dens = gm.score_samples(X)
threshold = np.percentile(dens, 4)   # expect about 4 % defects
anomalies = X[dens < threshold]
  • Pick the threshold from the known anomaly rate, then adjust it. Too many false positives → lower it. Too many missed anomalies → raise it. This is the usual precision/recall trade-off (ch 3).
  • Novelty detection assumes the training set is clean (no outliers) and flags new points that look different. Anomaly detection makes no such assumption, and is often used to clean a dataset.
  • A GMM tries to fit the outliers too. If there are many, they distort what "normal" looks like. Fix: fit, remove the most extreme outliers, then refit. Or use a robust estimator such as EllipticEnvelope.

Choosing the number of clusters book p. 267 ↗

Inertia and silhouette assume round clusters of similar size, so they are unreliable for GMMs. Instead, minimise an information criterion:

$$\text{BIC}=p\log m-2\log\hat L\qquad\qquad \text{AIC}=2p-2\log\hat L$$
  • m = number of instances, p = number of learned parameters, $\hat L$ = the maximised likelihood of the model.
  • Both reward a good fit and penalise extra parameters. BIC's penalty grows with log m, so it tends to pick simpler models than AIC, especially on big datasets.
  • In scikit-learn: gm.bic(X) and gm.aic(X). You can search over covariance_type the same way.
Probability vs likelihood, MLE vs MAP book p. 268 ↗
  • Probability: θ is fixed and x varies. How plausible is an outcome x? A PDF integrates to 1 over x.
  • Likelihood $\mathcal L(\theta\mid x)=f(x;\theta)$: x is fixed (already observed) and θ varies. How plausible are these parameter values? It is not a distribution over θ, and its integral over θ can be any positive number.
  • MLE (maximum likelihood estimation): choose the θ that maximises $\mathcal L$. MAP (maximum a-posteriori): maximise $\mathcal L(\theta\mid x)\,g(\theta)$ with a prior g, which acts like regularised MLE.
  • In practice you maximise the log-likelihood: it has the same maximiser, and it turns a product over independent instances into a sum.

Bayesian Gaussian mixtures book p. 270 ↗

BayesianGaussianMixture removes unneeded clusters for you. Set n_components to a number you are sure is too large, and the weights of the extra clusters shrink to about 0.

from sklearn.mixture import BayesianGaussianMixture
bgm = BayesianGaussianMixture(n_components=10, n_init=10, random_state=42).fit(X)
np.round(bgm.weights_, 2)   # most weights end up at 0.0
  • Here the cluster parameters (weights, means, covariances) are latent random variables with priors, not fixed values.
  • weight_concentration_prior encodes your prior belief: low → few clusters, high → many clusters. The more data you have, the less the prior matters.
  • The default weight prior is a stick-breaking process (Dirichlet process). Break off a Beta-distributed fraction of the remaining "stick" for each successive cluster, so big clusters tend to keep growing. A Wishart prior generates the covariance matrices.

By Bayes' theorem, the posterior over the latent variables is:

$$p(\mathbf z\mid\mathbf X)=\frac{p(\mathbf X\mid\mathbf z)\,p(\mathbf z)}{p(\mathbf X)}\qquad p(\mathbf X)=\int p(\mathbf X\mid\mathbf z)\,p(\mathbf z)\,d\mathbf z\ \ (\text{intractable})$$
  • Variational inference: choose a family $q(\mathbf z;\boldsymbol\lambda)$ and tune λ to make q close to the posterior, i.e. minimise $D_{KL}(q\,\|\,p)$.
  • Because $D_{KL}(q\|p)=\log p(\mathbf X)-\text{ELBO}$ and the evidence is constant, this means maximising the ELBO (evidence lower bound):
    $$\text{ELBO}=\mathbb E_q\big[\log p(\mathbf z,\mathbf X)\big]-\mathbb E_q\big[\log q(\mathbf z)\big]$$
  • Mean-field VI (what scikit-learn uses) needs carefully chosen q and priors so the ELBO has a usable closed form, which gives EM-like update rules. It is often much slower than GaussianMixture. Black-box stochastic VI instead estimates ELBO gradients from samples of q, which works for any differentiable model (the basis of Bayesian deep learning).
GMMs only know ellipsoids. On the two-moons data a Bayesian GMM uses many ellipses to tile each moon. The density estimate is fine (so it can still work for anomaly detection), but the clusters don't match the moons. For shapes like these, use DBSCAN or HDBSCAN.

Test yourself

Answer out loud first, then click the card.

Why can't you pick k by choosing the lowest inertia?
Inertia always falls as k grows (it is 0 when every point is its own cluster). Use the elbow, the silhouette score, or downstream CV accuracy.
What does a silhouette coefficient near −1 tell you?
The point is on average closer to another cluster than to its own (b < a), so it was probably assigned to the wrong cluster.
How does k-means++ choose the next starting centroid?
At random, with probability proportional to the squared distance from the nearest centroid already chosen. Far-away points are much more likely to be picked.
You can afford 50 labels. Which 50 instances should you label, and what next?
Cluster into 50 groups and label the point nearest each centroid. Then propagate each label to the closest members of its cluster (not the boundary points).
DBSCAN: what makes a point core, border or noise?
Core: at least min_samples points (itself included) within eps. Border: not core, but within eps of a core point. Noise (−1): neither.
How do you assign a new point to a DBSCAN cluster?
DBSCAN has no predict(). Train e.g. KNeighborsClassifier on the core instances, and call a point an anomaly if its nearest core is too far away.
EM vs K-Means: what are the two big differences?
EM makes soft assignments (responsibilities), and it learns each cluster's covariance (shape and orientation) and weight, not just its centre.
BIC vs AIC: which one prefers simpler models, and why?
BIC. Its penalty is p·log m, which exceeds AIC's 2p once m > e² ≈ 7, so it punishes extra parameters harder on real datasets.
