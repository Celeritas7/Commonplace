Chapter 7 — Ensemble Learning and Random Forests

In one line
Combine many models so their errors cancel out. You can train them in parallel on shuffled versions of the data and average them (bagging, Random Forests), train them one after another so each fixes the last one's mistakes (boosting), or train a model to combine them (stacking).

An ensemble is a group of predictors whose outputs are combined into one prediction. Ensemble learning is the practice of building one, and an algorithm that does it is an ensemble method. Ensembles usually come at the end of a project, once you already have a few decent models to combine.

The chapter opens with the "wisdom of the crowd" idea and notes that competition winners, such as the Netflix Prize team, often stacked several ensembles.

  • A weak learner is only slightly better than random guessing. A strong learner is highly accurate. With enough weak learners that are also diverse, the vote can be a strong learner.
  • SVC has no predict_proba() by default. Set probability=True for soft voting. This makes training slower, because the probabilities are calibrated with an internal cross-validation.

Why voting works: the law of large numbers

Suppose each of $n$ voters is right with probability $p$, independently of the others. The number of correct votes $K$ then follows a binomial distribution, and the ensemble is right when more than half the votes are correct:

$$P(\text{ensemble correct}) = \sum_{k > n/2} \binom{n}{k} p^k (1-p)^{n-k}$$

If $p$ is even slightly above 0.5, the fraction of correct votes $K/n$ settles closer and closer to $p$ as $n$ grows, so it ends up above one half almost every time. A coin that lands heads 51% of the time shows a heads majority in about three quarters of 1,000-toss runs, and in more than 97% of 10,000-toss runs.

That maths assumes the voters make independent errors. Models trained on the same data tend to make the same mistakes, so the real gain is much smaller. Anything that makes the members more different helps: different algorithms, different data samples, different feature subsets.

What to try
  • Keep ρ = 0 and set p = 0.51. The curve climbs slowly towards 100%, but it needs thousands of voters.
  • Set p to 0.45: the vote amplifies the errors too, and accuracy falls towards 0.
  • Raise ρ to 0.3. The curve flattens at a ceiling well below 100%, and adding voters stops helping. This is why ensemble members need to be diverse.

2 · Bagging and pasting book p. 192 ↗

This is the other route to diversity: use one algorithm, but train each copy on a different random sample of the training set.

  • Bagging (bootstrap aggregating) samples with replacement, so the same row can appear several times in one predictor's sample. Sampling with replacement is called bootstrapping.
  • Pasting samples without replacement. A row can appear in many predictors' samples, but at most once in each.
  • Aggregation: the most common label (the statistical mode) for classification, and the mean for regression.
  • Bias and variance: each member trains on less information, so on its own it has a little more bias. Averaging removes much of the variance, so the ensemble ends up with about the same bias and lower variance than a single model trained on all the data.
  • Members are independent of each other, so training and prediction run in parallel across CPU cores or machines. This is why bagging scales so well.
  • Bootstrapping adds diversity, which means slightly more bias but less correlated members. Bagging usually wins over pasting, but you can cross-validate both if you have the compute.
from sklearn.ensemble import BaggingClassifier
from sklearn.tree import DecisionTreeClassifier

bag = BaggingClassifier(
    estimator=DecisionTreeClassifier(),   # the model being copied
    n_estimators=300,                     # how many copies
    max_samples=0.8,                      # int = rows, float = fraction of rows
    bootstrap=True,                       # False → pasting
    n_jobs=-1)                            # use every CPU core
If the base model has predict_proba(), as decision trees do, BaggingClassifier averages the probabilities (soft voting) rather than counting labels. The result looks like a single tree with a much smoother, less jagged decision boundary.

Out-of-bag (OOB) evaluation

A bootstrap sample of size $m$ drawn from $m$ rows leaves some rows out. The chance that a given row is never picked is $(1-\tfrac1m)^m \approx e^{-1}$, so each predictor sees about 63% of the distinct rows, and the remaining ~37% are its out-of-bag instances. Each predictor has a different OOB set.

$$P(\text{row is sampled}) = 1-\Big(1-\frac1m\Big)^m \;\xrightarrow{m\to\infty}\; 1-e^{-1}\approx 0.632$$
  • Each row can be scored by the members that never saw it, so you get a validation estimate for free, with no hold-out set.
  • oob_score=True → read oob_score_ after fit. oob_decision_function_ holds each training row's OOB class probabilities.
  • OOB only exists with bootstrap=True. Pasting leaves nothing "out of bag".

4 · Random Forests book p. 197 ↗

A Random Forest is a bagging ensemble of decision trees, normally with each sample as large as the training set, plus one extra source of randomness: at each node, the tree searches for the best split among a random subset of the features rather than all of them.

  • RandomForestClassifier / RandomForestRegressor are faster and more convenient than wrapping trees in BaggingClassifier.
  • They take almost all the tree hyperparameters (max_depth, max_leaf_nodes, min_samples_leaf…) plus the ensemble ones (n_estimators, bootstrap, oob_score, n_jobs, max_samples).
  • max_features sets how many features are tried at each split. The current default is "sqrt" for classification and 1.0 (all features) for regression.
  • Random feature subsets make the trees less alike (less correlated), so averaging removes more variance. You trade a little bias for a clear drop in variance.
  • More trees rarely hurt accuracy. They only cost time. Add trees until the OOB score stops improving.
from sklearn.ensemble import RandomForestClassifier
rf = RandomForestClassifier(n_estimators=500, max_leaf_nodes=16, n_jobs=-1, oob_score=True)

Extra-Trees

Extremely Randomized Trees (Extra-Trees) go one step further. At each node they draw a random threshold for each candidate feature and keep the best of those random splits, instead of searching for the optimal threshold.

  • Even more bias traded for less variance.
  • Much faster to train, because searching for the best threshold is the most expensive part of growing a tree.
  • ExtraTreesClassifier / ExtraTreesRegressor have the same API as the Random Forest classes. Note: bootstrap=False by default.
  • You can't tell in advance which of the two will do better. Cross-validate both, ideally with a hyperparameter search.

Feature importance

After fitting, feature_importances_ gives each feature a score that sums to 1 across features. A feature's score is the total impurity decrease from the nodes that split on it, weighted by how many training samples reach each node, averaged over all trees. This score is also called mean decrease in impurity (MDI).

  • A quick way to see which features matter, and a handy first step for feature selection. On iris, the two petal measurements carry almost all the importance.
  • MDI is computed on the training data and favours high-cardinality features, such as IDs or continuous noise. For a more reliable ranking, use sklearn.inspection.permutation_importance on a validation set.

5 · Boosting book p. 199 ↗

Boosting (originally hypothesis boosting) turns weak learners into a strong learner by training them one after another. Each new model tries to fix what the ensemble so far gets wrong.

Because each model depends on the one before it, boosting can't be parallelised across members. It scales worse than bagging (a single tree can still be built in parallel).

AdaBoost — reweight the hard instances

AdaBoost (Adaptive Boosting) raises the weight of the training rows the previous model got wrong, so the next model focuses on them. It works much like gradient descent, except that the ensemble improves by adding predictors rather than by adjusting one model's parameters.

  1. Start with equal weights $w^{(i)} = 1/m$.
  2. Train predictor $j$ with these weights and compute its weighted error rate:
    $$r_j = \frac{\sum_{i:\,\hat y_j^{(i)} \ne y^{(i)}} w^{(i)}}{\sum_{i=1}^{m} w^{(i)}}$$
  3. Give the predictor a weight, where $\eta$ is the learning rate:
    $$\alpha_j = \eta \,\log\frac{1-r_j}{r_j}$$
    If the predictor is accurate, α is large. If it guesses at random ($r_j=0.5$), α ≈ 0. If it is worse than random, α is negative.
  4. Multiply the weight of every misclassified row by $\exp(\alpha_j)$, leave the others unchanged, then normalise all weights so they sum to 1.
  5. Repeat until you reach n_estimators, or until a predictor is perfect.

To predict, every predictor casts a vote weighted by its α, and the class with the largest total wins:

$$\hat y(\mathbf x) = \underset{k}{\operatorname{argmax}} \sum_{j=1}^{N} \alpha_j \,\big[\hat y_j(\mathbf x) = k\big]$$
  • scikit-learn uses SAMME, the multiclass version. It adds $\log(K-1)$ to α for $K$ classes, so with two classes it is exactly AdaBoost.
  • The default base model is a decision stump: a tree with max_depth=1, which has one split and two leaves.
  • If AdaBoost overfits, use fewer estimators, a lower learning rate, or a more regularised base model. If it underfits, do the opposite: more estimators, less regularisation, or a slightly higher learning rate.
  • The original AdaBoost has no learning rate; η was added later as a regularisation knob. SVMs make poor AdaBoost members, being slow and unstable in this setting.
from sklearn.ensemble import AdaBoostClassifier
ada = AdaBoostClassifier(estimator=DecisionTreeClassifier(max_depth=1),
                         n_estimators=200, learning_rate=0.5)

Gradient Boosting — fit the residuals

Gradient Boosting leaves the row weights alone. Instead, each new predictor is fitted to the residual errors of the ensemble so far. With trees as the base model, this is called Gradient Tree Boosting or GBRT (gradient boosted regression trees).

$$F_0(\mathbf x) = \bar y,\qquad h_m \leftarrow \text{fit to } \big(\mathbf x^{(i)},\; y^{(i)} - F_{m-1}(\mathbf x^{(i)})\big),\qquad F_m(\mathbf x) = F_{m-1}(\mathbf x) + \eta\, h_m(\mathbf x)$$

For squared error, the residual is the negative gradient of the loss with respect to the current prediction. Each tree is therefore one gradient-descent step taken in "function space", which is where the name comes from. Other losses (loss=) plug in their own gradients.

  • GradientBoostingRegressor / GradientBoostingClassifier take tree settings (max_depth, min_samples_leaf) plus ensemble settings (n_estimators, learning_rate).
  • Shrinkage: a small learning_rate, such as 0.1, needs more trees but usually generalises better. It is a form of regularisation.
  • Unlike a Random Forest, too many trees overfits. n_estimators and learning_rate must be tuned together.
  • Early stopping, three ways:
    • train many trees, then use staged_predict() on a validation set and pick the number with the lowest error;
    • grow the ensemble step by step with warm_start=True and stop once the validation error hasn't improved for a few rounds;
    • simplest today: n_iter_no_change=10, validation_fraction=0.1, which stops automatically. The number of trees kept is in n_estimators_.
  • Stochastic Gradient Boosting: subsample=0.25 trains each tree on a random 25% of the rows. Training is faster, with a little more bias and less variance.
  • If gradient boosting overfits, lower the learning rate (and use early stopping to find the new number of trees).

What to try
  • η = 1, then step n from 1 to 5. Each stump takes a large bite out of the residuals.
  • η = 1 with 400 trees: training error keeps falling, validation error turns back up, and the curve starts chasing noise.
  • η = 0.03: you need hundreds of trees, but the best validation error is usually a bit lower than with η = 1 (shrinkage).
  • subsample 0.5: the curves get noisier, but overfitting sets in later.

Faster implementations

  • XGBoost (Extreme Gradient Boosting) is a separate, heavily optimised library with a scikit-learn-style API (xgboost.XGBRegressor) and built-in early stopping. LightGBM and CatBoost are popular alternatives.
  • XGBoost began in the DMLC community and became a fixture of winning competition entries.
1. scikit-learn now has its own fast booster: HistGradientBoostingRegressor / HistGradientBoostingClassifier (stable since 1.0, no experimental import needed). It bins the features into histograms, so it is much faster on large data, handles missing values and categorical features natively, and turns early stopping on automatically for datasets over 10,000 rows. Prefer it to GradientBoosting* once you have more than about 10k rows.
2. The base_estimator parameter of BaggingClassifier, AdaBoostClassifier and related classes is now called estimator. The old name was removed in 1.4.
3. AdaBoostClassifier(algorithm="SAMME.R") is gone. SAMME.R was removed in 1.6, and the algorithm parameter itself was deprecated and then removed, so AdaBoost always uses SAMME. Just omit the parameter.
4. In XGBoost 2.x, pass early_stopping_rounds to the constructor. It no longer goes to fit().
5. RandomForestClassifier now also accepts max_samples (the bootstrap sample size), and the old presort option has been removed.

6 · Stacking book p. 208 ↗

Stacking (stacked generalization) replaces a fixed rule such as voting with a trained model that learns how to combine the base predictions. That final model is called a blender or meta learner.

  1. Split the training data. Fit the first-layer models on part A.
  2. Have them predict part B, the hold-out rows. These predictions are "clean", because the models never saw those rows.
  3. Build a new dataset: the inputs are the base models' predictions (one column per model) and the targets are the original ones. Train the blender on it.
  4. To predict, pass new data through the base models, then feed their outputs to the blender.
  • Using a hold-out set this way is often called blending. Using out-of-fold (cross-validated) predictions, so every row contributes, is often called stacking. Many people use the two names interchangeably.
  • You can stack several layers. Each extra layer needs its own fresh slice of data (three subsets for two layers of models plus a blender).
  • Never train the blender on predictions for rows the base models were trained on. Those predictions are too optimistic, so the blender learns to trust the models that overfit most.
The book says scikit-learn doesn't support stacking. Since version 0.22 it does: StackingClassifier / StackingRegressor build the out-of-fold predictions for you (cv=5), then fit final_estimator on them. passthrough=True also gives the blender the original features. 
from sklearn.ensemble import StackingClassifier
stack = StackingClassifier(
    estimators=[("rf", RandomForestClassifier()), ("svc", SVC(probability=True))],
    final_estimator=LogisticRegression(), cv=5)

Test yourself

Answer out loud first, then click the card.

Five different models all score 95% on the same data. Can combining them help?
Often, yes: try a voting or stacking ensemble. It helps most when the models are different kinds of model, so their errors are less correlated.
Hard vs soft voting?
Hard voting counts the predicted labels. Soft voting averages the class probabilities, so confident members count more. Soft voting needs predict_proba on every member.
Which ensembles can be trained across many servers?
Bagging, pasting and Random Forests: fully parallel. Stacking: each layer's models can run in parallel. Boosting: no, because each model needs the previous one.
What does out-of-bag evaluation buy you?
A validation score with no hold-out set. Each row is scored by the members that never saw it (about 37% of them), so all the data can be used for training.
Extra-Trees vs Random Forest: what's different, and which trains faster?
Extra-Trees also draw random split thresholds, so they are more random (less variance, a bit more bias). They train faster, because they skip the search for the best threshold.
AdaBoost underfits. What do you change?
Add estimators, loosen the regularisation on the base model (for example a deeper tree), or raise the learning rate a little.
Gradient boosting overfits. Raise or lower the learning rate?
Lower it (shrinkage), and use early stopping to find the right number of trees for the new rate.
Why does a bootstrap sample contain only about 63% of the distinct rows?
Each row is missed with probability (1 − 1/m)^m ≈ e⁻¹ ≈ 0.37. The rest, about 63%, gets picked at least once.
