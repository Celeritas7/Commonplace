Chapter 8 — Dimensionality Reduction

In one line
High-dimensional data is sparse and slow to learn from, but real data usually sits near a much smaller subspace or curved surface. Find that structure (with PCA, or a manifold method when the surface is curved) and keep only the few coordinates that matter.

0 · Why reduce dimensions at all? book p. 213 ↗

Dimensionality reduction maps each instance from $n$ features to $d < n$ new features while losing as little useful information as possible.

  • Speed: fewer features means faster training. This is the main reason to do it.
  • Visualisation (DataViz): squeeze the data to 2 or 3 dimensions so you can plot it, spot clusters and show the result to non-specialists.
  • Compression: the reduced data takes less memory and disk space.
  • Redundant features are common: border pixels in digit images are almost always blank, and neighbouring pixels are strongly correlated.
Reduction always throws some information away, so the model may get a little worse, and the pipeline gets more complex. Train on the original features first. Reduce only if training is too slow. Sometimes it removes noise and helps accuracy, but usually it only saves time.

1 · The curse of dimensionality book p. 214 ↗

The curse of dimensionality is the set of problems that appear when data has many features: our 3D intuition stops working, and the data becomes very sparse.

  • Almost every point is near the edge. In a unit hypercube, a random point is within $\varepsilon$ of some face with probability $1-(1-2\varepsilon)^n$. For $\varepsilon=0.001$ this is about 0.4% in 2D, but it tends to 100% as $n$ grows into the thousands.
  • Random points are far apart. The average distance between two random points in the unit hypercube grows roughly like $\sqrt{n/6}$: about 0.52 in 2D, 0.66 in 3D, and around 408 for a million dimensions.
  • Distances concentrate. In high dimensions the nearest and farthest neighbours of a point end up at almost the same distance, so "nearest" means less.
Sparse data means a new instance is probably far from every training instance, so predictions become long extrapolations. More dimensions → higher risk of overfitting.

You could, in principle, add training data until the space is densely covered. But the number of instances needed grows exponentially with the number of features. With only 100 uniform features you'd need more rows than there are atoms in the observable universe to keep neighbours within 0.1 of each other.

2 · Two main approaches book p. 215 ↗

Projection

Real features are rarely spread evenly: many are nearly constant and many are correlated. So the instances often lie close to a lower-dimensional subspace (a flat plane, or hyperplane, inside the full space). Projection drops each point perpendicularly onto that subspace, and the coordinates on the subspace ($z_1, z_2, \dots$) become the new features.

Projection fails when the data lies on a surface that curls back on itself, like the Swiss roll toy dataset (make_swiss_roll). Flattening it by projection stacks different layers on top of each other. What you actually want is to unroll it.

Manifold learning

A $d$-dimensional manifold is a shape inside $n$-dimensional space ($d<n$) that looks like a flat $d$-dimensional plane locally, but may be bent or twisted overall. The Swiss roll is a 2D manifold in 3D.

  • Manifold learning: algorithms that model the manifold the data lies on, then express each point in the manifold's own coordinates.
  • They rely on the manifold assumption (manifold hypothesis): most real high-dimensional data lies near a much lower-dimensional manifold. Example: randomly generated pixel grids almost never look like digits, so real digit images fill only a tiny, constrained region of pixel space.
  • A second, hidden assumption is that the task gets simpler in manifold coordinates. This is not guaranteed. A class boundary that is a straight plane in the original space can become a messy set of pieces after unrolling.
Reducing before training almost always saves time, but whether it gives a better or simpler model depends on the dataset. Check it with validation, not by assuming.

3 · PCA book p. 219 ↗

Principal Component Analysis (PCA) finds the hyperplane that lies closest to the data, then projects the data onto it. It is by far the most widely used reduction method.

Preserving the variance

Which axis should you project onto? Pick the one that keeps the most variance: the projected points stay as spread out as possible, so the least information is lost. Equivalently, it is the axis that minimises the mean squared distance between the points and their projections. The two criteria give the same axis because, for centred data,

$$\underbrace{\tfrac1m\textstyle\sum_i\|\mathbf x^{(i)}\|^2}_{\text{total variance (fixed)}}=\underbrace{\tfrac1m\textstyle\sum_i(\mathbf u^\top\mathbf x^{(i)})^2}_{\text{variance kept}}+\underbrace{\tfrac1m\textstyle\sum_i\|\mathbf x^{(i)}-(\mathbf u^\top\mathbf x^{(i)})\mathbf u\|^2}_{\text{squared projection error}}$$

What to try
  • Turn the axis slowly: "variance kept" and "reconstruction MSE" always add up to the same total. When one is at its maximum, the other is at its minimum.
  • Set elongation to 1 (a round cloud). PC1 becomes unstable: a new sample can send it in a completely different direction, because every axis keeps about 50%.
  • Snap to PC1, then turn 90°: that is PC2, the axis that keeps the least variance in 2D.

Principal components

  • The first principal component (PC1) is the axis with the largest variance. PC2 is orthogonal to PC1 and captures the most of what's left. PC3 is orthogonal to both, and so on. There are as many PCs as original dimensions.
  • For each PC, PCA returns a unit vector $\mathbf c_i$ along the axis.
  • The sign of these vectors is arbitrary. Refit on slightly different data and a vector may flip to point the other way. If two PCs have nearly equal variance, they may also rotate or swap, but the plane they span stays about the same.

Finding them with SVD

Singular Value Decomposition (SVD) factors the centred data matrix as $\mathbf X=\mathbf U\boldsymbol\Sigma\mathbf V^\top$. The columns of $\mathbf V$ are exactly the principal components, sorted by importance:

$$\mathbf V=\begin{pmatrix}|&|&&|\\\mathbf c_1&\mathbf c_2&\cdots&\mathbf c_n\\|&|&&|\end{pmatrix} \qquad \text{variance along } \mathbf c_i=\frac{\sigma_i^2}{m-1}$$
PCA assumes the data is centred (each feature has mean 0). scikit-learn's PCA classes centre for you. If you call np.linalg.svd yourself, subtract the column means first. PCA does not scale features, so standardise first when the features have different units.

Projecting down to $d$ dimensions

Keep the first $d$ columns of $\mathbf V$ as $\mathbf W_d$ and multiply. This keeps as much variance as any $d$-dimensional projection can.

$$\mathbf X_{d\text{-proj}}=\mathbf X\,\mathbf W_d$$

With scikit-learn

  • PCA(n_components=2).fit_transform(X) centres the data, runs SVD and projects it.
  • components_ holds the PCs as rows, so it is $\mathbf W_d^\top$ (PC1 is components_[0]).
  • mean_ is the stored centre, and explained_variance_ is the variance along each PC.

Explained variance ratio

explained_variance_ratio_ gives the explained variance ratio: the share of the total variance that lies along each PC. For example, [0.84, 0.15] means that two PCs hold about 99% of the variance, so a third PC would add little.

Choosing the right number of dimensions

  • Don't pick $d$ arbitrarily. Keep enough components to explain a target share of the variance, often 95%.
  • The manual way is to fit PCA() with no limit, take np.cumsum of the ratios, and find the first index where it reaches 0.95.
  • The easier way is to pass a float: PCA(n_components=0.95). The chosen number is then in n_components_.
  • You can also plot the cumulative curve and look for the elbow, where adding components stops helping much.
  • For visualisation, just use 2 or 3.

PCA for compression

Keeping 95% of the variance on 28×28 digit images shrinks 784 features to roughly 150, so the data is less than 20% of its original size. Algorithms such as SVMs then train far faster.

inverse_transform maps the reduced data back to the original space. The result is not identical, because the dropped variance is gone. The reconstruction error is the mean squared distance between the original and the reconstruction.

$$\mathbf X_{\text{recovered}}=\mathbf X_{d\text{-proj}}\,\mathbf W_d^\top \quad(\text{+ the mean, in scikit-learn})$$

Randomized PCA

svd_solver="randomized" uses a stochastic algorithm that quickly approximates only the first $d$ components. Its cost is about $O(m\,d^2)+O(d^3)$, compared with $O(m\,n^2)+O(n^3)$ for the full SVD, so it is much faster when $d \ll n$.

Incremental PCA

Standard PCA needs the whole training set in memory. Incremental PCA (IPCA), IncrementalPCA, learns from mini-batches instead:

  • Call partial_fit(batch) once per batch (for example with np.array_split), not fit. It also works online, as new data arrives.
  • Or keep the data on disk in a np.memmap array and call fit with a batch_size. Only one batch is loaded into memory at a time.

With "auto", scikit-learn now picks "covariance_eigh" for dense data with few features (≤ 1000) and many more rows than features. Otherwise it picks "randomized" when the data is larger than 500×500 and you ask for fewer than 80% of the components, and "full" in all other cases. Recent versions also accept sparse input for some solvers. Check pca._fit_svd_solver to see which solver actually ran.

4 · Kernel PCA book p. 226 ↗

The kernel trick from chapter 5 also works for PCA. Kernel PCA (kPCA) acts as if it mapped the data into a very high-dimensional feature space and ran linear PCA there. That gives a nonlinear projection in the original space. It often keeps clusters together, and can sometimes unroll a twisted manifold.

  • KernelPCA(n_components=2, kernel="rbf", gamma=0.04). Common kernels are "linear" (the same as plain PCA), "rbf", "poly", "sigmoid" and "cosine".
  • Its memory use grows with $m^2$ (it builds a kernel matrix between every pair of instances), so it's for small and medium datasets.

Selecting a kernel and tuning hyperparameters

kPCA is unsupervised, so there is no built-in score to optimise. There are two ways to choose:

  1. Supervised, through the downstream task. Put kPCA in a Pipeline before a classifier (for example LogisticRegression), then run GridSearchCV over kpca__kernel and kpca__gamma. Read the winner from best_params_.
  2. Unsupervised, by reconstruction error. Choose the settings that let you reconstruct the input best.

The catch with option 2: reversing the linear PCA step lands you back in feature space, which can be infinite-dimensional, so you can't compare that point with the original directly. Instead you find a point in the original space whose image is close to it: the reconstruction pre-image. Its squared distance to the original instance is the pre-image error.

  • KernelPCA(…, fit_inverse_transform=True) learns that mapping back for you, using kernel ridge regression from the reduced points to the original ones. Then inverse_transform works, and you can score with mean_squared_error(X, X_preimage).
  • Without fit_inverse_transform=True, calling inverse_transform fails. (In current scikit-learn the method exists but raises NotFittedError.)
KernelPCA now has eigen_solver="randomized" (added in 1.0), which is much faster when you want only a few components from a large kernel matrix. "auto" picks it when that pays off.

5 · LLE book p. 230 ↗

Locally Linear Embedding (LLE) is a nonlinear dimensionality reduction (NLDR) method from the manifold-learning family, and it doesn't use projection. The idea: describe each point as a weighted mix of its nearest neighbours, then find low-dimensional positions where the same weights still work.

Step 1: learn the local weights. Each point is rebuilt only from its $k$ nearest neighbours, and each point's weights add up to 1:

$$\hat{\mathbf W}=\arg\min_{\mathbf W}\sum_{i=1}^{m}\Big\|\mathbf x^{(i)}-\sum_{j=1}^{m}w_{i,j}\,\mathbf x^{(j)}\Big\|^2 \quad\text{s.t.}\quad w_{i,j}=0 \text{ unless } \mathbf x^{(j)}\in\text{kNN}(\mathbf x^{(i)}),\;\; \sum_j w_{i,j}=1$$

Step 2: freeze the weights and move the points. Find $d$-dimensional positions $\mathbf z^{(i)}$ that the same weights reconstruct as well as possible:

$$\hat{\mathbf Z}=\arg\min_{\mathbf Z}\sum_{i=1}^{m}\Big\|\mathbf z^{(i)}-\sum_{j=1}^{m}\hat w_{i,j}\,\mathbf z^{(j)}\Big\|^2$$

Step 1 fixes the points and solves for the weights. Step 2 does the reverse.

  • LocallyLinearEmbedding(n_components=2, n_neighbors=10) in sklearn.manifold. The method parameter also offers "modified", "hessian" and "ltsa" variants.
  • It is very good at unrolling twisted manifolds, especially when there isn't much noise.
  • It preserves distances only locally. On a larger scale, parts of the unrolled result can be stretched or squeezed.
  • Cost: $O(m\log m\;n\log k)$ to find neighbours, $O(m\,n\,k^3)$ for the weights and $O(d\,m^2)$ for the embedding. The $m^2$ term makes it scale poorly to very large datasets.
  • If you see errors or a collapsed result, try changing n_neighbors.

7 · Exercises — the ideas they test book p. 233 ↗

  • Why reduce (speed, visualisation, memory) and the costs (information loss, extra pipeline complexity, harder-to-interpret features).
  • Whether reduction can be undone: approximately for PCA (inverse_transform), only through a learned pre-image for kPCA, and not at all for methods like t-SNE.
  • How many dimensions 95% of the variance needs: it depends entirely on the data. It could be 1, or nearly all 1,000.
  • Which PCA variant fits which situation, and how to evaluate a reduction: reconstruction error, or performance on the downstream task.
  • Chaining methods is reasonable: for example, a fast PCA first to remove useless dimensions, then a slower method such as LLE or t-SNE.
  • Hands-on: time a random forest before and after PCA, and visualise digits in 2D with t-SNE compared with PCA, LLE and MDS.

Test yourself

Answer out loud first, then click the card.

Two good reasons to reduce dimensions, and two costs?
Faster training and 2D/3D visualisation (also less memory). Costs: some information is lost, and the pipeline is more complex, with less interpretable features.
Why do high dimensions make overfitting more likely?
The space is huge, so training points are sparse and far apart. New points are far from all of them, so predictions become long extrapolations.
Maximising projected variance vs minimising projection error: which axis wins?
The same one, PC1. For centred data, kept variance plus squared error equals the fixed total variance.
What must you do before running np.linalg.svd for PCA yourself?
Centre each feature (subtract its mean). Also standardise if the features are on different scales, because PCA doesn't do that.
PCA(n_components=0.95) on a 1,000-feature dataset: how many dims come out?
It depends on the data: anywhere from 1 (almost collinear data) to nearly 1,000 (almost isotropic noise). Check n_components_.
The data doesn't fit in RAM. Which PCA?
IncrementalPCA: partial_fit on mini-batches, or fit on a np.memmap array with a batch_size.
How can you tune Kernel PCA if it's unsupervised?
Grid-search it inside a pipeline with a supervised model, or pick the settings with the lowest pre-image error (fit_inverse_transform=True).
LLE in two steps?
1) Write each point as a weighted sum of its k nearest neighbours (weights sum to 1). 2) Freeze the weights and find low-dimensional points that the same weights rebuild best.
