Chapter 6 — Decision Trees

In one line
A decision tree asks a chain of yes/no questions about one feature at a time, and it is grown greedily so that every split makes the groups purer. Left unchecked it memorises the training data, so you have to limit its growth. It also only draws axis-aligned boundaries and changes a lot when the data changes slightly.

1 · Training and visualising a tree book p. 175 ↗

A decision tree is a flowchart-shaped model. It can do classification, regression and even multi-output tasks. In scikit-learn the classes are DecisionTreeClassifier and DecisionTreeRegressor (in sklearn.tree).

  • Trees are the building block of Random Forests and gradient boosting (chapter 7), so what you learn here carries over.
  • The chapter's running example: classify iris flowers from only petal length and petal width, with max_depth=2.

Three ways to look inside a fitted tree:

FunctionOutputWhen to use
export_graphviz(tree, out_file=…, feature_names=…, class_names=…, filled=True)a .dot file that the Graphviz dot tool turns into PNG/PDFthe method the book shows

Trees need almost no data preparation: no feature scaling or centring. Each split compares one feature with a threshold, so the units don't matter.

2 · Making predictions book p. 176 ↗

To predict, start at the root node (depth 0) and answer its question. That sends you to the left or right child node, and you repeat until you reach a leaf node, which has no children. The leaf gives the answer.

For the iris tree, the first question is about petal length (≈ 2.45 cm). Short petals go straight to a pure setosa leaf. Longer petals get a second question about petal width (≈ 1.75 cm), which separates versicolor from virginica.

What each node stores

  • samples: how many training instances reach this node.
  • value: how those instances split across the classes. (Since scikit-learn 1.4, tree_.value holds class fractions rather than counts for classifiers. The plotted tree still shows what you expect.)
  • gini: the node's impurity. A node is pure (gini = 0) when all of its instances share one class.

The Gini impurity of node $i$, where $p_{i,k}$ is the share of class $k$ among that node's training instances:

$$G_i = 1-\sum_{k=1}^{n} p_{i,k}^{2}$$

Worked example: a node holding 0 / 49 / 5 instances of the three classes has $G = 1-(0/54)^2-(49/54)^2-(5/54)^2 \approx 0.168$. It is almost pure, so the value is close to 0. For two classes, the largest possible value is 0.5 (a 50/50 mix).

Binary trees. scikit-learn's CART only builds binary trees: every internal node has exactly two children. Other algorithms, such as ID3, allow nodes with more than two children.

Each split is a line perpendicular to one axis. The root split cuts the plane at petal length ≈ 2.45. The depth-1 split then cuts only the right-hand region at petal width ≈ 1.75. Raising max_depth to 3 would add one more cut inside each of those regions.

White box vs black box

  • White-box model: you can read off why it made each prediction. A tree is a list of simple rules that you could even apply by hand.
  • Black-box model (Random Forests, neural nets): each calculation can be checked, but it's hard to explain in plain terms which parts of the input drove the result.
If you need a model whose decisions must be explained (to a regulator or a doctor, for example), a shallow tree is a strong candidate.

3 · Estimating class probabilities book p. 178 ↗

To get probabilities, predict_proba() walks down to the leaf and returns the class ratios of the training instances in that leaf. predict() then picks the class with the highest ratio.

  • For the 0/49/5 leaf above, the output is roughly [0, 0.907, 0.093], so the prediction is versicolor.
  • Every point in the same leaf region gets exactly the same probabilities, even a point far from the training data that "looks" like another class. The probabilities are piecewise constant and often poorly calibrated.

4 · The CART training algorithm book p. 179 ↗

scikit-learn grows trees with CART (Classification And Regression Trees). At each node it tries every feature $k$ and threshold $t_k$ and keeps the pair that gives the purest children, weighted by child size:

$$J(k,t_k)=\frac{m_{\text{left}}}{m}\,G_{\text{left}}+\frac{m_{\text{right}}}{m}\,G_{\text{right}}$$

Here $G$ is the impurity of each child and $m_{\text{left}}, m_{\text{right}}$ are the child sizes. The weighting stops the algorithm from carving off a tiny pure group just to get a low impurity number.

  • It then repeats the same search on each child, then on their children, and so on (it is recursive).
  • It stops when it hits max_depth, when no split lowers impurity, or when a limit such as min_samples_split, min_samples_leaf, min_weight_fraction_leaf or max_leaf_nodes blocks it.
CART is a greedy algorithm: it picks the best split at the current level without looking ahead. The result is usually good but not guaranteed optimal. A slightly worse split now could allow much better splits later. Why not search for the best tree directly? Finding the optimal tree is NP-complete, which takes roughly $O(\exp(m))$ time and is hopeless even for small datasets. That is why a good-enough greedy tree is accepted.

What to try
  • Moons with max_depth = None and min_samples_leaf = 1: 100% training accuracy, lots of tiny leaves, and a lower test score. That is overfitting.
  • Raise min_samples_leaf to about 5–10: fewer leaves and smoother regions. The gap between training and test accuracy shrinks. Try a few new samples, because with only 200 points the test score is noisy.
  • Set max_depth to 1 or 2: underfitting. A few big rectangles can't follow the curves.
  • Straight split, then slide "Rotate data" from 0° to 45°: one split is enough at 0°, but at 45° the tree needs a staircase of many leaves.
  • Switch gini ↔ entropy: the regions barely change.

5 · Computational complexity book p. 180 ↗

CostWhy
Prediction$O(\log_2 m)$, whatever the number of featuresA roughly balanced tree has about $\log_2 m$ levels, and each node checks just one feature.
Training$O(n \times m\log_2 m)$Every node considers every feature (or max_features of them) across its samples, which must be sorted.
  • So predictions stay fast even when the training set is huge.
  • Here $\log_2 m = \log m / \log 2$ is the binary logarithm.
The book mentions presort=True to speed up training on small datasets. That parameter was deprecated in scikit-learn 0.22 and removed in 0.24. Passing it now raises an error. Don't use it.

6 · Gini impurity or entropy? book p. 180 ↗

The criterion hyperparameter picks the impurity measure. The default is "gini". You can switch to entropy:

$$H_i=-\sum_{\substack{k=1\\ p_{i,k}\neq 0}}^{n} p_{i,k}\,\log_2 p_{i,k}$$
  • Entropy is 0 when a node holds only one class. For the same 0/49/5 node, $H \approx 0.445$.
  • A drop in entropy after a split is called information gain.
  • The idea comes from thermodynamics (disorder) and from Shannon's information theory (the average information in a message).

Keep the default gini. Tuning the criterion rarely pays off compared with tuning the regularisation hyperparameters. Current scikit-learn accepts criterion="gini", "entropy" or "log_loss" for classifiers. "log_loss" (added in 1.1) is simply another name for entropy.

7 · Regularisation hyperparameters book p. 181 ↗

Trees make very few assumptions about the data, which is why they overfit so easily.

  • Nonparametric model: the number of parameters is not fixed before training, so the model's structure can grow to fit the data. Trees are like this. (It doesn't mean the model has no parameters.)
  • Parametric model: a fixed number of parameters, as in a linear model. It has fewer degrees of freedom, so less risk of overfitting and more risk of underfitting.

To prevent overfitting, limit how freely the tree can grow:

Hyperparameter (default)What it limitsTo regularise more
max_depth (None = unlimited)number of levelsdecrease
min_samples_split (2)a node needs at least this many samples before it may splitincrease
min_samples_leaf (1)every leaf must keep at least this many samplesincrease
min_weight_fraction_leaf (0.0)like min_samples_leaf, but as a fraction of the total sample weightincrease
max_leaf_nodes (None)total number of leaves (the tree then grows best-first)decrease
max_features (None = all)how many randomly chosen features are tried at each split (int, float, "sqrt", "log2")decrease
min_impurity_decrease (0.0)a split must reduce weighted impurity by at least this muchincrease
ccp_alpha (0.0)cost-complexity pruning strength (see below)increase
Rule of thumb: raise the min_* ones, lower the max_* ones. Both make the tree simpler.

Pruning

Pruning means growing the full tree first and then deleting branches that don't earn their place.

  • The book describes the statistical version used by other algorithms. A node whose children are all leaves is tested, for example with a χ² test. If the purity gain could easily be due to chance (the p-value is above a threshold such as 5%, under the null hypothesis of "no real effect"), the children are removed. This repeats until nothing more can be pruned.
  • scikit-learn instead uses minimal cost-complexity pruning. It removes the subtrees whose impurity gain per extra leaf is smallest. That trades training impurity against tree size, $R_\alpha(T)=R(T)+\alpha\,|\text{leaves}(T)|$.
ccp_alpha arrived in scikit-learn 0.22, after the book. tree.cost_complexity_pruning_path(X, y) returns the candidate α values; pick one with cross-validation. A larger ccp_alpha gives a smaller tree.

On noisy moons, an unrestricted tree fits the training set perfectly with a jagged boundary. Setting min_samples_leaf=4 or so already gives a smoother boundary that generalises better. You can see this in the playground above.

8 · Regression book p. 183 ↗

DecisionTreeRegressor has the same structure, but each leaf predicts a number: the mean target value of the training instances in that leaf. The prediction is a step function.

CART now picks splits that minimise the weighted MSE instead of impurity:

$$J(k,t_k)=\frac{m_{\text{left}}}{m}\text{MSE}_{\text{left}}+\frac{m_{\text{right}}}{m}\text{MSE}_{\text{right}},\qquad \text{MSE}_{\text{node}}=\frac{1}{m_{\text{node}}}\sum_{i\in\text{node}}\big(\hat y_{\text{node}}-y^{(i)}\big)^2,\quad \hat y_{\text{node}}=\frac{1}{m_{\text{node}}}\sum_{i\in\text{node}}y^{(i)}$$
  • Each split places a cut so that the points on each side sit as close as possible to their own side's average.
  • Regression trees overfit just as badly. With the defaults, every training point ends up in its own leaf and the curve zig-zags through the noise. Something like min_samples_leaf=10 fixes most of that.
  • A tree can't extrapolate. Outside the training range, it predicts the value of the nearest edge leaf.
Regressor criterion names changed in scikit-learn 1.0: "mse" → "squared_error" (the default) and "mae" → "absolute_error". The old names were removed in 1.2. "friedman_mse" and "poisson" are also available.

9 · Instability book p. 185 ↗

Trees are easy to use, easy to interpret, versatile and powerful, but they have two main weaknesses.

1. Only axis-aligned boundaries

  • Every split is perpendicular to an axis, so a diagonal boundary has to be approximated by a staircase.
  • That makes trees sensitive to rotation. The same data rotated by 45° can go from needing a single split to needing a convoluted tree that generalises worse. (The "Straight split" data in the playground shows this.)
  • Fix: rotate the data first, for example with PCA (chapter 8), which often lines the important directions up with the axes.

2. High variance

  • Small changes in the training data can produce a very different tree. Removing a single iris flower can change which feature the root splits on.
  • Even the same data can give different trees. scikit-learn shuffles the features it considers at each split, so when two splits tie, the choice depends on random_state. Set it if you need reproducible results.
  • Fix: average many trees. That is exactly what a Random Forest does (chapter 7).
Newer tree features not in the book: since scikit-learn 1.3, trees can handle missing values (NaN) natively with the default splitter, and since 1.4 you can force monotonic relationships with monotonic_cst.

10 · Exercises book p. 186 ↗

The book's exercises cover the depth of a tree on a million rows, whether Gini goes down from parent to child, what to change when overfitting or underfitting, how training time scales, and two hands-on tasks on make_moons(n_samples=10000, noise=0.4): tuning max_leaf_nodes with GridSearchCV, then building a "forest" by hand from 1,000 small trees and a majority vote.

My quick answers (check against the book's answers)
  • Depth for 10⁶ instances: a balanced tree with one sample per leaf needs about $\log_2(10^6)\approx 20$ levels. Real trees are a bit deeper because they aren't perfectly balanced.
  • Child Gini vs parent: usually lower. The size-weighted average of the two children can't be higher than the parent, but one individual child can be less pure than its parent.
  • Overfitting → lower max_depth? Yes, that constrains the tree.
  • Underfitting → scale features? No. Trees don't care about scale. Loosen the constraints instead.
  • 1 h for 10⁶ rows → 10⁷ rows? Training grows like $m\log m$: $10\times\log(10^7)/\log(10^6)\approx 11.7$ hours.
  • presort for 100k rows? No. It only helped on small sets, and the option no longer exists.

Test yourself

Answer out loud first, then click the card.

A node holds 30 cats and 10 dogs. What is its Gini impurity?
1 − 0.75² − 0.25² = 1 − 0.5625 − 0.0625 = 0.375.
How does a tree compute predict_proba for a point?
It walks down to the point's leaf and returns the class ratios of the training instances in that leaf.
What does CART minimise at each split, and why weight by size?
The size-weighted impurity of the two children (or weighted MSE for regression). The weighting stops it from favouring tiny pure fragments.
Why is CART called greedy?
It picks the best split for the current node only and never looks ahead. The tree is good but not guaranteed optimal.
Your tree overfits. Name three knobs and which way to turn them.
Lower max_depth or max_leaf_nodes; raise min_samples_leaf or min_samples_split; raise ccp_alpha.
Why does a tree struggle with a 45° boundary?
Its splits are all axis-aligned, so it needs a staircase of many splits. Rotating the data (e.g. with PCA) can help.
What does a regression tree leaf predict?
The mean target value of the training instances in that leaf, so the model is a step function.
Do you need StandardScaler before a decision tree?
No. Each split compares one feature with a threshold, so scaling doesn't change the tree.
