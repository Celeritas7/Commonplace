Chapter 4 — Training Models

In one line
Training a model means finding the parameters that make a cost function as small as possible — either in one shot with an equation, or step by step with gradient descent — and then controlling how flexible the model is so it doesn't memorise the training data.

1 · Linear regression book p. 112 ↗

A linear model predicts by taking a weighted sum of the features plus a constant:

$$\hat y = \theta_0 + \theta_1 x_1 + \dots + \theta_n x_n = \boldsymbol\theta^\top \mathbf x$$

Here $\mathbf x$ gets an extra $x_0 = 1$ so the bias $\theta_0$ fits inside the dot product.

To train it, you pick the $\boldsymbol\theta$ that minimises the mean squared error (MSE):

$$\text{MSE}(\boldsymbol\theta)=\frac1m\sum_{i=1}^{m}\big(\boldsymbol\theta^\top\mathbf x^{(i)}-y^{(i)}\big)^2$$
The metric you report (for example RMSE) and the cost you minimise can differ. MSE is used for training because it has the same minimum as RMSE and a simpler derivative.

The Normal Equation — the one-shot answer

$$\hat{\boldsymbol\theta}=(\mathbf X^\top\mathbf X)^{-1}\mathbf X^\top\mathbf y$$
  • scikit-learn's LinearRegression actually uses the pseudoinverse (computed with SVD). That still works when $\mathbf X^\top\mathbf X$ can't be inverted, for example with duplicate features or more features than rows.
  • Cost grows fast with the number of features n: about $O(n^{2.4})$ to $O(n^3)$ for the inverse, and about $O(n^2)$ for SVD. With 100,000 features this becomes very slow.
  • Cost is linear in the number of rows m, so large datasets are fine as long as they fit in memory.
  • Once trained, making predictions is fast. Cost is linear in both m and n.
Use the closed form when there are few features. Use gradient descent when there are many features or the data doesn't fit in memory.

2 · Gradient descent book p. 118 ↗

Gradient descent (GD) starts from random parameters and repeatedly steps downhill, opposite to the gradient of the cost. The step size is the learning rate $\eta$.

  • η too small → many steps, slow.
  • η too large → overshoots the valley and can diverge.
  • MSE for linear regression is convex: a bowl with a single global minimum, so GD gets there if η is reasonable.
Scale your features, for example with StandardScaler. Unscaled features make the bowl long and narrow, so GD zig-zags and takes much longer.

The gradient of MSE for all parameters at once:

$$\nabla_{\boldsymbol\theta}\,\text{MSE}(\boldsymbol\theta)=\frac{2}{m}\mathbf X^\top(\mathbf X\boldsymbol\theta-\mathbf y) \qquad\qquad \boldsymbol\theta \leftarrow \boldsymbol\theta-\eta\,\nabla_{\boldsymbol\theta}\text{MSE}$$

  • An epoch is one full pass over the training set.
  • A learning schedule shrinks η over time, so SGD takes big steps early and settles down near the end. (This is simulated annealing, an idea borrowed from metallurgy.)
  • SGD assumes the rows are independent and identically distributed (IID). Shuffle the data, or visit rows in random order. Data sorted by label breaks SGD.

3 · Polynomial regression book p. 128 ↗

A linear model can fit curves: add powers of the features as new features, then run ordinary linear regression. PolynomialFeatures(degree=d) does this for you.

  • It also adds interaction terms such as $x_1x_2$, which is how it captures relationships between features.
  • The number of features explodes: $n$ features at degree $d$ become $\frac{(n+d)!}{d!\,n!}$ features.

4 · Learning curves book p. 130 ↗

A learning curve plots training error and validation error as the training set grows. It tells you which problem you have:

What you seeDiagnosisWhat helps
Both errors high and close together (a plateau)Underfitting (high bias)A more complex model or better features. More data won't help.
Training error low, a clear gap to validation errorOverfitting (high variance)More data, regularisation, or a simpler model

The bias/variance trade-off: the generalisation error splits into

  • bias: wrong assumptions about the data, which cause underfitting
  • variance: too much sensitivity to small changes in the data, which causes overfitting
  • irreducible error: noise in the data itself. Only cleaning the data reduces it.
Making a model more complex raises variance and lowers bias. The goal is the balance point between the two.

5 · Regularised linear models book p. 134 ↗

Regularisation limits how much the weights can grow. That makes the model less flexible, so it overfits less.

ModelPenalty added to the costEffectscikit-learn
Ridgeα × sum of squared weights (ℓ2)shrinks every weight smoothlyRidge(alpha=…), SGDRegressor(penalty="l2")
Lassoα × sum of absolute weights (ℓ1)pushes weak weights to exactly 0 (automatic feature selection)Lasso(alpha=…)
Elastic Neta mix of ℓ1 and ℓ2, controlled by l1_ratiolike Lasso, but steadier when features are correlatedElasticNet(alpha=…, l1_ratio=…)

  • Scale the features before regularising. The penalty treats every weight the same way.
  • The bias term θ₀ is not penalised.
  • The penalty is used only during training. Evaluate the model with the plain metric.
  • Default choice: Ridge. Try Lasso or Elastic Net if you suspect only a few features matter. Prefer Elastic Net over Lasso when features are many or correlated.
  • The exact constants in front of the penalty (½, 1/m…) differ between the book and scikit-learn. They change the scale of α, not the idea.

6 · Logistic & softmax regression book p. 142 ↗

Logistic regression is a linear model used for classification. It computes $t=\boldsymbol\theta^\top\mathbf x$ (the logit) and turns it into a probability with the sigmoid:

$$\hat p=\sigma(t)=\frac{1}{1+e^{-t}}\qquad \hat y=\begin{cases}1 & \hat p\ge 0.5\\ 0 & \text{otherwise}\end{cases}$$

It is trained with log loss (binary cross-entropy). The loss is convex, so GD finds the minimum, but there is no closed-form solution.

$$J(\boldsymbol\theta)=-\frac1m\sum_{i}\Big[y^{(i)}\log\hat p^{(i)}+(1-y^{(i)})\log(1-\hat p^{(i)})\Big] \qquad \nabla J=\frac1m\mathbf X^\top(\hat{\mathbf p}-\mathbf y)$$
The gradient has the same shape as the one for linear regression: (prediction − target) × input. Only the prediction changes.

The boundary sits where $\theta_0+\theta_1x=0$. A larger |θ₁| gives a more confident, sharper curve. Wrong confident predictions make the log loss jump.

  • scikit-learn's LogisticRegression applies ℓ2 regularisation by default, controlled by C, which is the inverse of α: a smaller C means stronger regularisation.
  • Softmax regression (multinomial logistic regression) handles more than two classes directly. It gives each class its own score and uses softmax to turn the scores into probabilities that sum to 1. It is trained with cross-entropy.
  • Softmax picks exactly one class per input. It is for mutually exclusive classes, not multi-label problems.
  • In recent scikit-learn versions, LogisticRegression uses softmax automatically when there are more than two classes (with the default lbfgs solver).

Test yourself

Answer out loud first, then click the card.

You have 1 million rows but only 10 features. Normal Equation or GD?
Either works. With so few features the Normal Equation / SVD is cheap. Its cost grows with the number of features, and only linearly with rows.
Your GD loss curve shoots up after a few steps. What's wrong?
The learning rate is too high, so it overshoots and diverges. Lower η. Also check that the features are scaled.
Why does plain SGD never settle exactly at the minimum?
Each step uses one random row, so the gradient is noisy. Fix: a learning schedule that shrinks η over time.
Training and validation error are both high and close. More data?
No. That pattern means underfitting. Use a more complex model or better features.
Ridge vs Lasso in one sentence each?
Ridge (ℓ2) shrinks all weights smoothly. Lasso (ℓ1) sets weak weights to exactly zero, so it also selects features.
In LogisticRegression, C goes from 1 to 0.01. What happens?
Regularisation gets stronger (C = 1/α), so the weights shrink and the model becomes simpler.
Can softmax regression tag one photo as both "cat" and "outdoor"?
No. Softmax picks one class out of mutually exclusive classes. Multi-label needs one binary classifier per label.
What must you do to the data before SGD and before regularisation?
Shuffle it (IID assumption for SGD) and scale the features (for GD speed and a fair penalty).
