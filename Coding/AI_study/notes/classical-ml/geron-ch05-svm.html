Chapter 5 — Support Vector Machines

In one line
An SVM draws the decision boundary with the widest possible gap between the classes. Only the few points touching or crossing that gap (the support vectors) decide where it goes. C sets how many of them may cross, and a kernel lets the same machinery bend the boundary without ever building the extra features.

1 · Linear SVM classification book p. 153 ↗

Many straight lines can separate two linearly separable classes. An SVM picks the one that leaves the widest street between them. This is large margin classification. The two edges of the street sit where the decision function equals ±1.

  • Support vectors: the training points on the edge of the street or inside it. Only they define the boundary. You can add or move points well outside the street and the model stays the same.
  • SVMs are sensitive to feature scale. If one feature has a much larger range, the widest street follows that axis, and the result is a poor boundary. Always put a StandardScaler in front.
  • SVM classifiers return a class and a score from decision_function, not a probability. The score is a signed distance-like value.

What to try
  • Drag C from 0.01 up to 1000. The street narrows and the number of support vectors drops.
  • Switch on the outlier and set C to 1000. That is almost a hard margin, and the boundary swings to accommodate one point. Lower C and the boundary settles back.
  • At C = 1, count the rings. Only those points enter $\mathbf w=\sum\alpha_i t_i\mathbf x_i$. Every other point has α = 0 and could move (while staying off the street) without changing the line.

Three ways to train a linear SVM in scikit-learn

from sklearn.svm import LinearSVC, SVC
from sklearn.linear_model import SGDClassifier
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

a = make_pipeline(StandardScaler(), LinearSVC(C=1, loss="hinge"))   # liblinear — fast
b = make_pipeline(StandardScaler(), SVC(kernel="linear", C=1))      # libsvm — slower, but kernels
c = make_pipeline(StandardScaler(),
                  SGDClassifier(loss="hinge", alpha=1/(m*C)))       # online / out-of-core
  • The alpha=1/(m·C) mapping comes from rescaling the SVM cost. With it, SGD minimises roughly the same objective, but it converges more slowly.
  • LinearSVC also regularises the bias term, so centre the data first. StandardScaler does this for you. This is why the three models above give slightly different intercepts.
LinearSVC / LinearSVR dual: the book says to set dual=False by hand when rows outnumber features. Since scikit-learn 1.5 the default is dual="auto", which picks the primal or dual solver based on the shape of the data and the loss/penalty combination. Note that loss="hinge" with an ℓ2 penalty is only available in the dual.
loss: the default is still "squared_hinge". Pass loss="hinge" if you want the textbook SVM.
max_iter (default 1000) often triggers a ConvergenceWarning on unscaled or hard data. Scale the data, or raise it to about 10 000.

2 · Nonlinear SVM classification book p. 157 ↗

Most real data can't be split by a straight line. There are two families of fixes: add features explicitly, or use a kernel to get the same effect implicitly.

a) Polynomial features + a linear SVM

A 1-D set that no single threshold can split can become separable once you add $x_2 = x_1^2$. In code this is PolynomialFeatures(d) → StandardScaler → LinearSVC. The book demonstrates it on make_moons.

  • A low degree can't follow complex shapes, and a high degree makes the feature count explode (see ch 4), so training becomes slow.

b) Polynomial kernel

The kernel trick gives the same result as training on all those polynomial features, without creating them. SVC(kernel="poly", degree=3, coef0=1, C=5).

  • degree: raise it if the model underfits, lower it if it overfits.
  • coef0 (the $r$ in the kernel formula): how much the high-degree terms matter compared with the low-degree terms. With coef0=0 only the degree-d terms remain.
Grid search coarse first (powers of 10), then fine around the winner. Knowing which direction each knob pushes the model helps you pick sensible grids.

c) Similarity features with landmarks

Pick some landmarks ℓ and give each point a new feature for each landmark: its similarity to that landmark. The usual similarity function is the Gaussian RBF:

$$\phi_\gamma(\mathbf x,\boldsymbol\ell)=\exp\!\big(-\gamma\,\lVert\mathbf x-\boldsymbol\ell\rVert^2\big)$$

It is a bell curve: 1 at the landmark, falling towards 0 far away. For example, with γ = 0.3, a point at distance 2 gets $e^{-1.2}\approx0.30$.

  • The simplest choice is a landmark at every training point. Then m rows × n features become m × m. The data is very likely to become separable, but the new feature matrix is huge for big m.

d) Gaussian RBF kernel

SVC(kernel="rbf", gamma=…, C=…) gets the effect of "a landmark at every point" through the kernel trick. kernel="rbf" is the default.

What to try
  • RBF with γ = 100 and C = 1000: small islands around single points, train accuracy near 100%, and test accuracy drops. That is overfitting.
  • RBF with γ = 0.03 and C = 0.01: an almost straight boundary and nearly every point is a support vector. That is underfitting.
  • Linear: no C makes the moons separable. Poly d=3 with a moderate γ gets close to RBF.
  • Notice that the number of support vectors falls as C rises. Fewer support vectors means faster predictions.

Which kernel first?

  • 1. Linear (LinearSVC) first, especially with many rows or many features. It is much faster than SVC(kernel="linear").
  • 2. RBF if the training set isn't too large. It works well on most problems.
  • 3. Other kernels only if you have time, or if there is a kernel made for your data type.
  • Specialised kernels exist for structured data, e.g. string kernels for text or DNA (subsequence kernels, edit-distance-based kernels).

3 · SVM regression book p. 162 ↗

Regression turns the classification goal around. Instead of keeping points out of the street, fit as many points as possible inside it, and penalise the ones outside.

  • ε (epsilon) sets the half-width of the tube around the prediction. Errors smaller than ε cost nothing.
  • ε-insensitive: adding training points inside the tube doesn't change the model. Only points on or outside the tube are support vectors.
  • A larger ε gives fewer support vectors and a flatter, simpler model. A smaller ε gives more support vectors.
  • C works as before: a large C means little regularisation, so the model chases outliers. A small C means a smoother fit.
ClassificationRegression twinNotes
LinearSVCLinearSVR(epsilon=…)linear time in m. Scale and centre the data first.
SVCSVR(kernel="poly", degree=2, C=…, epsilon=…)kernels are allowed, but it is slow for large m, just like SVC
In LinearSVR, epsilon defaults to 0. In SVR it defaults to 0.1. ε is measured in target units, so scale y (for example with TransformedTargetRegressor) or choose ε to match your target's range.

Outlier detection with SVMs: OneClassSVM (kernelised) and SGDOneClassSVM (linear, for large data). The book only mentions these in passing.

4 · Under the hood book p. 164 ↗

This is the maths behind the API. Must know: the decision function, why a small ‖w‖ means a wide margin, the soft-margin cost, the hinge loss, and why the dual enables kernels. You can skim the QP parameter mapping, the full dual derivation and Mercer's theorem.

Notation change: the bias is now $b$ and the weights are $\mathbf w$. There is no $x_0=1$ column. Labels are $t^{(i)}\in\{-1,+1\}$.

Decision function

$$\hat y=\begin{cases}0 & \text{if } \mathbf w^\top\mathbf x+b<0\\ 1 & \text{if } \mathbf w^\top\mathbf x+b\ge 0\end{cases}$$
  • The boundary is the set $f(\mathbf x)=0$, a hyperplane of dimension n − 1. The street edges are $f=\pm1$.

Training objective — why a small ‖w‖ means a wide street

The slope of $f$ is $\lVert\mathbf w\rVert$. If you halve the slope, $f$ needs twice the distance to climb from 0 to 1, so the street is twice as wide. In general the street width is $2/\lVert\mathbf w\rVert$, so maximising the margin is the same as minimising $\lVert\mathbf w\rVert$.

$$\text{Hard margin:}\quad \min_{\mathbf w,b}\ \tfrac12\mathbf w^\top\mathbf w\quad\text{s.t.}\quad t^{(i)}(\mathbf w^\top\mathbf x^{(i)}+b)\ge 1\ \ \forall i$$
$$\text{Soft margin:}\quad \min_{\mathbf w,b,\boldsymbol\zeta}\ \tfrac12\mathbf w^\top\mathbf w + C\sum_{i=1}^m\zeta^{(i)}\quad\text{s.t.}\quad t^{(i)}(\mathbf w^\top\mathbf x^{(i)}+b)\ge 1-\zeta^{(i)},\ \ \zeta^{(i)}\ge0$$
  • The objective uses $\tfrac12\lVert\mathbf w\rVert^2$ rather than $\lVert\mathbf w\rVert$ because it has the same minimiser, is differentiable everywhere (its gradient is just $\mathbf w$), and is easier for optimisers.
  • Slack variable $\zeta^{(i)}$: how far point i is allowed to violate the margin. C sets the trade-off between wide street and small slack.

Quadratic programming (skim)

Both problems are quadratic programming (QP) problems: a convex quadratic objective with linear constraints. The general form is $\min_{\mathbf p}\ \tfrac12\mathbf p^\top\mathbf H\mathbf p+\mathbf f^\top\mathbf p$ subject to $\mathbf A\mathbf p\le\mathbf b$.

How the hard-margin SVM maps onto a QP solver
  • $\mathbf p=[b,\ w_1,\dots,w_n]$, so there are $n+1$ parameters and $m$ constraints.
  • $\mathbf H$ = identity with a 0 in the top-left cell (the bias is not penalised), and $\mathbf f=\mathbf 0$.
  • Row i of $\mathbf A$ is $-t^{(i)}\,[1,\ \mathbf x^{(i)}]$, and $\mathbf b=-\mathbf 1$ (this turns "≥ 1" into "≤ −1").
  • For the soft margin (exercise 7), add the $m$ slack variables to $\mathbf p$, put $C$ in $\mathbf f$ at the slack positions, and add the constraints $\zeta\ge0$.

The dual problem

Every constrained primal problem has a related dual problem. For the SVM the two have the same solution, because the objective is convex and the constraints are well behaved. The linear SVM dual is:

$$\min_{\boldsymbol\alpha}\ \frac12\sum_{i=1}^m\sum_{j=1}^m\alpha^{(i)}\alpha^{(j)}t^{(i)}t^{(j)}\,\mathbf x^{(i)\top}\mathbf x^{(j)}-\sum_{i=1}^m\alpha^{(i)}\quad\text{s.t.}\quad\alpha^{(i)}\ge0$$
$$\hat{\mathbf w}=\sum_{i}\hat\alpha^{(i)}t^{(i)}\mathbf x^{(i)}\qquad \hat b=\frac1{n_s}\sum_{\hat\alpha^{(i)}>0}\Big(t^{(i)}-\hat{\mathbf w}^\top\mathbf x^{(i)}\Big)$$
  • $\alpha^{(i)}>0$ exactly for the support vectors. All other points have $\alpha=0$ and drop out.
  • For the soft margin the constraint becomes $0\le\alpha^{(i)}\le C$, and scikit-learn's solvers also enforce $\sum_i\alpha^{(i)}t^{(i)}=0$. That is exactly what the SMO solver in the playgrounds does.
  • The dual is faster when m < n (fewer rows than features). With millions of rows and hundreds of features, solve the primal (exercise 5).
  • The key point is that the training data appears in the dual only as dot products $\mathbf x^{(i)\top}\mathbf x^{(j)}$. That is what makes the kernel trick possible.

Kernelised SVMs

Take the degree-2 map $\phi(\mathbf x)=\big(x_1^2,\ \sqrt2\,x_1x_2,\ x_2^2\big)$. Expanding the dot product gives:

$$\phi(\mathbf a)^\top\phi(\mathbf b)=a_1^2b_1^2+2a_1b_1a_2b_2+a_2^2b_2^2=(a_1b_1+a_2b_2)^2=(\mathbf a^\top\mathbf b)^2$$

So wherever the dual needs $\phi(\mathbf x^{(i)})^\top\phi(\mathbf x^{(j)})$, you can compute $(\mathbf x^{(i)\top}\mathbf x^{(j)})^2$ directly. You never build $\phi$. A kernel is a function $K(\mathbf a,\mathbf b)$ that returns $\phi(\mathbf a)^\top\phi(\mathbf b)$ using only the original vectors.

Kernel$K(\mathbf a,\mathbf b)$scikit-learn args
Linear$\mathbf a^\top\mathbf b$kernel="linear"
Polynomial$(\gamma\,\mathbf a^\top\mathbf b+r)^d$"poly", gamma, coef0=r, degree=d
Gaussian RBF$\exp(-\gamma\lVert\mathbf a-\mathbf b\rVert^2)$"rbf", gamma
Sigmoid$\tanh(\gamma\,\mathbf a^\top\mathbf b+r)$"sigmoid", gamma, coef0
SVC / SVR now default to gamma="scale", which means $\gamma = 1/(n_\text{features}\cdot\operatorname{Var}(X))$. The old default was "auto", which is $1/n_\text{features}$. The book always sets γ explicitly, so its examples are unaffected. kernel can also be a Python callable or "precomputed".

Mercer's theorem: if $K$ satisfies Mercer's conditions (roughly: continuous, symmetric, and producing positive semi-definite matrices), then some $\phi$ exists with $K=\phi^\top\phi$, even if you can't write it down. For RBF, that $\phi$ maps into an infinite-dimensional space. The sigmoid kernel doesn't always satisfy the conditions but works in practice.

Predicting without ever computing w

With a kernel, $\mathbf w$ lives in $\phi$-space, which may be huge or infinite, so you can't store it. Substitute $\mathbf w=\sum\alpha^{(i)}t^{(i)}\phi(\mathbf x^{(i)})$ into the decision function instead:

$$h(\mathbf x)=\sum_{\alpha^{(i)}>0}\alpha^{(i)}t^{(i)}K(\mathbf x^{(i)},\mathbf x)+b\qquad b=\frac1{n_s}\sum_{\alpha^{(i)}>0}\Big(t^{(i)}-\sum_{\alpha^{(j)}>0}\alpha^{(j)}t^{(j)}K(\mathbf x^{(i)},\mathbf x^{(j)})\Big)$$
  • Each prediction costs one kernel evaluation per support vector, so a model with many support vectors predicts slowly.
  • In scikit-learn: support_vectors_, support_ (indices), n_support_ (count per class), dual_coef_ ($=\alpha^{(i)}t^{(i)}$) and intercept_.

Online SVMs and the hinge loss

The soft-margin primal can be written as a single unconstrained cost, which you can minimise with (sub)gradient descent, as SGDClassifier does:

$$J(\mathbf w,b)=\tfrac12\mathbf w^\top\mathbf w+C\sum_{i=1}^m\max\!\big(0,\ 1-t^{(i)}(\mathbf w^\top\mathbf x^{(i)}+b)\big)$$

The hinge loss $\max(0,1-t)$ (solid) against the logistic log loss (dashed), plotted over $t\cdot f(\mathbf x)$. The hinge loss is exactly zero once a point is past the street edge, and that is why SVMs end up sparse, with few support vectors. Its slope is −1 for $t<1$ and 0 for $t>1$. At the kink, any subgradient in [−1, 0] works, just as with Lasso.

  • The first term keeps $\mathbf w$ small (a wide street). The second term adds up the violations: zero for points on the correct side and off the street, and growing with the distance for the rest.
  • GD converges much more slowly than the QP-based solvers. Use it for streaming or out-of-core data.
  • Online kernel SVMs exist in research papers (incremental/decremental SVMs, LASVM), with Matlab/C++ code. For large nonlinear problems, the book suggests neural networks instead.

What you should see (and why)
  • As C grows, the street width shrinks (about 3.6 → 0.7 → 0.25 in scaled units).
  • The three linear models point in nearly the same direction but have slightly different intercepts, because LinearSVC penalises the bias.
  • On moons, all three nonlinear models score around 95–98%. The grid search picks a mid-range γ, and roughly half the training points end up as support vectors.
  • SVR with a larger ε has far fewer support vectors (about 70 → 10) and nearly the same slope. The linear model fails on the quadratic data, and the degree-2 poly kernel fits it.

Test yourself

Answer out loud first, then click the card.

You delete a training point that lies far outside the street. What changes?
Nothing. It isn't a support vector (its α is 0), so the boundary stays exactly where it is.
Why must you scale features before an SVM?
The margin is measured as a Euclidean distance. A feature with a large range dominates it, and the street lines up with that axis.
An RBF SVM overfits. Which way do you move γ and C?
Lower both. A smaller γ gives each point a wider, smoother reach, and a smaller C tolerates more violations.
Street width in terms of w?
2 / ‖w‖. That's why the objective minimises ½‖w‖²: a smaller w gives a wider street.
Why does the kernel trick need the dual form?
In the dual, the data appears only inside dot products xᵢᵀxⱼ, and those can be swapped for K(xᵢ, xⱼ). The primal needs w and φ(x) explicitly.
10 million rows, 200 features, linear problem. Which class?
LinearSVC (primal), or SGDClassifier with hinge loss if the data doesn't fit in memory. Avoid SVC, whose cost is O(m²) to O(m³).
What does ε do in SVR, and what happens to the support vectors when it grows?
ε is the half-width of the no-penalty tube. A larger ε puts more points inside the tube, so there are fewer support vectors and the model is simpler.
Can an SVC give you probabilities?
Not by default: it gives a decision_function score. With probability=True it fits Platt scaling using internal CV, which is slower.
