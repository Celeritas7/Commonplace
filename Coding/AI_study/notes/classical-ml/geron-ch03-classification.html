In one line

1 · MNIST book p. 85 ↗

MNIST is 70,000 grayscale images of handwritten digits, each 28 × 28 pixels, which gives 784 features per image (pixel intensity 0–255). Each image comes with a label from 0 to 9. People test new classifiers on it so often that it is the field's standard warm-up dataset.

  • You get it with fetch_openml('mnist_784', version=1). Like most scikit-learn datasets, the result is a dict-like Bunch with data, target and DESCR.
  • The labels come back as strings. Convert them to integers (y.astype(np.uint8)) before you compare them with numbers.
  • It is already split: the first 60,000 images are the training set and the last 10,000 are the test set. Set the test set aside before you explore.
  • The training set is already shuffled. That keeps cross-validation folds similar, and it helps algorithms that are sensitive to row order (SGD).
  • Shuffling is a bad idea for time series, where the order carries meaning. Covered in later chapters.
fetch_openml now returns a pandas DataFrame by default (as_frame="auto"). Pass as_frame=False if you want NumPy arrays so that X[0].reshape(28, 28) works. The download is about 55 MB. The Python cell below uses the built-in 8 × 8 load_digits set (1,797 images, 64 features) instead, because it works offline.

2 · Training a binary classifier book p. 88 ↗

Start simple: a binary classifier separates just two classes. Here that is a "5-detector": the target is y == 5 (True/False).

  • SGDClassifier is a good first model. It is a linear model trained with stochastic gradient descent, and it handles very large datasets and online learning because it looks at one instance at a time.
  • With the default loss="hinge" it is a linear SVM. With loss="log_loss" it becomes logistic regression and gains predict_proba.
  • Training is random, so set random_state if you want the same result every run.

3 · Performance measures book p. 88 ↗

Evaluating a classifier is harder than evaluating a regressor. Most of the chapter is about this.

3.1 The accuracy trap book p. 89 ↗

Accuracy is the share of predictions that are correct. With 3-fold cross-validation (cross_val_score(..., scoring="accuracy")) the 5-detector scores above 93%. That sounds great until you notice that a model which always answers "not 5" scores about 90%, because only about 10% of images are 5s.

On skewed datasets (one class much more common than the others), accuracy mostly measures the class ratio. Always compare against a trivial baseline, for example DummyClassifier(strategy="most_frequent").
Writing cross-validation yourself

When you need more control than cross_val_score gives, loop over StratifiedKFold(...).split(X, y). In each fold, clone() the model, fit it on the training folds and score it on the held-out fold. Stratified folds keep the class ratio the same in every fold.

Since scikit-learn 0.24, StratifiedKFold(random_state=42) raises an error unless you also pass shuffle=True.

3.2 The confusion matrix book p. 90 ↗

A confusion matrix counts how often instances of each actual class were predicted as each class. Rows are actual classes, columns are predicted classes.

predicted negativepredicted positive
actually negativeTN — true negativeFP — false positive (false alarm)
actually positiveFN — false negative (miss)TP — true positive
  • To get honest predictions for every training row, use cross_val_predict(model, X, y, cv=3). Each prediction comes from a model that never saw that row. Then call confusion_matrix(y_true, y_pred).
  • Keep the test set untouched until the very end. Do this kind of analysis on out-of-fold predictions.
  • A perfect classifier has non-zero counts only on the main diagonal.

3.3 Precision, recall, F1 book p. 92 ↗

$$\text{precision}=\frac{TP}{TP+FP}\qquad \text{recall}=\frac{TP}{TP+FN}\qquad F_1=\frac{2}{\frac{1}{\text{precision}}+\frac{1}{\text{recall}}}=\frac{TP}{TP+\frac{FN+FP}{2}}$$
  • Precision: of everything the model flagged positive, how much really was positive.
  • Recall (also sensitivity or true positive rate, TPR): of all real positives, how many the model found.
  • F1 score: the harmonic mean of the two. It is high only when both are high, because the harmonic mean is dragged down by the smaller value.
  • Precision alone can be gamed: make one confident positive prediction, get it right, and precision is 100%. That is why you always report it with recall.
  • scikit-learn: precision_score, recall_score, f1_score, or classification_report for all three per class.

For the book's 5-detector, precision and recall are both only about 73–76%. That is far less impressive than the accuracy suggested.

The precision/recall trade-off: for a given model you can raise one only by lowering the other.

3.4 The trade-off and the decision threshold book p. 93 ↗

The classifier computes a score for each instance with its decision function. If the score is above the decision threshold, the instance is labelled positive. SGDClassifier uses a threshold of 0.

  • Raise the threshold → fewer positives are predicted → fewer false alarms (precision usually goes up) but more misses (recall goes down).
  • Lower the threshold → the reverse.
  • Recall can only fall as the threshold rises, so its curve is smooth. Precision usually rises, but it can dip for a moment when a true positive drops out before a false positive does. That is why the precision curve looks bumpy.

How to pick a threshold yourself:

  1. Get out-of-fold scores: cross_val_predict(clf, X, y, cv=3, method="decision_function").
  2. Get every candidate: precisions, recalls, thresholds = precision_recall_curve(y, scores). The first two arrays are one element longer than thresholds, so drop their last value when you plot against it.
  3. Plot precision and recall against the threshold, or precision against recall. Look for the point just before precision starts to fall steeply.
  4. For a target such as 90% precision, take the lowest threshold that reaches it: thresholds[np.argmax(precisions[:-1] >= 0.90)]. Then predict with scores >= t.

In the book, reaching 90% precision this way costs a lot: recall drops to about 44%.

Almost any precision is easy to reach: just raise the threshold. So when someone quotes a precision figure, ask what recall came with it. scikit-learn 1.5 added FixedThresholdClassifier (wrap a model and set its threshold) and TunedThresholdClassifierCV (choose the threshold by cross-validation to maximise a metric). You no longer have to apply the threshold to raw scores by hand. PrecisionRecallDisplay.from_predictions(y, scores) draws the PR curve in one line.

3.5 The ROC curve and AUC book p. 97 ↗

The ROC curve (receiver operating characteristic) plots the true positive rate (recall) against the false positive rate for every threshold.

$$\text{FPR}=\frac{FP}{FP+TN}=1-\text{TNR}\qquad \text{TNR}=\text{specificity}=\frac{TN}{TN+FP}$$
  • So the ROC curve is sensitivity vs. 1 − specificity. Compute it with fpr, tpr, thresholds = roc_curve(y, scores).
  • The diagonal is a random classifier. A good one bends toward the top-left corner.
  • ROC AUC (area under the curve, roc_auc_score): 1.0 is perfect, 0.5 is random. It equals the probability that a random positive gets a higher score than a random negative.
  • Models without decision_function, such as RandomForestClassifier, have predict_proba. Use the positive class's probability as the score: cross_val_predict(..., method="predict_proba")[:, 1].
  • In the book the random forest clearly beats SGD: ROC AUC ≈ 0.998 vs 0.96, about 99% precision at 87% recall.
ROC or PR curve? Prefer the PR curve when the positive class is rare, or when false positives matter more to you than false negatives. With few positives, FPR stays small even when there are many false alarms, so the ROC curve looks flattering. Otherwise the ROC curve is fine. RocCurveDisplay.from_predictions(y, scores) and RocCurveDisplay.from_estimator(clf, X, y) replace the hand-written plotting helper. The old plot_roc_curve and plot_precision_recall_curve functions were removed in 1.2. For a single-number PR summary, use average_precision_score.

4 · Multiclass classification book p. 100 ↗

Multiclass (or multinomial) classifiers choose among more than two classes. Some algorithms handle this natively (SGD, random forests, naive Bayes, and LogisticRegression today). Others are binary at heart (SVMs). You can build a multiclass model from binary ones in two ways:

One-versus-the-rest (OvR / OvA)One-versus-one (OvO)
Models trainedN: one detector per class$N(N-1)/2$: one per pair of classes (45 for 10 digits)
Data per modelthe whole training setonly the rows of the two classes involved
Predictionclass with the highest scoreclass that wins the most duels
Best formost binary algorithms (the default choice)algorithms that scale badly with training-set size, such as kernel SVMs
scikit-learnOneVsRestClassifier(est)OneVsOneClassifier(est)
  • scikit-learn chooses automatically. SVC trains OvO internally, and a fitted OneVsRestClassifier exposes its N models in estimators_.
  • decision_function then returns one score per class, and np.argmax of those scores gives the prediction.
  • The labels live in clf.classes_, sorted. Map an argmax index back through classes_[i]. It equals the class itself only when the labels happen to be 0…N−1.
  • Scaling the inputs with StandardScaler moved the book's 10-class SGD accuracy from about 87% to about 90%. Random guessing would get 10%.
SVC(decision_function_shape="ovr") is the default. It trains OvO but reshapes the pairwise votes into one score per class, which is why you see 10 scores rather than 45. The SGDClassifier loss names changed as well: "log" is now "log_loss" (the old name was removed in 1.3), and "squared_loss" is now "squared_error".

5 · Error analysis book p. 102 ↗

Once you have a promising model, study which mistakes it makes. The 10 × 10 confusion matrix is the main tool.

  1. Get out-of-fold predictions and the confusion matrix.
  2. Divide each row by its row total, so you compare error rates rather than raw counts. Otherwise common classes look worse just because they are common.
  3. Set the diagonal to zero so that only the errors remain, then display it as an image.
  • A bright column means many different digits get predicted as that class. In the book this is 8. A bright row means that class is often misread.
  • The matrix is not symmetric: 3→5 and 5→3 are separate cells. In the book, 3 and 5 are confused in both directions.
  • Ways to fix it: collect more examples of the digits that look like 8 but aren't; engineer features (for example, count closed loops: 8 has two, 6 has one, 5 has none); preprocess the images to make such patterns stand out.
  • Why 3 and 5 get mixed up: a linear model like SGD gives each pixel one weight per class and adds them up. 3 and 5 differ in only a few pixels (where the top stroke meets the lower curve), so a small shift or rotation flips the answer.
  • Centring and deskewing the images would reduce this error and others like it.
  • Looking at the individual misclassified images tells you more, but it takes time. Some are messy enough to fool a human.
confusion_matrix(y, y_pred, normalize="true") does the row division for you. ConfusionMatrixDisplay.from_predictions(y, y_pred, normalize="true") draws the heatmap with labelled axes in one line. sample_weight=(y_pred != y) keeps only the errors.

6 · Multilabel classification book p. 106 ↗

A multilabel classifier outputs several binary tags per instance. For example, a face tagger that knows Alice, Bob and Charlie outputs [1, 0, 1] for a photo of Alice and Charlie.

  • The book's toy example gives each digit two labels, "is it ≥ 7?" and "is it odd?", stacked with np.c_[...]. It then fits a KNeighborsClassifier, which supports multilabel targets natively. Not every classifier does.
  • Evaluation: compute a binary metric per label, then average it. f1_score(Y, Y_pred, average="macro") weights every label equally.
  • If some labels are much more common, use average="weighted", which weights each label by its support (the number of instances that have that label).
If a model can't do multilabel, wrap it: MultiOutputClassifier(est) trains one model per label. ClassifierChain also feeds earlier predictions into later models, so it can use correlations between labels.

7 · Multioutput classification book p. 107 ↗

Multioutput–multiclass classification (or just multioutput) generalises multilabel: each output can take more than two values.

  • Example: image denoising. The input is a noisy digit and the output is the clean image: one "label" per pixel, each with values from 0 to 255.
  • Recipe: add random integer noise to the pixels to make the inputs, use the original images as targets, and fit a KNeighborsClassifier on (noisy → clean).
  • The boundary between classification and regression is blurry here. Predicting pixel intensities is arguably regression, and a multioutput system can mix class outputs with numeric ones.
  • The book peeks at a test image for the demo and admits it is cheating a little.

8 · Exercises book p. 108 ↗

  1. Get over 97% test accuracy on MNIST. Hint: KNeighborsClassifier with a grid search over weights and n_neighbors.
  2. Write a function that shifts an image one pixel up, down, left or right. Add four shifted copies of every training image, retrain, and compare. This is data augmentation (training set expansion). scipy.ndimage.shift(img, [dy, dx], cval=0) does the shifting. The book's scipy.ndimage.interpolation path is deprecated.
  3. Work through the Titanic dataset (Kaggle).
  4. Build a spam classifier from the SpamAssassin corpus: split the data, write a pipeline that turns each email into a sparse word-presence or word-count vector (with options for lowercasing, stripping headers and punctuation, replacing URLs and numbers, and stemming), then try several models and aim for high precision and high recall.
For exercise 4, CountVectorizer or TfidfVectorizer (binary=True for presence/absence) replaces most of the hand-written pipeline.

Test yourself

Answer out loud first, then click the card.

A fraud model is 99.5% accurate and 0.5% of transactions are fraud. Impressed?
No. Answering "not fraud" every time also scores 99.5%. Check the confusion matrix, precision and recall.
In scikit-learn's confusion matrix, what do rows and columns mean?
Rows are the actual classes, columns are the predicted classes. For binary labels: [[TN, FP], [FN, TP]].
Precision vs recall in one phrase each?
Precision: how many of the flagged items were right. Recall: how many of the real positives were found.
Why is F1 a harmonic mean rather than an average?
The harmonic mean is pulled toward the smaller value, so F1 is high only if precision and recall are both high.
You raise the decision threshold. What happens to recall and precision?
Recall can only fall or stay the same. Precision usually rises, but it can dip at some steps.
Positives are 1% of the data. ROC curve or PR curve?
PR curve. With so many negatives, FPR stays tiny even when there are lots of false alarms, so the ROC curve looks too good.
10 classes with a kernel SVM: OvR or OvO, and how many models?
OvO: 45 small models. Kernel SVMs scale badly with the number of rows, so many small training sets are faster. SVC does this internally.
Multilabel vs multioutput?
Multilabel: several yes/no tags per instance. Multioutput: several outputs, each of which can have many values (for example, every pixel of a denoised image).
