Installing Python — Anaconda, and why you already have it

You installed this months ago and may not know what you got. Before adding anything new, let's find out what's already on the machine — because it is almost certainly enough.

8 sections~10 minUses your own machine
1

Why this matters

The most common way to lose an afternoon in Python is to install it twice.

You type pip install pandas, it reports success, you run your script, and Python says ModuleNotFoundError: No module named 'pandas'. Nothing is broken. You simply installed pandas into one Python and ran your script with a different one.

So this lesson is mostly not about installing. It is about finding out what is already on your machine and learning to ask which Python is speaking. Do that once, properly, and the whole class of problem disappears.

✨ Newly written

Your machine already has Anaconda — there is an anaconda3 folder in your home directory, along with .conda, .jupyter, .ipython and .matplotlib. Those last four are settings folders that only appear once you have actually run the tools. You are not starting from zero.

2

The mental model

A Python installation is three things that travel together:

The interpreter

One executable file — python.exe on Windows. This is the program that reads your source and acts on it.

The standard library

A folder of modules that ship with it: math, random, json, pathlib. Always there, no install needed.

And the third: a site-packages folder, where everything you pip install lands. Each interpreter has its own. That is the whole source of the confusion — pandas installed for interpreter A is invisible to interpreter B.

Anaconda is a distribution: one interpreter, plus about 250 pre-installed packages including NumPy, pandas, Matplotlib and Jupyter, plus conda, a tool for making more interpreters when a project needs a different set. For what this book covers, the one Anaconda gives you is enough. You will not need to create an environment until you hit two projects that need conflicting versions.

📖 From your notes

Your document-processing toolkit already runs on Windows + Anaconda Python — so this is the same interpreter you have been using for the PDF and Word conversion work, not a new one to learn.

3

Walk-through

Three commands answer everything. Open Anaconda Prompt from the Start menu (not plain Command Prompt — Anaconda Prompt has the paths already set up).

Anaconda Prompt
# 1 — which Python is answering, and what version?
python --version

# 2 — where does that executable actually live?
where python

# 3 — what is already installed for it?
conda list
1Should print something like Python 3.12.x. Anything 3.10 or newer is fine for this book. If it prints 2.7, you are talking to a different, very old Python — see the mistakes below. 2The important one. It lists every python.exe on your PATH, in the order Windows searches. The first line is the one that runs. If you see several, that is your future ModuleNotFoundError waiting to happen. 3A long list. Scroll for numpy, pandas, matplotlib, jupyter. If they are there — and with Anaconda they will be — you need install nothing for Parts 0 through XI.

There is a fourth command worth knowing, because it is the one that settles arguments:

Anaconda Prompt
python -c "import sys; print(sys.executable)"

That asks Python itself where it lives, rather than asking Windows. When where python and sys.executable disagree, believe sys.executable — it is the one actually running your code.

4

Try it

This one is not a puzzle. Go and run it.

Open Anaconda Prompt and run all four commands above. Then answer three questions, in a notes file you keep:

1. What version of Python answers?  2. How many python.exe did where python list?  3. Are numpy, pandas and matplotlib in conda list?

✨ Newly written

If the answer to 2 is "more than one", do not panic and do not uninstall anything. Multiple Pythons are normal — Windows itself ships one, and so does the Microsoft Store. The rule is simply: always launch from Anaconda Prompt, and you will always get the Anaconda one.

5

Predict the output

You run pip install requests in an ordinary Command Prompt. It says Successfully installed requests. Then you open Anaconda Prompt, start Python, and type import requests. What is the most likely result?

ModuleNotFoundError. The plain Command Prompt found some other pip on the PATH — the Windows Store Python, most likely — and installed requests into that interpreter's site-packages. Anaconda's Python cannot see it.

This is the single most common Python setup problem, and it has nothing to do with Python being badly designed. It is just PATH. The cure is a habit, not a fix: install and run from the same prompt, every time. For you, that means Anaconda Prompt.

6

What trips people here

🔀
Installing a second Python from python.org

You already have Anaconda. Adding the python.org installer gives you two interpreters competing for the same PATH, and every pip install becomes a coin flip. If you want a specific version later, use conda create — it keeps them separate on purpose.

📛
'python' is not recognized as an internal or external command

You are in plain Command Prompt, not Anaconda Prompt. Anaconda deliberately does not put itself on the global PATH by default, because doing so breaks other software. Use the Anaconda Prompt shortcut and the message goes away.

🧊
Treating conda and pip as interchangeable

Both install packages, into the same folder, without telling each other. Rule of thumb: prefer conda install <name>; fall back to pip install <name> only when conda does not have the package. Mixing them freely is how an environment gets quietly wrecked.

8

Quick recap

What to carry forward

  • You already have Anaconda — an interpreter plus ~250 packages. Nothing to install for most of this book.
  • A package is installed for one interpreter, not for the machine. That is the whole reason ModuleNotFoundError happens.
  • where python shows what Windows will run; sys.executable shows what is running. Trust the second.
  • Launch from Anaconda Prompt, always. One habit removes an entire category of problem.
  • Prefer conda install; use pip only when conda hasn't got it.
