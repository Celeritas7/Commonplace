*args and **kwargs

Accept any number of arguments, or forward a whole call unchanged. The stars look cryptic and mean exactly one thing: pack them up, or spread them out.

8 sections~11 minLinks to a live notebook
1

Why this matters

C's variadic functions are the unsafe corner of the language — va_list, a format string the compiler mostly cannot check, and undefined behaviour when they disagree.

Python's version is safe and, once the notation clicks, ordinary. *args collects extra positional arguments into a tuple. **kwargs collects extra keyword arguments into a dict. That is genuinely all they do.

You already rely on this: print("a", "b", "c") takes any number of things because print is defined with *args.

2

The mental model

In a definition, the stars pack.

packing.py
def total(*args):
    print(type(args).__name__, args)   # tuple (1, 2, 3)
    return sum(args)

print(total(1, 2, 3))       # 6
print(total())              # 0 — zero arguments is fine

def tag(**kwargs):
    print(type(kwargs).__name__, kwargs)  # dict {'colour': 'red'}

tag(colour="red", size=10)

# both, with ordinary parameters first
def record(name, *values, unit="mm", **meta):
    print(name, values, unit, meta)

record("bolt", 10, 12, 14, unit="cm", batch="B7")
# bolt (10, 12, 14) cm {'batch': 'B7'}

The signature order is fixed and worth memorising: ordinary, *args, keyword-only, **kwargs. The names args and kwargs are convention only — the stars do the work — but use them anyway, because every Python reader expects them.

3

Walk-through

In a call, the same stars unpack — the exact opposite direction.

unpacking.py
def area(w, h):
    return w * h

dims = (3, 4)
print(area(*dims))            # same as area(3, 4)

opts = {"w": 3, "h": 4}
print(area(**opts))           # same as area(w=3, h=4)

# the real use — forwarding a whole call untouched
def logged(fn, *args, **kwargs):
    print(f"calling {fn.__name__}")
    result = fn(*args, **kwargs)     # spread them back out
    print(f"  → {result}")
    return result

logged(area, 3, 4)
logged(area, w=5, h=2)
*dims in a callSpreads the tuple into separate positional arguments. Without the star, area(dims) passes the tuple as a single argument and fails. **opts in a callSpreads the dict into keyword arguments. The keys must match the parameter names exactly. loggedThis is the payoff. It accepts any call, forwards it unchanged, and adds behaviour around it. Every decorator, wrapper and middleware in Python is built on these four lines.

5

Predict the output

The same tuple, passed two ways. What does each print?

stars.py
def show(*args):
    print(len(args), args)

dims = (3, 4)
show(dims)
show(*dims)
1 ((3, 4),) then 2 (3, 4).

The first call passes one argument that happens to be a tuple. *args packs that single argument into a one-element tuple — hence the nested-looking ((3, 4),), with the trailing comma from 3.3 marking a one-tuple.

The second call spreads the tuple first, so two separate arguments arrive and args is (3, 4).

This is the whole distinction: a star in a def packs; a star in a call unpacks. Same symbol, opposite directions, and which one you are reading depends entirely on where it sits.

6

What trips people here

🔀
Wrong order in the signature

def f(*args, x) makes x keyword-only, which may not be what you meant. The fixed order is ordinary → *args → keyword-only → **kwargs.

✳️
Forgetting the star when forwarding

fn(args, kwargs) passes a tuple and a dict as two ordinary arguments. It needs fn(*args, **kwargs). The symptom is a TypeError about argument counts that looks baffling until you spot the missing stars.

🎯
Reaching for **kwargs too early

It makes a signature that documents nothing — the reader cannot see what the function accepts, and typos in keyword names pass silently into the dict. Use named parameters with defaults unless you genuinely need to forward an unknown call.

8

Quick recap

What to carry forward

  • In a def, *args packs extra positionals into a tuple; **kwargs packs extra keywords into a dict.
  • In a call, * and ** do the opposite — they spread a tuple or dict into arguments.
  • Signature order is fixed: ordinary → *args → keyword-only → **kwargs.
  • fn(*args, **kwargs) forwards a whole call unchanged — the basis of every wrapper.
  • f(dims) and f(*dims) are completely different calls.
  • Don't use **kwargs where named parameters would do — it hides the interface.
