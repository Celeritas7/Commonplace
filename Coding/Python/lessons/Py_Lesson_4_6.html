Lambdas and higher-order functions

Functions are values. Once that lands, you can pass them to other functions — which is what sorted(), max() and every key= argument are really doing.

8 sections~11 minLinks to a live notebook
1

Why this matters

In 4.1 you saw say = greet tie a second name to a function. That was not a curiosity — it is the basis of this lesson.

Because functions are ordinary objects, they can be passed as arguments. A function that takes another function is called higher-order, and you have already used several: sorted(), max(), min() all accept a key= argument that is a function.

C has function pointers, and they work — but the syntax is heavy enough that you use them rarely. In Python it is common enough to need a shorthand, and that shorthand is lambda.

2

The mental model

A lambda is a function written as an expression: no name, no def, no return. The body is a single expression whose value is returned.

lambda.py
# these two are the same function
def double(n):
    return n * 2

double = lambda n: n * 2      # works, but see section 6

# the real use: passed inline, never named
parts = [("bolt", 40), ("nut", 12), ("pin", 7)]

print(sorted(parts))                          # by name — the default
print(sorted(parts, key=lambda p: p[1]))       # by quantity
print(max(parts, key=lambda p: p[1]))          # biggest quantity

Limits, deliberately. A lambda holds one expression — no statements, no if/else blocks (the ternary is fine), no loops, no assignments. If you need any of those, you need def. That restriction is the point: a lambda is for things too small to deserve a name.

3

Walk-through

key= is where you will meet this in real work. It takes a function, calls it on each item, and sorts by whatever comes back.

key.py
stock = [
    {"name": "bolt",   "qty": 40},
    {"name": "nut",    "qty": 12},
    {"name": "washer", "qty": 7},
]

# sort dicts by a field
by_qty = sorted(stock, key=lambda d: d["qty"])
most   = max(stock, key=lambda d: d["qty"])

# descending
top = sorted(stock, key=lambda d: d["qty"], reverse=True)

# case-insensitive sort — key can be any function, not just a lambda
names = ["Zebra", "apple", "Mango"]
print(sorted(names))                  # ['Mango','Zebra','apple'] — 1.7!
print(sorted(names, key=str.lower))    # ['apple','Mango','Zebra']

# sort by two things: a tuple key
sorted(stock, key=lambda d: (-d["qty"], d["name"]))
key=Receives one item and returns the value to sort by. It is not a comparison function — there is no a, b pair like C's qsort. str.lowerA plain function passed by name, no lambda needed. When a suitable function already exists, use it — it is clearer than wrapping it. tuple keySorts by the first element, then breaks ties with the second. The minus sign reverses just that one field. Predict the output

What does the key function receive on each call?

what.py
parts = [("bolt", 40), ("nut", 12)]
sorted(parts, key=lambda p: p[1])
One item. p is ("bolt", 40), then ("nut", 12). The lambda returns 40, then 12, and Python sorts by those values.

This is worth stating because it differs from C's qsort, where the comparator receives two items and returns −1, 0 or 1. Python's key= is a transformation, not a comparison: “what should I sort this item by?”

The consequence is that it is called once per item rather than once per comparison, which is both faster and much easier to get right — there is no way to write an inconsistent comparator.

6

What trips people here

🏷️
Assigning a lambda to a name

double = lambda n: n * 2 works, but def double(n): is clearer, gets a real name in tracebacks, and can carry a docstring. If it deserves a name, it deserves a def. Lambdas are for inline use.

📏
Cramming logic into a lambda

No statements allowed, so people force it with nested ternaries. When you reach that point, write a small def just above and pass it by name — key=quantity_of reads better than any lambda.

🔁
Lambdas in a loop capturing the loop variable

[lambda: i for i in range(3)] gives three functions that all return 2, because they capture the variable, not its value at the time. The fix is a default argument: lambda i=i: i. This one is genuinely subtle and worth knowing exists.

8

Quick recap

What to carry forward

  • Functions are objects — pass them as arguments, store them, return them.
  • lambda args: expression is a nameless one-expression function. No statements, no loops.
  • key= takes a function of one item and returns what to sort by — a transformation, not a comparison.
  • Pass an existing function by name when there is one: key=str.lower.
  • A tuple key sorts by several fields; -x reverses one numeric field.
  • If it deserves a name, use def. Lambdas are for inline use only.
