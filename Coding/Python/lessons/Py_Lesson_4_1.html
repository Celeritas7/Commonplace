Defining and calling; why functions exist

No return type, no prototype, no header file. A Python function is four lines of ceremony less than a C one — which makes it cheap enough to write the small ones you would otherwise skip.

8 sections~11 minLinks to a live notebook
1

Why this matters

In C, adding a small helper means a prototype, a return type, a definition, and often a header edit. The friction is enough that you inline the logic instead.

Python's version is def, a name, and a colon. That is the whole declaration. No return type to choose, no forward declaration, no separate header.

The consequence is behavioural rather than technical: because a function costs nothing to write, you write the three-line ones. And it is those small named pieces — is_valid(), clean(line), average(values) — that make a program readable, far more than any comment.

2

The mental model

def creates a function object and ties a name to it — the same binding you learned in 1.1. Functions are objects: you can pass them around, store them in lists, return them from other functions. That becomes the point of 4.6.

shape.py
def greet(name):
    """Return a greeting for name."""     # docstring — 4.4
    return f"Hello, {name}"

msg = greet("Aniket")     # the CALL — parentheses do it
print(msg)

print(greet)               # <function greet at 0x...> — the object
say = greet                # a second name for the same function
print(say("Cobra"))        # works

Walk-through

Definition and call are two separate moments, and confusing them causes the error in section 5.

moments.py
# --- definition time: Python stores the body, runs nothing ---
def area(w, h):
    print("computing...")
    return w * h

print("defined")          # prints first — no "computing..." yet

# --- call time: now the body runs ---
a = area(3, 4)         # prints "computing..." and returns 12
b = area(5, 2)         # runs again, independently

# a function with no return gives None
def log(msg):
    print(f"[log] {msg}")

result = log("started")
print(result)              # None

When to extract a function, in practice: when a block needs a comment to explain it (the function name replaces the comment), when the same logic appears twice, or when a function has grown past about twenty lines and has an obvious inner step.

Naming: lowercase with underscores, and a verb — calculate_total, load_readings, is_valid. Functions answering yes/no conventionally start with is_ or has_, which makes if is_valid(row): read as a sentence.

Predict the output

What happens when this file runs?

order.py
print(double(5))

def double(n):
    return n * 2
NameError: name 'double' is not defined. Python runs the file top to bottom. At line 1 the def has not executed yet, so no name double exists.

This is the interpreted/compiled difference from 0.1 showing up again. A C compiler reads the whole file before generating anything, so it can resolve a call to a function defined later. Python simply has not got there yet.

Two useful consequences. Define before you call at the top level. But a function may freely call another defined below it, as long as neither runs until both definitions have — which is why the standard layout is: all the defs, then the code that uses them at the bottom.

6

What trips people here

()
Forgetting the parentheses when calling

result = greet ties result to the function object rather than calling it. No error — and then print(result) shows <function greet at 0x...>. Whenever output looks like that, a call is missing its ().

🕳️
Forgetting to return

A function that computes and prints but never returns gives back None. total = add(2, 3) then leaves total as None, and the failure surfaces later in an arithmetic error. If a function's job is to produce a value, it must return it.

📛
Naming a function after a built-in

def sum(...) shadows the built-in sum for the rest of the file — the same shadowing problem as 1.1, and harder to spot because the code reads perfectly well.

8

Quick recap

What to carry forward

  • def name(params): and an indented body. No return type, no prototype.
  • def creates a function object and binds a name — functions are values you can pass around.
  • The body runs only when called. Definition and call are separate moments.
  • Define before you call at the top level — Python reads the file in order.
  • No return means the function returns None.
  • f is the function; f() calls it. Missing parentheses fails silently.
