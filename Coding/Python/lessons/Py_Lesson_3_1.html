Lists — building, mutating, growing

A list is a growable array that holds anything. No size to declare, no realloc, no element type — and one consequence about copying that you met in 1.1 and will meet again here.

8 sections~12 minLinks to a live notebook
1

Why this matters

In C, a growable array of strings means malloc, a capacity, a count, realloc when it fills, and free at the end.

In Python it is [], and then you .append() to it. The list handles its own memory, grows when needed, and holds objects of any type — including a mix.

The one thing to carry from 1.1: a list is mutable. Two names can point at the same list, and changing it through one is visible through the other. That property is what makes lists useful and what makes them the thing to be careful with.

2

The mental model

An ordered, mutable sequence. Ordered means position is meaningful and stable — item 0 stays item 0 until you move it.

lists.py
parts = ["bolt", "nut", "washer"]
mixed = [1, "two", 3.0, True, [4, 5]]   # all legal
empty = []

print(len(parts))       # 3
print(parts[0])         # bolt
parts[0] = "screw"      # lists CAN be changed in place

That last line is the difference from strings. s[0] = "J" was an error in 1.3; parts[0] = "screw" is fine. Lists are mutable, strings are not.

The methods split into two groups, and confusing them is the source of most list bugs:

Change in place

.append() .extend() .insert() .remove() .pop() .sort() .reverse() — these modify the list and return None.

Build something new

+, sorted(), reversed(), slicing — these leave the original alone and hand you a new object.

Walk-through

The methods you will use weekly.

methods.py
parts = ["bolt", "nut"]

parts.append("washer")         # add ONE item at the end
parts.extend(["pin", "clip"])  # add SEVERAL
parts.insert(0, "screw")       # add at a position

parts.remove("nut")            # delete by VALUE (first match)
last = parts.pop()             # remove & return the last
first = parts.pop(0)           # remove & return by INDEX

print(parts.count("pin"))      # how many
print(parts.index("pin"))      # where (raises if absent)
print("pin" in parts)          # yes/no — prefer this for a test

# in place vs new
nums = [3, 1, 2]
nums.sort()                      # nums is now [1,2,3]; returns None
ordered = sorted([3, 1, 2])      # original untouched; returns a NEW list
append vs extendappend([1,2]) adds the list itself as one item, giving a nested list. extend([1,2]) adds its two elements. Mixing them up produces a list that looks almost right. remove vs popremove takes a value and returns nothing; pop takes an index and returns the item. remove on a missing value raises ValueError. .sort() vs sorted()The method sorts in place and returns None. 5

Predict the output

Sorting a list of readings. What does this print?

sortbug.py
nums = [3, 1, 2]
nums = nums.sort()
print(nums)
None. .sort() sorted the list in place and returned None — and the assignment then replaced nums with that None. The sorted list existed for an instant and was thrown away.

This is the most common list bug in Python, and it follows a rule worth internalising: methods that mutate return None. That applies to .sort(), .reverse(), .append(), .extend() — all of them. It is deliberate, precisely so that x = y.sort() fails loudly instead of quietly looking right.

Either nums.sort() on its own line, or nums = sorted(nums). Never both.

6

What trips people here

✖️
Building a grid with [[0] * 3] * 3

This makes three references to the same inner list, so grid[0][0] = 1 changes all three rows. * repeats the reference, not the object. Use a comprehension: [[0] * 3 for _ in range(3)].

📋
Assuming b = a copies

Straight from 1.1, and it bites hardest with lists. Use a.copy() or a[:] for a shallow copy; copy.deepcopy(a) when the list contains other lists.

🗑️
Removing items while iterating

Covered in 2.3 and worth repeating, because lists are where it happens. Build a new list with a comprehension instead — 3.6.

8

Quick recap

What to carry forward

  • A list is a growable, ordered, mutable sequence that holds any mix of types.
  • Mutating methods return None — x = items.sort() gives you None.
  • .sort() in place; sorted() returns a new list. Same for .reverse() / reversed().
  • .append(x) adds one item; .extend(xs) adds each of several.
  • .remove(value) vs .pop(index) — one takes a value, one an index and returns it.
  • [[0]*3]*3 repeats a reference. Use a comprehension for grids.
