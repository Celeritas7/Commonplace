Return values, multiple returns, docstrings

A function that returns nothing is a function you cannot test. This is about giving values back properly — including several at once — and writing the one sentence that explains what a function is for.

8 sections~11 minLinks to a live notebook
1

Why this matters

There are two things a function can do with a result: print it, or return it. The difference decides whether the function is reusable.

A function that prints has done its one job and thrown the value away. You cannot add its result to another, store it, test it, or write it to a file. A function that returns can do all four — and the caller can print it if that is what is wanted.

Compute and return; let the caller decide about output. That single habit is most of what separates a script from a program.

2

The mental model

return hands a value back and ends the function immediately.

returns.py
def average(values):
    if not values:               # truthiness from 2.2
        return 0                 # early return — done here
    return sum(values) / len(values)

# several values: really one tuple (3.3)
def stats(values):
    return min(values), max(values), sum(values) / len(values)

lo, hi, avg = stats([4, 9, 2])     # unpack all three
everything = stats([4, 9, 2])         # or keep the tuple

Early return is worth adopting deliberately. Handle the awkward cases at the top and return; the main logic then sits unindented at the bottom instead of nested inside an else. This is the fix for the deep nesting flagged in 2.1.

early.py
# nested — the real work is two levels in
def process(row):
    if row:
        if row.get("qty"):
            return row["qty"] * 2
    return 0

# early return — the real work is at the top level
def process(row):
    if not row:
        return 0
    if not row.get("qty"):
        return 0
    return row["qty"] * 2

Walk-through

The docstring is a string literal as the first statement in the function. Tools read it, help() prints it, and editors show it on hover.

doc.py
def average(values):
    """Return the mean of values, or 0 for an empty sequence.

    Args:
        values: a sequence of numbers.

    Returns:
        float: the arithmetic mean, or 0 if values is empty.
    """
    if not values:
        return 0
    return sum(values) / len(values)

help(average)              # prints the docstring
print(average.__doc__)     # same text, as a string
first lineOne sentence, imperative — “Return the mean”, not “This function returns…”. For a short function this line alone is enough. the edge caseSay what happens for empty input, zero, or missing keys. That is the part a reader cannot infer, and the part you will forget in three months. triple quotesFrom 1.3. They allow the multi-line form, and are used even for one-liners by convention. help()Works on anything — help(str.split), help(list). Faster than a web search when you just need the signature.

5

Predict the output

Three functions, three returns. What does each print?

nothing.py
def a():
    return 1

def b():
    return

def c():
    print("hi")

print(a(), b(), c())
It prints hi first, then 1 None None.

Python evaluates the three calls before printing, so c()'s own print runs first. Then the outer print shows the three return values.

A bare return is not “return nothing” — it is return None. And c(), which never returns at all, also gives None. Falling off the end of a function is identical to return None.

This is why the print-versus-return distinction bites: total = c() looks like it worked, prints the right thing on screen, and leaves total as None. The failure appears later, in arithmetic, far from the cause.

6

What trips people here

🖨️
Printing instead of returning

The function can then only ever be used one way. If you want both, return the value and let the caller print — or return it and print, but never print only.

🎭
Returning different types from different branches

return 0 in one branch and return "error" in another means every caller must check the type before using it. Prefer None for “no result”, or raise an exception (Part V) for a real failure.

🚪
Code after an unconditional return

return exits immediately, so anything below it in that branch never runs. No warning — the lines simply sit there looking functional. Some editors grey them out; Python says nothing.

8

Quick recap

What to carry forward

  • Compute and return; let the caller print. A printing function cannot be reused or tested.
  • return exits immediately. Code after it in that branch never runs.
  • Returning several values returns one tuple — unpack it at the call site.
  • A bare return, and falling off the end, both give None.
  • Early return for edge cases keeps the main logic unindented.
  • A docstring is the first statement, in triple quotes. One imperative sentence, plus the edge cases.
