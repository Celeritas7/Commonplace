Dictionaries — keys, lookup, iteration

Look something up by name instead of by position. This is the collection you will reach for most, and it is the shape of every JSON file, every CSV row, and every configuration you will ever read.

8 sections~13 minLinks to a live notebook
1

Why this matters

A list answers “what is at position 3?”. A dictionary answers “what is stored under this name?”.

Finding a part by number in a list means scanning it — and the longer the list, the longer that takes. A dictionary finds it in the same time whether it holds ten entries or ten million, because it hashes the key straight to the value.

In C this is a hash table you write yourself, or borrow. In Python it is built into the language, has its own syntax, and underpins JSON, CSV rows, function keyword arguments and object attributes. Learning it well pays back across the whole book.

2

The mental model

Keys and values, in braces, separated by colons.

dicts.py
part = {
    "code": "A-10",
    "name": "bolt",
    "qty":  40,
}

print(part["name"])       # bolt
part["qty"] = 35          # update
part["supplier"] = "X"   # add — same syntax
del part["supplier"]      # remove

Two rules govern what can go where.

Keys must be immutable — string, number, tuple. Not a list. This is where 3.3 pays off: Python needs to hash the key, and hashing something that can change underneath it would break the table. {[1,2]: "a"} raises TypeError: unhashable type: 'list'.

Values can be anything, including other dicts and lists. Nested dicts are how JSON is represented, and you will see them constantly in Part X.

Since Python 3.7 dictionaries also keep insertion order, so looping gives you keys back in the order you added them.

3

Walk-through

Lookup, and the three ways to iterate.

access.py
stock = {"bolt": 40, "nut": 12, "washer": 0}

# [] raises KeyError if absent; .get() returns None (or a default)
print(stock["bolt"])              # 40
print(stock.get("pin"))            # None
print(stock.get("pin", 0))         # 0   ← the useful form

if "nut" in stock:                # membership tests KEYS
    print("we stock nuts")

# iterate — keys, values, or both
for name in stock:                 # default: keys
    print(name)

for qty in stock.values():
    print(qty)

for name, qty in stock.items():    # ← the one you want most
    print(f"{name}: {qty}")
.get(k, default)The most useful method on a dict. No exception, and you choose what “absent” means. stock.get(name, 0) treats a missing part as zero stock, which is usually right. inTests keys, never values — the trap from 2.2. For values, 40 in stock.values(). .items()Yields (key, value) tuples, which the for unpacks — tuple unpacking from 3.3 again. This is the standard way to walk a dict. orderingInsertion order is preserved. Do not confuse that with sorted — use sorted(stock.items()) if you want alphabetical.

Predict the output

Reading a key that is not there. What happens on each line?

missing.py
stock = {"bolt": 40}

a = stock.get("pin", 0)
b = stock["pin"]
a is 0; b raises KeyError: 'pin'.

Both behaviours are correct — the choice is yours, and it should be deliberate.

Use [] when the key must exist and its absence is a bug you want to hear about immediately. A loud KeyError naming the key beats a silent None propagating through three functions before failing somewhere unrelated.

Use .get(key, default) when absence is normal — optional configuration, a part you have not stocked yet, a field some records omit.

The mistake is reaching for .get() everywhere to avoid errors. That converts a clear failure into a confusing one.

6

What trips people here

🔑
Expecting in to search values

"Tokyo" in record is False even when a value is "Tokyo". Keys only. Use .values() or .items().

🧊
Trying to use a list as a key

TypeError: unhashable type: 'list'. Convert to a tuple: tuple(my_list). This is the practical reason tuples exist.

🔁
Changing the dict while looping over it

RuntimeError: dictionary changed size during iteration. Unlike the list version in 2.3, this one at least tells you. Loop over list(stock.keys()) if you must delete as you go.

8

Quick recap

What to carry forward

  • A dict looks up by name, in constant time — size does not matter.
  • Keys must be immutable (str, int, tuple). Values can be anything.
  • d[k] raises KeyError when absent; d.get(k, default) does not. Choose deliberately.
  • in tests keys. For values, d.values().
  • for k, v in d.items(): is the standard walk — tuple unpacking again.
  • Insertion order is preserved (3.7+), but that is not the same as sorted.
