while loops — accumulator and sentinel patterns

Use for when you know the collection. Use while when you don't know how many times — waiting on a user, a file, a condition. Two patterns cover almost every real case.

8 sections~11 minLinks to a live notebook
1

Why this matters

A for loop needs to know what it is walking. A while loop does not.

That is the whole basis for choosing between them. Reading every line of a file, every item in a list, every number in a range — for. Asking until the user types something valid, retrying until a connection succeeds, iterating until a value converges — while.

The cost is that while gives you no automatic progress. A for loop always ends because the collection runs out. A while loop ends only if you make its condition false, and forgetting to is how you write your first infinite loop.

2

The mental model

Every correct while has three parts, and they are easy to see once named.

three-parts.py
count = 0              # 1. SET UP  — before the loop

while count < 5:        # 2. TEST    — checked before every pass
    print(count)
    count += 1         # 3. UPDATE  — must move toward the test failing

Drop part 3 and the loop runs forever. There is no compiler to warn you; the program simply never returns. (Ctrl-C stops it.)

Two shapes cover most real uses:

Accumulator

A running total or collection built up across passes. Set it up empty, add to it each time, use it after.

Sentinel

Loop until a special value appears — the user types quit, a reading goes out of range, a file line is blank.

Walk-through

Both patterns, and the safe-input loop you will reuse constantly.

patterns.py
# ACCUMULATOR — build a total
total, n = 0, 1
while n <= 100:
    total += n
    n += 1
print(total)                    # 5050

# SENTINEL — loop until a signal value
line = input("> ")
while line != "quit":
    print(f"you said {line}")
    line = input("> ")      # the update — easy to forget

# the while-True + break idiom: no duplicated input line
while True:
    line = input("> ")
    if line == "quit":
        break
    print(f"you said {line}")
accumulatortotal and n both set up before. Note this particular one is better as sum(range(1, 101)) — while earns its keep when the count is genuinely unknown. sentinelNotice input() appears twice — once before the loop, once at the end of the body. That duplication is the classic annoyance of the sentinel shape. while True + breakRemoves the duplication by testing in the middle. Not a hack — it is the idiomatic Python answer, and it is what you already wrote in 1.6 for safe input.

Predict the output

Where the update sits. What does this print?

update.py
n = 0
while n < 3:
    n += 1
    print(n)
1 2 3. The increment happens before the print, so the first value shown is 1, and the last pass takes n from 2 to 3 and prints 3 — the test only runs again afterwards, and 3 < 3 is false.

Move n += 1 below the print and you get 0 1 2 instead. Same three lines, same three passes, different output — because the update's position decides whether you see the value before or after it changes.

This is the whole reason for n in range(3) is preferred where it fits: it gives 0 1 2 with no decision to get wrong.

6

What trips people here

♾️
Forgetting the update

The commonest while bug, and it hangs rather than crashing. If a program stops responding, this is the first suspect. Ctrl-C in a terminal, or the stop button in a notebook, breaks out.

🎯
Updating the wrong variable

while i < n: with j += 1 in the body. The test and the update must involve the same name. Easy to do when a loop grows and picks up a second counter.

🔂
Using while where for fits

i = 0; while i < len(items): ... ; i += 1 is three chances to make a mistake instead of none. If you know what you are walking, use for.

8

Quick recap

What to carry forward

  • for when you know what you're walking; while when you don't know how many times.
  • Every while needs set up · test · update. Missing the update hangs the program.
  • Accumulator: build a total or list across passes. Sentinel: loop until a signal value.
  • while True: with break is idiomatic — it avoids duplicating the read.
  • Where the update sits decides what you see. n += 1 before or after the print gives different output.
  • Ctrl-C stops a runaway loop.
