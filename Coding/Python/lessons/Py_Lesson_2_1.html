if / elif / else, and nesting

No braces, no parentheses — the indentation is the block. That one decision shapes how Python code looks, and it turns a familiar C bug into an impossible one.

8 sections~11 minLinks to a live notebook
1

Why this matters

In C the braces say what is inside the if, and the indentation is a courtesy to the reader.

Python removes the braces and promotes the courtesy to law. Whatever is indented under the if is the block; when the indentation goes back out, the block has ended.

The trade is real. You lose the freedom to format however you like. You gain the guarantee that the code's appearance and its behaviour cannot disagree — which kills the C bug where a stray semicolon or a missing brace makes an indented line run unconditionally. In Python there is nothing to get out of sync.

2

The mental model

Three keywords, and a colon at the end of each condition line.

shape.py
if temp > 40:
    print("too hot")
elif temp < 5:
    print("too cold")
else:
    print("fine")

Four things to notice, all of which differ from C:

No parentheses around the condition. if (temp > 40): works but marks you as visiting from another language.

A colon ends every line that opens a block. Forgetting it gives SyntaxError: expected ':' — a clear message, and the most common beginner error.

elif, one word. Not else if. Python needs it because else followed by a nested if would indent one level deeper each time, and a five-way choice would march off the right of the screen.

Exactly one branch runs. Python tests each condition in order and takes the first that is true. The rest are skipped, even if they are also true — which is why order matters, as section 5 shows.

3

Walk-through

Nesting, and the standard four spaces.

grade.py
score = int(input("Score: "))

if score >= 0 and score <= 100:
    if score >= 90:
        grade = "A"
    elif score >= 75:
        grade = "B"
    else:
        grade = "C"
    print(f"grade {grade}")
else:
    print("score out of range")

print("done")   # no indent — always runs
4 spacesThe convention, from PEP 8. Any consistent amount works, but every editor and every other Python programmer expects four. Configure your editor to insert spaces on Tab and never think about it again. the inner blockIndented eight spaces — two levels. The print(f"grade {grade}") at four spaces is inside the outer if but after the inner chain, so it runs for any valid score. print("done")Zero indent, so it is outside everything. This is how a block ends — there is no }, just a line that starts further left. nesting depthTwo levels is fine. Three is a smell. Four means the logic wants restructuring — see the exercises.

Note the chained comparison from 1.7 would be tidier here: if 0 <= score <= 100:.

5

Predict the output

Score is 95. What does this print?

order.py
score = 95
if score >= 50:
    print("pass")
elif score >= 90:
    print("distinction")
pass. Both conditions are true, but an if/elif chain stops at the first one that holds. score >= 90 is never even evaluated.

This is not a Python quirk — C's else if does the same. What makes it worth a whole section is that it is a silent logic bug: the code runs, prints something sensible, and the distinction branch is simply unreachable forever.

The rule: in an elif chain, order from most specific to least. Put >= 90 first. If you ever write a branch that can never be reached, no error will tell you.

6

What trips people here

␣
Mixing tabs and spaces

Looks identical on screen, and Python raises TabError: inconsistent use of tabs and spaces. Set your editor to insert four spaces for Tab. In VS Code the indicator is in the status bar, bottom right — it should say Spaces: 4.

🔤
Using = instead of ==

if x = 5: is a SyntaxError in Python. In C it compiles, assigns, and tests the result — one of the classic C bugs. Python simply forbids it. A small thing you get for free here.

🪜
Nesting three or four deep

Each level is another thing the reader has to hold. Usually the fix is an early exit — check the invalid case first and return or continue, leaving the main path unindented. The exercises have you do exactly that.

8

Quick recap

What to carry forward

  • Indentation is the block. No braces; four spaces by convention; consistency is enforced by the interpreter.
  • Every block-opening line ends with a colon.
  • elif is one word, and exists so long chains don't march right.
  • The first true branch wins — order from most specific to least, or you'll hide a branch silently.
  • if x = 5: is a SyntaxError here. The C assignment-in-condition bug cannot happen.
  • Three levels of nesting means it's time for an early exit.
