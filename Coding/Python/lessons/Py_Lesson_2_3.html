for loops and range

Python's for loop does not count. It walks. Once that lands, the index variable you have carried since C mostly disappears — and with it a whole family of off-by-one bugs.

8 sections~12 minLinks to a live notebook
1

Why this matters

C's for is three expressions bolted together: set up a counter, test it, change it. The counter is the point, and the data is reached through it.

Python's for is a different construct with the same name. It takes a collection and hands you its items, one at a time. There is no counter unless you ask for one.

// C
for (i = 0; i < n; i++) printf("%s", names[i]);

# Python
for name in names:
    print(name)

The Python version cannot run off the end, cannot start at the wrong index, and does not need to know how long names is. Those three bugs are simply gone.

2

The mental model

The loop asks the collection for its items. Anything that can produce items in sequence — an iterable — works: strings, lists, tuples, dicts, sets, files, ranges.

When you genuinely need numbers, range() produces them:

range(5) → 0 1 2 3 4  ·  range(2, 6) → 2 3 4 5  ·  range(0, 10, 2) → 0 2 4 6 8

The stop value is excluded — the same rule as slicing in 1.3, for the same reason: range(n) gives exactly n numbers, and range(a, b) gives b - a of them.

3

Walk-through

The four shapes you will actually write.

loops.py
names = ["bolt", "washer", "nut"]

# 1 — walk the items. The default.
for n in names:
    print(n)

# 2 — need the position too? enumerate.
for i, n in enumerate(names):
    print(i, n)            # 0 bolt / 1 washer / 2 nut

# 3 — two lists in step? zip.
qty = [10, 50, 25]
for n, q in zip(names, qty):
    print(f"{n}: {q}")

# 4 — a fixed number of repeats, item unused
for _ in range(3):
    print("tick")
shape 1Reach for this first. If you are not using an index for anything, do not create one. enumerateGives (index, item) pairs. Add start=1 for human numbering: enumerate(names, start=1). This is the honest replacement for a C index loop. zipWalks several sequences together, stopping at the shortest. Much clearer than indexing both with the same i. _A conventional name meaning “I don't use this”. Ordinary variable, but readers take the hint.

Predict the output

Removing items while looping over the same list. What is left in nums?

mutate.py
nums = [1, 2, 3, 4]
for n in nums:
    if n % 2 == 0:
        nums.remove(n)
print(nums)
[1, 3, 4]. The loop tracks a position. It hands you index 1 (2), you remove it, and everything shifts left — 3 is now at index 1. The loop moves to index 2, which is now 4. 3 was never visited.

No error, no warning. Just a quietly wrong answer, and one that gets more confusing the longer the list.

Never add to or remove from a collection you are looping over. Build a new one instead:

nums = [n for n in nums if n % 2 != 0]

That is a comprehension — Part III.6 — and it is the standard answer to this whole class of problem.

6

What trips people here

🔢
range(1, n) when you meant range(n)

range(5) gives five numbers starting at 0. range(1, 5) gives four starting at 1. If a loop runs one time too few, this is usually why — and if you want 1 to 5 inclusive, it is range(1, 6).

🔁
Keeping the C index habit

for i in range(len(names)): print(names[i]) works and marks the code as translated rather than written. It also reintroduces the off-by-one you just escaped. Use enumerate if you need i, and nothing if you don't.

👻
Using the loop variable after the loop

It survives, holding the last item — which is legal and occasionally useful, but usually a bug. If the loop body never ran, the name may not exist at all, and you get NameError.

8

Quick recap

What to carry forward

  • Python's for walks a collection; it does not count. No index unless you ask.
  • range(n) gives n numbers starting at 0 — stop is excluded, same as slicing.
  • enumerate(x) when you need the position; enumerate(x, start=1) for human numbering.
  • zip(a, b) walks two sequences together and stops at the shorter.
  • for _ in range(n) for plain repetition.
  • Never add to or remove from the collection you are looping over — build a new one.
