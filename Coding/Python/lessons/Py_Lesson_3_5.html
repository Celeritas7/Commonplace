Sets — membership and deduplication

No duplicates, no order, and membership tests that stay fast however big it gets. A set is the right answer to two questions you will otherwise solve slowly with a list.

8 sections~10 minLinks to a live notebook
1

Why this matters

Two problems, both of which you have probably solved with a list and a loop:

“Is this value in there?” On a list, Python scans from the front. On ten items that is nothing; on a hundred thousand, inside another loop, it is the reason your script takes minutes.

“Remove the duplicates.” With a list that is a nested loop, or a growing seen list you check against each time.

A set does both natively. It stores unique items only, and it finds them by hashing — same trick as a dictionary, which is why a set is essentially a dict with only the keys.

2

The mental model

Braces, or the set() function.

sets.py
tools = {"drill", "saw", "drill"}
print(tools)             # {'saw', 'drill'} — duplicate gone
print(len(tools))        # 2

empty = set()            # NOT {} — that is an empty dict

tools.add("file")
tools.discard("saw")     # no error if absent
tools.remove("saw")      # KeyError if absent

print("drill" in tools)  # fast, whatever the size

Three properties, and each has a consequence:

Unique. Adding something already there does nothing — no error, no duplicate.

Unordered. There is no “first” item, no indexing, no slicing. tools[0] is a TypeError. Printing may show any order, and it can differ between runs.

Items must be hashable — the same rule as dict keys, so strings, numbers and tuples but not lists.

3

Walk-through

The set operators are the ones from school mathematics, and they read that way.

ops.py
have   = {"bolt", "nut", "washer"}
needed = {"nut", "washer", "pin"}

print(have & needed)    # {'nut','washer'}   in BOTH  — intersection
print(have | needed)    # all four            in EITHER — union
print(needed - have)    # {'pin'}             MISSING — difference
print(have ^ needed)    # {'bolt','pin'}      in one but not both

# the dedup one-liner
nums   = [3, 1, 3, 2, 1]
unique = list(set(nums))       # [1, 2, 3] — order NOT guaranteed
ordered = sorted(set(nums))    # [1, 2, 3] — order guaranteed
needed - have“What do I still need to order?” — one line, and it reads as the question. dict, then set. Empty braces make a dictionary. Dicts got the braces first, historically, and sets were added later — so {} was already taken.

To make an empty set you must write set(). This trips people because the code looks symmetrical and is not: {"x"} is a set, {"x": 1} is a dict, and {} is a dict.

The symptom is usually an AttributeError: 'dict' object has no attribute 'add' a few lines later, when you try to add to what you thought was a set.

6

What trips people here

🔀
Expecting list(set(x)) to keep the order

Sets are unordered, so the result can come back in any order — and it may differ between runs. When order matters, use sorted(set(x)), or list(dict.fromkeys(x)) which deduplicates while preserving first-seen order.

#️⃣
Indexing a set

tools[0] raises TypeError: 'set' object is not subscriptable. There is no first item. If you need positions, you wanted a list.

🧊
Putting lists in a set

Same unhashable rule as dict keys. {[1,2]} fails. Convert to tuples first — {(1,2)} is fine, and a set of tuples is a genuinely useful thing.

8

Quick recap

What to carry forward

  • A set holds unique, unordered, hashable items — think dict keys with no values.
  • Fast membership: x in s does not slow down as the set grows.
  • & intersection · | union · - difference · ^ symmetric difference.
  • needed - have answers “what's missing?” in one line.
  • {} is an empty dict. An empty set is set().
  • list(set(x)) deduplicates but loses order. Use sorted(set(x)) or dict.fromkeys(x).
