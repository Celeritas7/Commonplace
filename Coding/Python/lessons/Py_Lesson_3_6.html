Comprehensions — list, dict, set

Build a collection by describing it rather than by looping and appending. This is the single most Python-looking construct in the language, and it is the answer to the loop-mutation trap from 2.3.

8 sections~12 minNo setup needed
1

Why this matters

This pattern appears everywhere: make an empty list, loop over something, transform each item, append it.

squares = []
for n in range(10):
    squares.append(n ** 2)

Three lines, two of which are bookkeeping. A comprehension says the same thing once:

squares = [n ** 2 for n in range(10)]

It is not merely shorter. It states an intent — this list is the squares of those numbers — rather than a procedure. And because it builds a new list, it is the clean answer to the “never modify what you are looping over” rule from 2.3.

2

The mental model

The shape, and how to read it.

Reading order is the trick. The for clause in the middle is what happens first; the expression on the left is what gets collected; the if on the right filters. Say it as: “for each n in range 10, if n is even, keep n squared.”

The same shape builds dicts and sets by changing the brackets:

three.py
nums = [1, 2, 3, 4]

[n * 2 for n in nums]              # list  [2, 4, 6, 8]
{n: n ** 2 for n in nums}        # dict  {1:1, 2:4, 3:9, 4:16}
{n % 3 for n in nums}            # set   {1, 2, 0}
3

Walk-through

Filtering, transforming, and both together.

comps.py
readings = [12, -3, 45, 0, -8, 22]

# filter only
valid = [r for r in readings if r > 0]
# [12, 45, 22]

# transform only
doubled = [r * 2 for r in readings]

# both
scaled = [r * 1.8 for r in readings if r > 0]

# the 2.3 fix — build new instead of removing while looping
odds = [n for n in nums if n % 2]

# over a dict, using .items()
stock = {"bolt": 40, "nut": 0, "pin": 7}
in_stock = {k: v for k, v in stock.items() if v > 0}

# cleaning text — a real one
lines = ["  a ", "", " b", "   "]
clean = [l.strip() for l in lines if l.strip()]
# ['a', 'b']

5

Predict the output

Two comprehensions with an if in different places. What does each produce?

twoifs.py
nums = [1, 2, 3, 4]

a = [n for n in nums if n % 2 == 0]
b = [n if n % 2 == 0 else 0 for n in nums]
a is [2, 4]; b is [0, 2, 0, 4]. Two different constructs that look similar.

At the end, if is a filter — it decides whether an item is included at all, and the result is shorter than the input. No else is allowed.

Before the for, it is the ternary from 2.2 — part of the expression, choosing what value to produce. Every item is included, so the result is the same length, and the else is mandatory.

Position tells you which you are reading: filter at the end, ternary at the front. Getting a result of the wrong length is the symptom of confusing them.

6

What trips people here

🌀
Nesting until it is unreadable

[[y for y in row if y] for row in grid if row] is at the limit. Three levels, or a comprehension spanning more than about eighty characters, should be a plain loop. Shorter is not the goal; clearer is.

🧠
Using one for its side effects

[print(x) for x in items] works and builds a list of Nones that you throw away. If you are not collecting a result, write a for loop — that is what it is for.

💧
Building a huge list you only iterate once

sum([n ** 2 for n in range(10_000_000)]) builds ten million items in memory first. Drop the brackets — sum(n ** 2 for n in range(10_000_000)) — and it becomes a generator that produces them one at a time. Same answer, almost no memory.

8

Quick recap

What to carry forward

  • [expr for x in iterable if cond] — read the for clause first, then the expression, then the filter.
  • Same shape builds dicts {k: v for ...} and sets {x for ...}.
  • if at the end filters (result is shorter, no else). if before the for is a ternary (same length, else required).
  • This is the clean answer to never modify what you're looping over.
  • Don't use one for side effects, and don't nest three deep — write the loop.
  • Drop the brackets inside sum() or any() to get a generator and skip the memory.
