Booleans, comparison and logical operators

Python's and/or don't return True and False — they return one of the operands. That sounds like trivia until it explains three idioms you will read constantly.

8 sections~12 minLinks to a live notebook
1

Why this matters

C got booleans late and grudgingly — zero is false, everything else is true, and && yields 1 or 0.

Python has real True and False objects, comparison operators that can be chained the way mathematics writes them, and — the interesting part — and/or that return one of the values you gave them rather than a boolean.

That last behaviour is not a curiosity. It is the basis of several idioms you will meet in real code within a week, and it is why x = name or "anonymous" works.

2

The mental model

Six comparisons, three logical operators.

OperatorMeansNote
== !=equal / not equalCompares values. Works on strings, lists, anything.
< <= > >=orderingOn strings this is dictionary order, capitals first.
and or notlogicWords, not && || !. Those exist but mean bitwise.
is / is notsame object?Not the same as ==. See the mistakes.
in / not inmembershipWorks on strings, lists, dicts, sets.

Two properties do the real work.

Short-circuit. a and b does not evaluate b if a is falsy — the answer is already settled. Likewise a or b skips b when a is truthy. Same as C, but it matters more here because you will lean on it deliberately as a guard.

They return an operand. and returns the first falsy value, or the last value if none are falsy. or returns the first truthy value, or the last. Neither converts to a boolean.

returns.py
print(3 and 5)          # 5    — both truthy, so the last
print(0 and 5)          # 0    — first falsy, stops there
print("" or "anonymous")  # anonymous — first truthy
print(not 3)            # False — not ALWAYS gives a boolean
3

Walk-through

Two things Python does that C cannot.

compare.py
age = 25

# 1 — chained comparison, written like mathematics
if 18 <= age < 65:
    print("working age")

# in C you would need:  age >= 18 && age < 65
# and in C, 18 <= age < 65 compiles and is ALWAYS true.

# 2 — comparisons work on more than numbers
print("apple" < "banana")      # True  — dictionary order
print([1, 2] == [1, 2])       # True  — element by element
print("Zebra" < "apple")       # True  — capitals sort first!

# the guard idiom — short-circuit doing real work
if items and items[0] == "x":
    print("starts with x")
chaining18 <= age < 65 means what it looks like. In C the same text parses as (18 <= age) < 65 — a 0 or 1 compared against 65, always true. A real class of C bug that simply cannot happen here. "Zebra" < "apple"True, because comparison is by character code and uppercase letters come before lowercase. For human-order sorting, compare .lower() versions. the guardIf items is empty, and stops and items[0] never runs — so no IndexError. Reverse the order and it crashes. This ordering is the point of short-circuit.

Predict the output

What does this print — and what type is it?

shortcircuit.py
name = ""
display = name or "anonymous"
print(display, type(display).__name__)
anonymous, and it is a str. or evaluates name, finds "" is falsy, moves on, finds "anonymous" is truthy, and returns that object — not True.

This is the idiom value = something or fallback, and it is everywhere in Python. It works for 0, "", [], None — every falsy value — which is usually what you want and occasionally exactly what you don't. If 0 is a legitimate value, count or 10 will wrongly replace it. Then you want count if count is not None else 10.

6

What trips people here

🟰
Using is when you mean ==

is asks “the same object?”; == asks “the same value?”. a = [1,2]; b = [1,2] — then a == b is True but a is b is False. Small integers and short strings are cached, so x is 5 sometimes appears to work, which makes it worse. Use is only with None, True, False.

🧩
Writing && and ||

& and | exist in Python but are bitwise. 3 & 5 is 1, not True. && is a plain SyntaxError. The words are and, or, not.

🕳️
Ordering a guard wrongly

if items[0] == "x" and items: crashes on an empty list — the index runs before the check. The test that protects must come first. Short-circuit only helps if you order it correctly.

8

Quick recap

What to carry forward

  • and / or return an operand, not a boolean. Only not always gives True/False.
  • Short-circuit lets you guard: if items and items[0] == 'x'. Order matters.
  • value = something or fallback is the default-value idiom — but it also replaces 0 and "".
  • Comparisons chain: 18 <= age < 65 means what it reads. In C the same text is a bug.
  • == compares values; is compares identity. Use is only with None/True/False.
  • The operators are the words and or not. & and | are bitwise.
