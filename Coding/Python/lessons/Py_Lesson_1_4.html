String methods, split, join, find, replace

Almost every text job you will ever do is four methods deep. This is the lesson that replaces about two hundred lines of C string handling with about six.

8 sections~12 minLinks to a live notebook
1

Why this matters

Splitting a line of CSV in C means strtok, a mutable buffer, and remembering that it destroys the input.

In Python it is line.split(","), which returns a list and leaves the original untouched. That is the shape of this whole lesson: a small set of methods that read like verbs, none of which modify anything.

You have already used most of these in the beginner practice notebooks — the word-count exercise, the Caesar cipher, the Hangman word handling. This lesson names them properly and points at the two that behave differently from how they read.

2

The mental model

A method is a function that belongs to an object. You call it with a dot: s.upper() rather than upper(s). Discovering them is easy — in a notebook or REPL, type s. and press Tab.

The rule that governs all of them: a string method never changes the string. It returns a new one. Which means this line does nothing at all:

nothing.py
name = "  aniket  "
name.strip()          # computes "aniket" and throws it away
print(name)             # "  aniket  " — unchanged

name = name.strip()   # this is what you meant
✨ Newly written

This catches everybody at least once, because in C most string functions do modify in place. In Python, if a string method's result is not assigned to something, the work is discarded. When a text transformation “does nothing”, this is nearly always why.

3

Walk-through

The six that matter, and one pairing worth memorising.

methods.py
line = "  Aniket,Tokyo,Engineer  "

# 1 — clean the edges
line = line.strip()              # "Aniket,Tokyo,Engineer"

# 2 — split on a separator → a LIST
parts = line.split(",")         # ['Aniket', 'Tokyo', 'Engineer']

# 3 — join a list back into a string
out = " | ".join(parts)         # "Aniket | Tokyo | Engineer"

# 4 — case
print(line.upper(), line.lower())

# 5 — replace every occurrence
print(line.replace(",", "; "))

# 6 — where is it? -1 means "not there"
print(line.find("Tokyo"))       # 7
print(line.find("Osaka"))       # -1
.strip()Removes whitespace from both ends only — never the middle. .lstrip() and .rstrip() do one side. Essential on anything read from a file, because of trailing newlines. .split()With no argument it splits on any run of whitespace and drops empties — which is what you want for prose. With an argument it splits on exactly that separator, and keeps empties. .join()Reads backwards at first: the separator owns the method. ", ".join(items). Say it as “join these with this”. This is also the fast way to build a long string. .find()Returns the index, or -1 if absent. Its sibling .index() raises ValueError instead. Use in when you only want a yes/no.

Three more that pay for themselves: .startswith() and .endswith() for prefix and suffix tests, and .count(sub) for how many times something appears.

5

Predict the output

.strip() takes an optional argument. What does this print?

strip.py
print("xxhelloxx".strip("x"))
print("mississippi".strip("mip"))
hello, then ssiss. The argument is not a prefix to remove — it is a set of characters. .strip("mip") chews inward from both ends removing any of m, i or p, and stops at the first character not in that set. From the left it eats m, i; from the right i, p, p, i. What survives is ssiss.

The trap is code like filename.strip(".txt"), meant to remove an extension. On "report.txt" it happens to work. On "test.txt" it returns "es" — it ate the leading t too. Use .removesuffix(".txt") (3.9+) or pathlib, covered in 6.2.

6

What trips people here

🪞
Forgetting to assign the result

s.upper() on its own line does nothing. Every string method returns; none mutate. If a transformation appears to have no effect, look for a missing s = .

🔍
Using .index() when you meant .find()

.find() returns -1 for absent; .index() raises ValueError. Neither is wrong — but if s.find(x) is a bug, because -1 is truthy and index 0 is falsy. Write if s.find(x) != -1, or better, if x in s.

🧵
Splitting on "," to parse real CSV

Fine for clean data. It breaks the moment a field contains a quoted comma — "Tokyo, Japan" becomes two fields. For real files use the csv module (Part VI.3). Your .split() is for simple, known-shape text.

8

Quick recap

What to carry forward

  • String methods return a new string and never modify. Assign the result or lose it.
  • .strip() cleans both ends only — and its argument is a set of characters, not a suffix.
  • .split(sep) → list. sep.join(list) → string. The separator owns join.
  • .find() returns -1 when absent; .index() raises. For yes/no, use in.
  • .replace() changes every occurrence unless you pass a count.
  • Build long strings with "".join(parts), not repeated +=.
