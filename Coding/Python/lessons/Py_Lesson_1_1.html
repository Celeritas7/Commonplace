Variables, names, and dynamic typing

In C a variable is a labelled box of a fixed size. In Python it is a luggage tag you tie onto a value. Almost every surprise in this Part comes from that one difference.

8 sections~13 minNo setup needed
1

Why this matters

You already know what int x = 5; does in C. Python's x = 5 is not the same thing, and the difference is not cosmetic.

In C, declaring x reserves four bytes somewhere and calls that place x. Assigning writes into that place. The box exists first; values pass through it.

In Python, 5 is an object that exists on its own, and x is a name tied to it. There is no box. Assigning again does not overwrite anything — it unties the name and ties it somewhere else. Once you see it that way, a whole family of otherwise baffling behaviours becomes obvious.

2

The mental model

Think of a luggage tag, not a box.

Three consequences, and they explain most of what follows:

A name has no type; the object does. x = 5 then x = "hello" is perfectly legal. Nothing was redeclared — the tag simply moved to a string. This is what dynamic typing means. Not “no types” — Python is strict about types — but that types live on values, not on names.

Two names can tag the same object. b = a does not copy. It ties a second tag to the same thing.

Some objects can be changed in place; some cannot. A list can. A number or string cannot. That distinction is the subject of section 5, and it is the single most useful thing in this lesson.

3

Walk-through

Read = as “tie this name to that object”, never as “store into”.

names.py
x = 5              # tie x to the integer 5
y = x              # tie y to the SAME object
x = 7              # re-tie x to 7. y is untouched.
print(x, y)        # 7 5

name = "Aniket"    # names have no declared type...
name = 42           # ...so this is legal

print(type(name))    # <class 'int'> — the OBJECT has the type
line 2y = x copies the tag, not the value. Both names now point at the same 5. For numbers this never matters, because you cannot change a 5. For lists it matters enormously. line 3x is re-tied. Nothing was written into y, so y still shows the old object. type()Asks an object what it is. Useful when a value is not behaving — it is the first thing to reach for, before guessing.

Names follow three rules: letters, digits and underscores only; not starting with a digit; and not one of Python's ~35 keywords. Convention is lower_snake_case for variables and UPPER_SNAKE for values you intend never to change — Python will not stop you changing them, the capitals are a message to the next reader.

✨ Newly written

One name is worth learning to avoid: do not call a variable list, str, sum, type or id. Those are built-in functions, and re-tying the name hides the function for the rest of the program. TypeError: 'list' object is not callable almost always means someone did exactly this.

5

Predict the output

Two names, one list. What does this print?

shared.py
a = [1, 2, 3]
b = a
b.append(4)
print(a)
[1, 2, 3, 4]. b = a tied a second tag to the same list. append changes that list in place — so both names see the change, because there is only one list.

Compare with the earlier example, where x = 7 left y alone. The difference is not the assignment; it is that append mutates while = re-ties. Lists, dicts and sets can be mutated. Numbers, strings and tuples cannot — which is exactly why the number example felt safe.

When you want a real copy: b = a.copy() or b = a[:].

6

What trips people here

🔗
Expecting b = a to copy a list

It never copies. For anything mutable — list, dict, set — you have handed out a second key to the same room. Use .copy() when you mean a copy, and copy.deepcopy() when the thing contains other mutable things.

🕳️
Shadowing a built-in

list = [1,2,3] works, and then list(range(5)) fails with 'list' object is not callable. The fix is to rename your variable — items, rows, values. Coming from C, where there is no such global namespace to trample, this one is easy to walk into.

🧨
Assuming a name exists because you wrote it in an if

if flag: msg = "hi" then print(msg) raises NameError whenever flag is false. No compiler warned you, because the binding only happens when the branch runs. Give the name a value before the branch.

8

Quick recap

What to carry forward

  • A Python name is a tag tied to an object, not a box holding bytes.
  • Types live on values, not names. x can hold an int then a string; type(x) asks the object.
  • b = a never copies — it ties a second name to the same object.
  • = re-ties a name; mutating methods like .append() change the object everyone can see.
  • Lists, dicts, sets are mutable. Numbers, strings, tuples are immutable — which is why they feel safe.
  • Never name a variable list, str, sum or type.
