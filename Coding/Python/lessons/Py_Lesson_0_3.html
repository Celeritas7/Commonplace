Three ways to run code: script, REPL, notebook

The same five lines of Python behave differently depending on where you type them. Knowing which of the three you want — and why — saves more time than any other habit in this Part.

8 sections~11 minLinks to a live notebook
1

Why this matters

In C there is one way to run code: compile it, then run the executable.

Python has three, and they are genuinely different tools rather than three doors to the same room. Choose wrong and you will fight the environment instead of the problem — trying to explore data in a script that forgets everything each run, or trying to ship a scheduled job as a notebook nobody can execute unattended.

You already use all three without necessarily having named them. This lesson names them.

2

The mental model

The difference is what survives between lines.

WayWhat it isWhat survives
scriptA .py file you run start-to-finishNothing. Every run starts empty and ends empty.
REPLAn interactive prompt — type a line, see the answerEverything, until you close the window.
notebookCells you run individually, in any orderEverything, plus the outputs are saved into the file.

REPL stands for read, evaluate, print, loop — it reads what you type, works it out, prints the answer, and waits for more. That printing is the part people miss: in a REPL, typing 2 + 2 shows 4. In a script, 2 + 2 computes four and throws it away. You need print(2 + 2).

✨ Newly written

A notebook is a REPL whose history is a document you can edit and re-run. That single sentence explains both why notebooks are wonderful for exploring and why they are dangerous for anything that must be reproducible.

3

Walk-through

The same job, in all three, so the difference is concrete.

script — count.py
total = 0
for n in range(1, 11):
    total += n
print(total)

# run it:  python count.py     →  55
# run it again: it recomputes from scratch. total is gone.
REPL — Anaconda Prompt, type: python
>>> total = 0
>>> for n in range(1, 11):
...     total += n
...
>>> total
55
>>> total * 2       # total is still here
110
scriptOne shot. Good for anything you will run more than once the same way, hand to someone else, or schedule. REPL>>> is the prompt; ... means it is waiting for the rest of an indented block — press Enter on an empty line to finish it. Note total printed 55 without print(). That is the P in REPL. exitexit() or Ctrl-Z then Enter on Windows. Everything you defined vanishes.

The notebook version is the same code in a cell, with one difference that matters enormously: you can run the loop cell twice. Do that and total becomes 110, because the second run adds to the value the first run left behind. The code did not change. The state did.

5

Predict the output

In a notebook you run three cells top to bottom. Then you go back, edit cell 1, and re-run only cell 3. What does cell 3 see?

notebook
[1]  price = 100          # edited to 250, not re-run
[2]  tax = price * 0.1
[3]  print(price + tax)    # re-run now
110. Editing a cell changes the text. It changes nothing in memory until you run it. price is still 100 and tax is still 10.

This is the notebook's defining hazard. The document you are reading and the state you are computing with can silently disagree. Anyone reading the saved notebook later sees price = 250 and an output of 110, and cannot explain it.

The cure is a reflex: before you trust a notebook's result, Kernel → Restart & Run All. If it does not survive that, it was never really working.

6

What trips people here

🔢
Trusting execution numbers to be in order

The [1] [2] [3] counters show the order cells were run, not the order they appear. A notebook showing [7] [3] [12] down the page has been run all over the place. Read those numbers — they are the truth about what happened.

🖨️
Forgetting print() when you move code from a notebook into a script

A notebook shows the value of the last expression in a cell automatically. A script shows nothing unless you ask. Code that printed beautifully in a cell goes silent as a .py file, and it looks like the code broke.

📦
Shipping a notebook as if it were a program

Notebooks are for exploring and explaining. When something needs to run unattended, on a schedule, or on someone else's machine, move it into a .py file. Part XII.5 covers scheduling; notebooks do not schedule well.

8

Quick recap

What to carry forward

  • Script — runs start to finish, remembers nothing. For things you run more than once, or hand over.
  • REPL — remembers everything until you close it, and prints values without print(). For quick questions.
  • Notebook — a REPL whose history is an editable document. For exploring and explaining.
  • The notebook hazard is state disagreeing with text. Restart & Run All before you trust a result.
  • Moving notebook code into a script? Add the print() calls you were getting for free.
