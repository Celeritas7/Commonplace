break, continue, and loop else; nested loops and patterns

Two words that change a loop's flow, one clause almost nobody knows exists, and the nested loops behind every pattern program you have written.

8 sections~12 minLinks to a live notebook
1

Why this matters

Sometimes a loop has done its job before the collection runs out — you found what you were searching for. Sometimes one item should be skipped and the rest handled normally.

break and continue handle both, and they work identically in C, so this part is quick. What is genuinely new is for...else — a clause with no C equivalent that solves the “did I find it?” problem cleanly — and the nesting rules behind the pattern programs you have already written by hand.

2

The mental model

Two keywords, and a third thing that surprises people.

KeywordEffectUse for
breakLeave the loop entirely, nowFound it; stop searching
continueSkip the rest of this pass, start the nextNot interested in this item
elseRuns only if the loop was not broken out of“Searched everything, found nothing”

That last one reads wrongly at first. A loop's else has nothing to do with a condition being false. Think of it as “on exhaustion” — it runs when the loop finished naturally, and is skipped when break cut it short. That is exactly the flag variable you would otherwise have to maintain by hand.

And the nesting rule, which is the whole of pattern printing: the inner loop runs to completion for every single pass of the outer loop. Outer moves once, inner runs all the way through.

3

Walk-through

All four ideas, in the smallest useful examples.

flow.py
# break — stop as soon as you find it
for n in [4, 7, 2, 9]:
    if n > 5:
        print(f"found {n}")
        break

# continue — skip this one, keep going
for n in range(10):
    if n % 2:
        continue          # odd → skip
    print(n)              # 0 2 4 6 8

# for-else — ran to the end without breaking
for n in [4, 2, 1]:
    if n > 5:
        print("found one")
        break
else:
    print("nothing above 5")   # this runs

# nested — inner completes for EVERY outer pass
for row in range(1, 5):
    for col in range(row):
        print("*", end="")
    print()                   # newline after each row
if n % 2:Truthiness from 2.2 — a remainder of 1 is truthy, so this reads as “if odd”. Idiomatic once you see it. for...elseThe else lines up with for, not with if. It runs on natural exhaustion, and is skipped by break. Replaces a found = False flag entirely. end=""print normally adds a newline; end="" suppresses it so the row builds across. The bare print() afterwards ends the line. the triangleOuter picks the row; inner prints that many stars. This is exactly the structure of your Pattern_programs scripts.

5

Predict the output

A search for a part number. What does this print?

search.py
parts = ["A-10", "B-22", "C-31"]

for p in parts:
    if p.startswith("Z"):
        print("found it")
        break
else:
    print("not in stock")
not in stock, once. The else belongs to the for, not to the if. It runs exactly once, after the loop finishes — and only because break never fired.

Add "Z-99" to the list and the output becomes found it with no not in stock: the break skips the else entirely.

The alternative, without for...else, is a flag:

found = False … found = True; break … if not found:

Three extra lines and a variable to keep in sync. The else clause is worth knowing precisely because it deletes all of that.

6

What trips people here

🚪
Expecting break to leave both loops

It leaves one — the innermost it sits in. To escape a nested pair, either put the loops in a function and return, or set a flag the outer loop checks. There is no break 2 in Python.

🤔
Reading else as attached to the if

Indentation settles it: an else lined up with for or while belongs to the loop. This is genuinely confusing naming — many people read it as “no-break” in their head, which is what it means.

🔄
continue in a while loop, before the update

continue jumps straight back to the test. If the update line sits below it, the update is skipped and the loop hangs. This is why continue is safe in for loops and needs care in while loops.

8

Quick recap

What to carry forward

  • break leaves the loop; continue skips to the next pass.
  • for...else runs the else only if no break happened — read it as “on exhaustion”. It replaces a flag variable.
  • break escapes one loop only. For nested loops, use a function and return.
  • Nested loops: the inner runs completely for every outer pass. That's all pattern printing is.
  • print(x, end="") suppresses the newline; a bare print() ends the row.
  • In a while, continue before the update line will hang the loop.
