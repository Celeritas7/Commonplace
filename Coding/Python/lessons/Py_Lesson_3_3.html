Tuples and unpacking

A tuple is a list that cannot change. That sounds like a limitation until you see what it buys: dict keys, multiple return values, and the swap that needs no temporary.

8 sections~11 minLinks to a live notebook
1

Why this matters

A tuple looks like a list with round brackets and behaves like one you cannot modify.

The obvious question is why you would want that. Three answers, and each is a thing you will do constantly:

It can be a dict key. Only immutable things can — a list cannot. {(52.5, 13.4): "Berlin"} works.

It signals shape, not sequence. A list is “several of the same kind of thing”. A tuple is usually “one thing with several parts” — a coordinate, a row, a name-and-score.

It is how Python returns more than one value — and how you take them apart on the receiving end.

2

The mental model

The syntax has one surprise: the comma makes a tuple, not the brackets.

tuples.py
point  = (3, 4)
also   = 3, 4            # same thing — brackets optional
single = (3,)             # ONE-element tuple. The comma is required.
nope   = (3)              # just the number 3 in brackets
empty  = ()

print(point[0])          # 3 — indexing works
print(len(point))         # 2
# point[0] = 9              → TypeError. Immutable.

Everything read-only works — indexing, slicing, len, in, looping. Everything that changes is absent: no append, no sort, no item assignment.

Walk-through

Unpacking is the real payoff. It takes a tuple apart into named pieces in one line.

unpacking.py
point = (3, 4)
x, y = point              # x is 3, y is 4

# the swap — no temporary variable
a, b = b, a

# a function returning two things returns a tuple
def min_max(values):
    return min(values), max(values)

lo, hi = min_max([4, 9, 2])   # unpack straight into two names

# star collects the rest
first, *rest = [1, 2, 3, 4]     # first=1, rest=[2,3,4]

# unpacking in a for loop — you have used this already
for i, name in enumerate(parts):
    print(i, name)
the swapa, b = b, a builds the tuple (b, a) first, then unpacks it — which is why no temporary is needed. In C this is three lines and a spare variable. two return valuesThere is no special syntax. The function returns one tuple; you unpack it. Every “returns multiple values” in Python is this. *restCollects whatever is left into a list. Works anywhere in the pattern: first, *middle, last = items. enumerateIt yields tuples, and for i, name in ... unpacks each one. You have been using tuple unpacking since 2.3 without naming it.

Predict the output

One of these is not a tuple. Which, and what is it?

comma.py
a = (1, 2)
b = (1,)
c = (1)
print(type(a).__name__, type(b).__name__, type(c).__name__)
tuple tuple int. (1) is the number one wrapped in ordinary grouping brackets — the same brackets as in (a + b) * c. Nothing makes it a tuple, because there is no comma.

This matters in practice more than it looks. return (value) returns a bare value, not a one-tuple. And parts = ("bolt") makes a string, so len(parts) is 4 and looping over it gives you letters.

The rule: the comma builds the tuple. Brackets only group. (1,) and even 1, are one-element tuples.

6

What trips people here

🔒
Thinking immutable means “contents are frozen”

A tuple's slots cannot be re-pointed, but a mutable object inside one can still change. t = ([1,2], 3) — then t[0].append(9) works fine. The tuple still holds the same list; the list is different. This also means such a tuple cannot be a dict key.

⚖️
Unpacking the wrong number of items

x, y = (1, 2, 3) raises ValueError: too many values to unpack. Clear message, but it appears at runtime — there is no compiler checking the shapes match. *rest is the fix when the count varies.

🤷
Using a tuple where a list belongs

If you will add, remove or sort, use a list. Tuples are for fixed-shape records. Choosing a tuple and then needing to change it means rebuilding the whole thing.

8

Quick recap

What to carry forward

  • A tuple is an immutable sequence — indexing, slicing, len, in all work; nothing that changes it does.
  • The comma makes the tuple. (1) is an int; (1,) is a tuple.
  • Unpacking: x, y = point. The swap a, b = b, a needs no temporary.
  • Returning several values is returning a tuple — there's no special syntax.
  • first, *rest = items collects the remainder into a list.
  • Immutable means the slots are fixed — a list inside a tuple can still be changed.
