f-strings and formatting output

Putting a value into a sentence is the most common thing you will do in Python. There are four ways to do it, three of them are legacy, and the modern one is genuinely delightful.

8 sections~11 minLinks to a live notebook
1

Why this matters

In C, printing a name and a number means printf("%s scored %d\n", name, score) — and getting the specifier wrong is undefined behaviour.

Python's modern answer puts the expression where it appears in the sentence:

print(f"{name} scored {score}")

No positional matching, no type specifiers, nothing to keep in sync. These are f-strings, and since Python 3.6 they are the right default. You will still meet the older forms in code you read — this lesson covers the modern one properly and the old ones briefly, so you can recognise them.

2

The mental model

Put f before the opening quote. Then anything inside { } is evaluated as Python and inserted.

fstrings.py
name = "Aniket"
parts = 3
rate  = 0.0825

print(f"{name} checked {parts} parts")

# any expression, not just a name
print(f"next batch: {parts * 2}")
print(f"upper: {name.upper()}")

# = shows the expression AND its value — a debugging gift
print(f"{rate = }")      # rate = 0.0825
the fWithout it you get the literal text {name}. This is the most common typo in Python, and it fails silently — no error, just wrong output. expressionsMethod calls, arithmetic, indexing — all fine inside the braces. Keep them short; a long expression buried in a string is hard to read. {rate = }Python 3.8+. Prints the expression text and its value. Faster than typing print("rate =", rate) and it never goes stale when you rename things.
✨ Newly written

You will also see "%s scored %d" % (name, score) — the oldest form, borrowed straight from C — and "{} scored {}".format(name, score). Both still work. Neither is worth writing new. Recognise them, and reach for f-strings.

3

Walk-through

After a colon inside the braces comes a format spec: how the value should look.

formatting.py
value = 1234.5678

print(f"{value:.2f}")      # 1234.57      2 decimal places
print(f"{value:,.2f}")     # 1,234.57     thousands separator
print(f"{value:10.2f}")    #    1234.57   width 10, right-aligned
print(f"{0.0825:.1%}")     # 8.2%         as a percentage

label = "bolt"
print(f"{label:<10}|")     # bolt      |   left-align in 10
print(f"{label:>10}|")     #       bolt|   right-align
print(f"{label:^10}|")     #    bolt   |   centre
.2fFixed-point, two decimals. Rounds for display only — the underlying value is untouched. ,Thousands separators. f"{1234567:,}" gives 1,234,567. 10.2fTotal width 10, two decimals, padded with spaces. This is what lines up columns. < > ^Left, right, centre. Numbers default to right, text to left — which is usually what you want in a table.

5

Predict the output

One of these prints something other than a formatted value. Which, and what does it print?

oops.py
n = 7
print(f"count: {n}")
print("count: {n}")
It prints count: {n}, literally. Without the f, the braces are just characters. No error, no warning — the string is perfectly valid, it simply is not an f-string.

This is why the missing f is worth calling out on its own. Every other formatting mistake announces itself. This one produces output that looks almost right in a log file and is completely wrong. When you see literal braces in your output, that is the whole diagnosis.

6

What trips people here

🅵
Leaving out the f

Silent, and the only formatting error that produces no error. If your output contains { and }, this is why.

💬
Quote collision inside the braces

f"{d["key"]}" ends the string early. Before Python 3.12 you must use different quotes inside: f"{d['key']}". Easiest habit — double quotes outside, single inside.

🧮
Thinking :.2f rounds the value

It rounds the display only. total is unchanged, and summing displayed values will not match the displayed sum. If you need the value itself rounded, use round(x, 2) — and remember 1.2 on why money should not be a float at all.

8

Quick recap

What to carry forward

  • f"..." — the f is mandatory, and forgetting it fails silently.
  • Anything in { } is evaluated as Python: names, arithmetic, method calls.
  • {x = } prints both the expression and its value — the fastest debug print there is.
  • After a colon comes the format spec: .2f, ,, 10.2f, .1%, < > ^.
  • Formatting changes display only. The value is untouched.
  • % and .format() are legacy — read them, don't write them.
