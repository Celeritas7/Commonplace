Parameters: positional, keyword, default

Python lets the caller name the arguments, and lets the definition supply fallbacks. Together they replace the overloaded-function zoo you would write in C — and hide one genuinely dangerous trap.

8 sections~12 minLinks to a live notebook
1

Why this matters

In C, a function that can be called three different ways means three functions, or a struct of options, or a variadic mess.

Python gives one definition and lets the caller choose how to supply the arguments — by position, by name, or by leaving some out entirely and taking the defaults.

This is why so many Python library functions have long signatures you can ignore. print() takes sep, end, file and flush; you have used it a hundred times without knowing.

2

The mental model

Two ways to pass, one way to default.

params.py
def order(part, qty, priority="normal"):
    print(f"{qty} x {part} ({priority})")

order("bolt", 40)                        # positional; priority defaults
order("bolt", 40, "urgent")              # all positional
order(part="bolt", qty=40)              # all keyword
order("bolt", priority="urgent", qty=40)  # mixed; keywords in any order

# order(qty=40, "bolt")   → SyntaxError: positional after keyword

Positional arguments match by position, left to right. Keyword arguments match by name and may come in any order. The one rule: once you start using keywords in a call, everything after must also be keyword.

Defaults are written in the definition with =. Parameters with defaults must come after those without — otherwise a positional call would be ambiguous, and Python rejects the definition outright.

When to use which, in practice: positional for the one or two obvious arguments, keyword for anything a reader could not guess. order("bolt", 40, True) is a puzzle at the call site; order("bolt", 40, urgent=True) is not.

3

Walk-through

Defaults make a function grow options without breaking old calls.

defaults.py
def report(values, precision=2, label="total", show_count=False):
    total = sum(values)
    line = f"{label}: {total:.{precision}f}"
    if show_count:
        line += f" ({len(values)} items)"
    return line

print(report([1.5, 2.25]))
# total: 3.75

print(report([1.5, 2.25], precision=1, show_count=True))
# total: 3.8 (2 items)
three defaultsEvery one is optional, so the simplest call passes a single argument. Adding a fourth option later breaks nothing that already works. show_count=TrueA boolean passed by keyword. Passing True positionally would be unreadable at the call site — this is the clearest case for insisting on a keyword. nested format spec{total:.{precision}f} — the precision itself comes from a variable. A small f-string trick from 1.5 that is worth knowing.

You can force callers to use keywords by putting a bare * in the signature — everything after it must be named:

def report(values, *, precision=2, label="total"):    # precision and label are keyword-only

Predict the output

A function that collects items into a list. What does the second call print?

mutable.py
def add_part(name, basket=[]):
    basket.append(name)
    return basket

print(add_part("bolt"))
print(add_part("nut"))
['bolt'] then ['bolt', 'nut']. The list is created once, when the def line runs — not on each call. Every call that omits basket gets the same list, and appends accumulate across calls forever.

This is the most notorious trap in Python, and it is a direct consequence of 4.1: def executes once, and the default value is evaluated at that moment.

The fix is a fixed idiom:

def add_part(name, basket=None):
    if basket is None: basket = []

Now a fresh list is made on each call that needs one. Never use a list, dict or set as a default value. Immutable defaults — numbers, strings, None, True — are entirely safe, because there is nothing to accumulate.

What trips people here

📦
Mutable default arguments

Section 5. The rule is absolute: default to None and build inside. This one has shipped bugs in real libraries.

↔️
Putting a defaulted parameter before a plain one

def f(x=1, y): is a SyntaxError at definition time — Python catches it immediately, which is the one mercy here.

⏱️
Expecting a default to re-evaluate

def log(msg, when=datetime.now()): captures the time the module was imported, not the time of the call. Every log line gets the same timestamp. Same cause as the mutable default; same fix.

8

Quick recap

What to carry forward

  • Positional match by order; keyword match by name and can be reordered. Positional cannot follow keyword.
  • Defaults go last in the definition — Python rejects the reverse.
  • Use keywords for anything a reader couldn't guess, especially booleans.
  • A bare * in the signature makes everything after it keyword-only.
  • Never default to a list, dict or set. Default to None and build inside.
  • Defaults are evaluated once, at definition time — that's the whole reason for the trap.
