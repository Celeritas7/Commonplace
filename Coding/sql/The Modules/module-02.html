What this module covers

After Module 1 you can pull columns out of a table. This module gives you three operators that turn a raw column dump into a focused answer — keep the rows you want, sort them, and show only the top few.

  • WHERE — keep only the rows that match a condition. Equality, ranges, set membership, pattern matching: every filter you will ever write lives here.
  • ORDER BY — sort the result by one or more columns, ascending or descending.
  • LIMIT — cap the result at N rows. The natural partner of ORDER BY when you want “the top 5 by anything”.

The SQL funnel — the middle layers

Every query is written in the same fixed order, top to bottom, and each clause narrows the result further than the one above it. This module lives in three layers — WHERE, ORDER BY and LIMIT — but the order never changes.

Order of execution

ORDER BY runs after any grouping but before LIMIT — you sort the final shape, then cut it to size. Swap the two and you change which rows survive.

Lesson 2.1 — WHERE

Why this matters

WHERE keeps only the rows that satisfy a condition and drops the rest before anything else happens. It runs on the raw rows fresh from FROM, so every later clause sees only what survived this filter.

The shape of a filter

SELECT column1, column2
FROM table_name
WHERE condition;

The condition is checked once per row. Rows where it is true are kept; rows where it is false — or unknown, see NULL below — are dropped.

Comparison operators

=, != (or <>), >, <, >=, <=. Text values go in single quotes; numbers do not.

Ranges

Write both ends of the range and join them with AND. BETWEEN a AND b means the same thing and includes both ends.

Patterns with LIKE

% matches any run of characters (including none); _ matches exactly one. 'A%' means “starts with A”, '%son' “ends with son”.

Case sensitivity

In this SQLite playground LIKE ignores case for plain letters. PostgreSQL's LIKE is case-sensitive; use ILIKE there when you want a case-insensitive match.

Combining conditions

AND needs both sides true; OR needs either. AND binds tighter than OR, so use brackets whenever you mix them.

NULL is not a value

NULL means “unknown”. It never equals anything — not even another NULL — so WHERE email = NULL matches no rows. Use IS NULL and IS NOT NULL.

Common mistakes

Comparing with = NULL

Returns nothing, silently. Any comparison with NULL is unknown, and unknown rows are dropped. Write IS NULL.

Mixing AND and OR without brackets

WHERE rating = 'G' OR rating = 'PG' AND length > 100 reads as G, or (PG and long). Bracket the OR to say what you mean.

Double quotes around text

In standard SQL, single quotes are text and double quotes are column names. WHERE rating = "PG" asks for a column called PG.

Aniket, Amara and Anna.

Solution 2.1.5

SELECT first_name, last_name
FROM customer
WHERE email IS NULL;

email = NULL is never true — comparing with NULL is always unknown, so every row is dropped. IS NULL is the test for a missing value.

Solution 2.1.6

SELECT title, rating, length
FROM film
WHERE (rating = 'G' OR rating = 'PG')
  AND length > 100;

Without the brackets, AND binds first and short G films sneak in.

Lesson 2.2 — ORDER BY

Why sort

Without ORDER BY, rows come back in whatever order the database finds convenient. That order is not guaranteed and can change between runs. If the order matters to you, say so.

Ascending and descending

ASC (the default) sorts smallest first — A to Z, low to high, oldest to newest. DESC reverses it.

Sorting by more than one column

The first column decides the order; the second only breaks ties among rows that share the first; and so on. Each column gets its own ASC or DESC.

By rating, then longest first within each rating
SQLite · dvdrental schema

Filter first, then sort

WHERE goes before ORDER BY, always. Sorting fewer rows is also cheaper — on big tables sorting costs roughly N·log N.

Cheap rentals, alphabetical
SQLite · dvdrental schema

Common mistakes

Expecting a default order

Rows that happen to come back in insert order today may not tomorrow. Only ORDER BY guarantees an order.

DESC applies to one column

ORDER BY rating, length DESC sorts rating A–Z and only length descending. Write DESC after every column you want reversed.

Solution 2.2.1

FROM actor

Solution 2.2.2

SELECT title, rating, length
FROM film
ORDER BY rating, length DESC;

rating sorts ascending by default; DESC applies to length only.

Solution 2.2.3

SELECT payment_id, customer_id, amount
FROM payment
WHERE amount > 2
ORDER BY amount DESC;

Solution 2.2.4

SELECT title, length
FROM film
ORDER BY length DESC;

ORDER BY 2 sorts by the second column in the SELECT list. It breaks silently when someone reorders the columns. Name the column, put keywords in capitals, one clause per line, and end with a semicolon.

Lesson 2.3 — LIMIT

Why cap the rows

LIMIT N returns at most N rows. It is the last step of the query: every filter, sort and group runs first, then LIMIT trims the survivors. On a table with millions of rows it is also cheap insurance while you explore.

A quick peek at a table

Top N and bottom N

LIMIT on its own just samples. With ORDER BY it answers real questions: the five longest films, the three most recent payments. ORDER BY decides which rows; LIMIT decides how many.

Pages with OFFSET

OFFSET k skips the first k rows. LIMIT 5 OFFSET 5 is page 2 of a list shown five at a time. Always pair it with ORDER BY, or the pages can overlap.

Page 2, five films per page
SQLite · dvdrental schema

Habit worth forming

Never LIMIT a result you will act on without an explicit ORDER BY. The five rows you see today may not be the five you see tomorrow.

Common mistakes

LIMIT without ORDER BY

Fine for a peek, wrong for “the top 5”: without a sort there is no top.

Ties at the cut-off

If the 5th and 6th rows have the same value, LIMIT 5 keeps one of them arbitrarily. Add a tie-breaker column to ORDER BY so the answer is stable.

Solution 2.3.1

FROM customer

Which three you get is up to the database — that is fine for a peek.

Solution 2.3.2

SELECT title, length
FROM film
ORDER BY length DESC
LIMIT 3;

Agent Truman (169), Ali Forever (150), Alaska Phantom (136).

Solution 2.3.3

SELECT payment_id, amount
FROM payment
ORDER BY amount, payment_id
LIMIT 4;

Four payments tie at 0.99; payment_id makes the order stable.

Solution 2.3.4

SELECT title
FROM film
ORDER BY title
LIMIT 5 OFFSET 10;

Page n of size s is LIMIT s OFFSET (n - 1) * s.

Solution 2.3.5

SELECT title, rating, length
FROM film
WHERE rating IN ('PG', 'PG-13')
ORDER BY length DESC
LIMIT 3;
