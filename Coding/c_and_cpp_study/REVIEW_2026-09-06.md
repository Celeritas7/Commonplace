# Interactive C / C++ Books — Supervision Review (2026-09-06)

**Scope:** all 153 lesson pages in `Coding/c_and_cpp_study/lessons/` (72 C, 81 C++).
**Nature:** read-only review. Nothing was changed. Every finding below is a *report*, not a fix.

**How it was done**
1. Automated structural scan of every file (title/breadcrumb/lesson-number consistency, section & mascot-line counts, quiz `data-correct` sanity, prev/next links, placeholder text, encoding, duplicate ids).
2. Every page rendered in headless Chromium at desktop (1280 px) and phone (390 px): JS errors, failed requests, horizontal overflow, and a functional check — click the correct quiz option (does feedback appear? does XP change?), click every button, scroll to the last section (does the mascot bubble change?).
3. Content read of every lesson by eight parallel reviewers (C/C++ accuracy, beginner-fitness, template compliance, source labelling, in-code UI logic), working from a per-lesson digest of everything the reader sees plus the quiz/feedback/simulation data in the JS.
4. Spot-verification of the highest-severity claims against the raw HTML (all held up).

**Verdict at a glance**

| Grade | Count | Meaning |
|---|---|---|
| A | 35 | ship as is (maybe one nit) |
| B | 96 | minor fixes |
| C | 20 | needs a real content/UI fix |
| D | 2 | broken on load |

Issues logged: 352 (25 High · 107 Med · 220 Low) — 145 accuracy, 88 pedagogy, 61 UI, 35 template, 20 labelling, 3 accessibility.

Overall the books are in good shape: prose is beginner-friendly, the template is followed almost everywhere, mascots are correct, no placeholder/lorem text, no mojibake, and out of ~500 "Predict the output" programs the reviewers found only **four** with a wrong marked answer. The problems that matter are concentrated in a handful of *systemic* defects (section 1) plus a short list of lessons with wrong or non-compiling code (section 2).

## 1. Systemic issues (fix once, affects many files)

### 1.1 UI — "Next lesson" button is dead in 82 of 153 lessons  **[High]**
`<a href="#" class="nav-btn next disabled">` even though the next file exists. A reader cannot click through the middle of either book; the only way forward is the index page.
Affected: **C 2.5, 2.7 → 8.6** (42 lessons) and **C++ 2.5, 2.7 → 7.9** (40 lessons). Chapters 0–2.4, C 6.8–6.9, C 9–10, C++ 8–12 are fine. (C 2.5 and C++ 2.5 have `href="#"` without the `disabled` class, so they *look* clickable and do nothing.)
Also: **C 7.1** "Previous" points to 6.8 instead of 6.9.

### 1.2 UI — two lessons are completely non-interactive on load  **[High → grade D]**
**C 0.1** and **C++ 0.3** end their main script with
`document.body.innerHTML = document.body.innerHTML.replace('{{currentYear}}', …)`.
That rebuilds the whole DOM *after* every event listener and the IntersectionObserver were attached, so the quiz, the drag-and-drop / journey cards, XP, streak and the mascot bubble are all dead. Confirmed in the browser: clicking the correct answer does nothing, XP stays 0, bubble never changes; patching out that one line restores everything. (The year itself *is* replaced — the text is fine, the behaviour is not.)

### 1.3 UI — mascot bubble is one section behind in 5 lessons  **[Med]**
`BIT_LINES`/`PIXEL_LINES` has one more entry than there are sections (an "intro" line at index 0), so from section 2 on each section shows the *previous* section's line: **C 0.1, C 1.5, C 2.6, C 9.1** (lines 2–4 only), **C++ 1.5**. A few other lessons have one line on the wrong section (C 6.9 [6], C 8.1 [6], C++ 7.4 [6]).

### 1.5 Content — C++ idioms and cross-book references inside the C book  **[Med]**
The design rule is "books are independent". Found:
- Explicit pointers to the C++ book / `std::vector` / `.size()` / RAII / destructors: **C 2.3, 2.7, 3.7, 4.2, 5.1, 5.2, 6.6, 7.5** (five `std::vector` mentions incl. hero + recap), **8.2, 9.1, 10.7**.
- C++ rules taught as C: `const int N` as an array size (**C 5.1, 5.2, 10.2**), `static int n = expensive();` said to run once (**C 4.5** — it is a compile error in C), the C++ explanation for `case 1: int y;` (**C 3.2**), "namespace" used as a term (**C 2.3, 8.3**).
- Reverse direction: **C++ 7.5** stretch exercise says "(C book 7.6!)", **C++ 11.1** twice sends the reader to the C book's Part IX / binary-I/O lesson, **C++ 5.2** refers to "the previous C lesson's headache".

### 1.6 Content — concepts used before they are taught  **[Med]**
- C book: `%s`/`%d`/`scanf` before 2.8 (1.3, 2.1, 2.3, 2.5); loops before 3.3 (2.2, 2.5, 2.7); bitwise ops before 2.9 (**2.6 depends on them centrally**); arrays before 5.1 (3.4, 3.5, **3.6 stretch exercise unanswerable**); pointers/NULL before Part VI (2.5, 3.1); `malloc`/`qsort` before 7.2 (**6.9** central example); structs before Part VIII (6.6, **7.5 stretch**); `argv` before 9.5 (5.2, **9.2 stretch**); `toupper`, `time.h`, `remove`, `sleep` never taught but required (9.1, 9.3, 9.4).
- C++ book: raw pointers, `&`, `*`, `->`, `nullptr` are **never introduced anywhere** in the C++ plan, yet **2.5** (short-circuit + stretch), **2.7** (half the lesson and its whole quiz), 3.1, 5.5, 6.2 (`this`) rely on them; `std::vector`/iterators/range-for before 5.1 (2.1, 2.2, 2.3, 3.3, 3.4, 3.5, 4.1); `enum class` used as the centre of **3.2** without ever being defined; exceptions before Part X (7.8, 8.1); `noexcept` before 10.5 (8.3, 10.4); `std::variant` in the **12.2** capstone is never introduced and untagged.
- The C99 `for (int i = 0; …)` form is never introduced in **C 3.4** (the `for` lesson) but is used from 3.6 onward.

### 1.7 Content — standard/version tagging  **[Low–Med]**
- C: `0b101010` called "C99" in **2.3** (it is C23 / GCC extension — the lesson's own widget says so); `%lu` used for `size_t` throughout Part V–VII (**5.2, 5.3, 5.4, 5.5, 6.1, 6.5, 7.2** — should be `%zu`); "about 30 keywords" in 0.3, 0.4, 2.1 (C99 has 37).
- C++: `std::make_unique` is C++14, untagged in **8.5** (hero says "C++11") and **8.7**; `std::optional` untagged in **10.1, 10.6**; `std::variant` untagged in **12.2**; `noexcept`-is-part-of-the-type and one-argument `static_assert` are C++17, presented as baseline in **10.5**; `std::filesystem` untagged in 2.8; `contains()` (C++20) untagged in 3.1. **1.1/1.2** tell the reader to compile with `-std=c++20` and that "half this book" needs C++17/20 — contradicts the C++11-floor design and the standards paragraph that was supposed to explain this (planned C++ 0.5) was never written.

### 1.8 Template — C++ Part 0, VII, XI, XII drifted from TOPIC_LIST  **[Med]**
- **C++ 0.4 and 0.5** are ports of the C-book topics; the planned C++-specific topics ("types, ownership, zero-cost abstractions" and "standards in one paragraph — C++11 floor") do not exist anywhere in the book.
- **C++ Part VII**: files insert 7.5 *Virtual destructors* and 7.8 *dynamic_cast & RTTI*, shifting override/final → 7.6 and object slicing → 7.9 (10.2 still references "slicing in 7.9"; 7.3 says virtual destructors are "next lesson").
- **C++ Part XI/XII**: delivered 11.1 file streams / 11.2 string streams / 11.3 manipulators / 11.4 binary; 12.1 to-do / 12.2 JSON / 12.3 expression evaluator / 12.4 where-to-go. Planned: stream basics, file, stringstream, `std::filesystem`, `std::format`; CMake, unit tests, warnings + sanitizers, Core Guidelines, capstones. So CMake, testing, sanitizers, filesystem, format and the Guidelines are absent — and 12.4 itself lists tooling as "not covered" while its §4 says "recall Part X / 10.5" for sanitizers (nothing there).
- **C++ 12.x** (4 files) have no `READING_SYNC` block → chapter 12 progress never syncs to the cloud.
- Hero label "PART II · CORE LANGUAGE" (the C book's name) appears in C++ 2.5–2.8; 0.1–2.4 use "THE BUILDING BLOCKS".
- Every C++ lesson's mascot array is still named `BIT_LINES`/`updateBit` (display name is correctly Pixel — cosmetic).

### 1.9 Labelling  **[Low]**
📖 FROM YOUR NOTES callouts exist only in C 0.1, 1.1, 1.2, 2.1, 2.3 and C++ 0.1, 6.8. Everything else is 100 % ✨ NEWLY WRITTEN — including lessons TOPIC_LIST marks **Have** (C++ 4.1–4.4, 6.1–6.7, 6.9–6.11, 7.1–7.4, Part IX/X). #### C 2.2 — `C_Book_Lesson_2_2.html`
Grade: B
- [Med] [Pedagogy] Exercises → Medium — "Now signed int from `INT_MAX` … compile with `-Wall` — note the compiler's warning that this is undefined behavior." Also the exercise asks for "a loop" before loops are taught (3.3). → Either show `int y = INT_MAX + 1;` (constant) to trigger the warning, or suggest `-fsanitize=undefined` to see it at runtime; replace "loop" with five explicit `c++;` lines.
