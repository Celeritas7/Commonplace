🚀 PART 0 · BEFORE YOU CODE

Standards in One Paragraph

You will see things like C++11, C++17 and C++20 everywhere — in error messages, in answers online, in this book. They are just version numbers, and knowing what they mean does two useful things: it tells you which compiler you need, and it lets you tell good advice from advice that expired fifteen years ago.

1 Why this matters

A new version every three years 🗓️

C++ is not owned by a company. It is defined by a published international standard, revised by a committee on a fixed schedule: a new version every three years, named after the year it was finished.

VersionWhat it meant
C++98the first standard — this is "old C++", and a lot of the internet still lives here
C++11the big one. So large a change that people started saying "modern C++" to mean "after this"
C++14 · C++17steady polish — smaller, genuinely useful additions
C++20the second large one — new ways to write generic and concurrent code
C++23 · C++26recent; compiler support is still catching up in places

You do not need to memorise that table. You need one line from it: C++11 is the dividing line. Code written before it and code written after it look different enough that an experienced reader can date a piece of C++ at a glance — and so, shortly, will you.

That dividing line is the practical reason this lesson exists. There is an enormous amount of C++ material online written before 2011 and never updated, and none of it is labelled "warning: this is the old way". It will teach you to manage memory by hand where a modern tool would do it for you, and to write out things the standard library now does in one line. It is not wrong, exactly — it still compiles — it is just the dialect nobody writes any more, and it is much harder work.
2 What this book uses

C++11 as the floor, newer bits tagged 🏠

So which version does this book use? C++11 is the floor.

Everything taught here works on a C++11 compiler, which in practice means any compiler released in the last decade or so. You do not need a brand-new machine or the latest anything, and you will not hit "your compiler is too old" partway through Part VII.

Some things are genuinely nicer in later versions, and those appear too — clearly marked, right where they are used:

Create one with std::make_unique<T>(args) (C++14)

std::optional<T> (C++17) packs both into the return type

Concepts (C++20) let you say what a template needs

So the rule for reading this book is simple. Untagged means C++11 — it will work anywhere. A tag means "this needs at least that version", and if your compiler is older you can either upgrade it or use the plain-C++11 alternative, which the text gives you.

Why not simply teach the newest version? Two reasons, both practical. Real projects pin themselves to a version and stay there for years, so the C++ you meet at work is very often not the newest. And a feature is only useful once compilers actually implement it well — which lags the standard by a while. C++11 is the sweet spot: modern enough that everything in this book is the right way to write it, old enough that it works everywhere.
3 Telling your compiler

The -std flag ⚙️

Your compiler does not guess which version you meant; you tell it, with one flag:

g++ -std=c++11 hello.cpp -o hello      # this book's floor
g++ -std=c++17 hello.cpp -o hello      # if you want the tagged bits
g++ -std=c++20 hello.cpp -o hello      # newer still

Leave the flag off and you get whatever that particular compiler happens to default to — which differs between compilers and between versions of the same compiler. That is a genuinely annoying source of "it works on my machine": the same file, the same code, two different results, because two people's defaults differed.

Always pass the flag. Lesson 1.1 sets up your compiler and Part XII shows how to write it down once in a build file so you never type it again.

This is also how a specific and confusing error message gets fixed. If you try to use something tagged (C++17) while compiling as C++11, you will see something like:

error: 'optional' is not a member of 'std'
note: 'std::optional' is only available from C++17 onwards

That reads like the feature does not exist. It exists — you just have not asked for that version. Raise the flag and it appears.

4 Dating code at a glance

Spotting pre-2011 C++ 📅

Here is the part that will actually save you time. Once you can date C++ by looking at it, you can judge anything you read in about five seconds.

If you see…It was probably written…Modern equivalent
a bare new paired with a delete you must rememberbefore 2011a smart pointer that frees it for you
NULL or 0 for "no pointer"before 2011nullptr
a long type name spelled out where it is obviousbefore 2011auto
an index loop just to visit every itembefore 2011a range-based for
a hand-written array with a separate length variablebefore 2011std::vector, which knows its own size

Each of those right-hand entries gets a proper lesson later; the point right now is only the left-hand column. If a tutorial's examples are full of it, the tutorial is old, and you should find a different one — not because it will fail to compile, but because it will teach you habits this book will then have to undo.

A practical test for anything you find online: look for the date, and if there is not one, look for nullptr. It arrived in C++11 and is now universal in new code, so a substantial example that never uses it — and uses NULL instead — is almost certainly pre-2011. That one word is a surprisingly reliable carbon dating.
5 Two things people mix up

Newest ≠ best, and standard ≠ compiler 🧭

Two last things about version numbers that are worth having straight, because both confuse people early on.

Newer is not automatically better for you. A feature added in C++23 is of no use if the project you join is pinned to C++17, and pinning is completely normal — upgrading a large codebase's language version is a real piece of work that has to be scheduled. Knowing which version you are in matters far more than being in the newest one.

And the version of the standard is not the version of your compiler. These are two different numbers and they get mixed up constantly:

NumberWhat it isExample
the standardwhich version of the language you are writingC++11, C++17, C++20
the compilerwhich release of the program that compiles itGCC 13, Clang 17, MSVC 19.38

A newer compiler can compile older standards perfectly well — GCC 13 will happily build C++11 all day. The relationship runs one way: you need a compiler new enough to support the standard you asked for. That is the whole rule, and it is why "which compiler version do I need?" always has the same shape of answer: a recent one, and then whatever -std= you like.

8 Traps, practice, recap

Wrap up — and Part 0 complete! 🏆

Three traps to watch for 🚧

🕰️
Learning from undated material The single biggest hazard for a new C++ programmer. Pre-2011 material still compiles, so nothing warns you — it just teaches habits that are two or three times more work than the modern equivalent. Check the date; if there is none, check for nullptr.
🎚️
Leaving out -std= Without the flag you get the compiler's default, which varies by compiler and by version. That is a classic "works on my machine" — same file, two people, two results. Always pass it, and from Part XII, write it into your build file once.
🏃
Chasing the newest version C++26 is finished and C++29 is already being drafted, and neither fact helps you write your first program. Real projects pin a version and stay there for years. Knowing which version you are in beats being in the newest one.

Think it through 💪

Easy Date three pages. Search for "C++ tutorial pointers" and open the first three results. For each, find the publication date if there is one, and look for nullptr versus NULL. Write down your guess at which era each page belongs to. You are practising the most useful filter you will have for the next year.
Medium Read a version number in the wild. Find any open-source C++ project and look for the line that sets its language version — often CMAKE_CXX_STANDARD in a file called CMakeLists.txt, or a -std= in a build script. Note which version it pinned. If it is not the newest, that is the normal case, not a sign of neglect.
Stretch Look one up properly. Pick any feature name from the table in section 4 — auto, nullptr, range-based for — and find, on a reference site, the version that introduced it and what people wrote before it existed. Learning to read a reference page is a skill in itself, and it is the one that makes you independent of tutorials.

🎓 What to remember

  • C++ is revised every three years and each version is named for its year: C++98, C++11, C++14, C++17, C++20, C++23, C++26.
  • C++11 is the dividing line. "Modern C++" means after it, and the difference is large enough to date code at a glance.
  • This book's floor is C++11 — untagged code works on any compiler from the last decade. Newer features are marked (C++14), (C++17), (C++20) where they appear.
  • Tell the compiler which version you mean: -std=c++11. Never rely on the default.
  • The standard version and the compiler version are different numbers. A recent compiler builds old standards happily; you only need one new enough for the standard you ask for.
  • Check the date on anything you read. If there is no date, look for nullptr.
