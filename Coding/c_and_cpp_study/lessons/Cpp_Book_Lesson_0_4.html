🚀 PART 0 · BEFORE YOU CODE

The C++ Way of Thinking

Before a single line of syntax, it is worth knowing what this particular language is for — because C++ makes three decisions differently from almost everything else, and every strange-looking thing you meet later is one of those three showing through. They are: types, ownership, and abstractions that cost nothing.

1 Why this matters

Every language picks a side 🎛️

Every programming language is a set of trade-offs wearing a syntax. Some languages decide that your time matters more than the computer's, and quietly do a great deal of work for you. Others decide the opposite.

C++ sits firmly at the second end, and it is worth being honest about what that means before you start:

Most modern languagesC++
a background process reclaims memory for youyou decide when things are created and destroyed
a variable can hold anything; you find out at run timeevery value has a type, fixed and checked before it runs
convenient features cost a little speedthe convenient version is meant to cost nothing at all

Neither column is better. They are different answers to "who should do the hard part?", and C++ answers "you should, so that nothing is happening behind your back."

That is why C++ is what people reach for when the machine is the constraint — the engine inside a game running at sixty frames a second, the browser rendering this page, a trading system where a millisecond is money, the software inside a car. In each of those, "the language will handle it, don't worry" is not an acceptable answer.

This lesson is the map. Three ideas — types, ownership, zero-cost abstractions — and no code to memorise. When something later in the book looks fussier than it needs to be, it will almost always be one of these three asking you to be explicit about something other languages decide on your behalf.
2 Idea one

Types: promises checked before you run 🏷️

Idea one: everything has a type, and the compiler checks it before your program runs.

A type is a label on a piece of data that says what it is and what may be done with it — a whole number, a decimal, a piece of text, a list of customers. In C++ that label is fixed when you write the code, not discovered while it runs.

Think of it as the difference between a form and a conversation. Some languages take whatever you hand them and sort it out later; if it turns out you gave them a word where a number belonged, they discover that at the moment they trip over it — possibly in front of a user, six months from now. C++ is a form with labelled boxes: fill in the wrong kind of thing and the compiler, the program that turns your code into a program, refuses to proceed. You have not run anything yet. Nobody has seen it.

This is why the compiler will feel like an obstacle for your first week, and like a colleague forever after. Every "error" it gives you is a bug it found before your program was allowed to exist — and the errors it finds are the boring, mechanical, easy-to-miss kind that are genuinely hard to spot by reading. There is a reason people who have used both call this the best deal in the language.

Types buy a second thing, less obvious and just as important: speed. If the compiler knows for certain that something is a whole number, it can emit the exact machine instruction that adds whole numbers. Nothing has to be checked while the program runs, because it was all settled beforehand.

3 Idea two

Ownership: who cleans this up? 🧹

Idea two: everything that gets made has an owner, and the owner cleans it up.

Programs use things that have to be given back — a chunk of memory, an open file, a network connection. The question every language has to answer is: who gives it back, and when?

Most modern languages answer "a background process, at some point later; don't think about it." C++ answers: an owner, at a moment you can see in the code.

The analogy that fits best is a library book. Somebody borrowed it, that somebody is responsible for returning it, and if they lend it to a friend it should be clear whether they handed over the responsibility or just the book. Almost every serious C++ bug is a version of this question answered badly: nobody returned it (a leak), two people returned the same book (a double free), or someone read a book that had already gone back (use after free).

C++ has a very tidy answer, and you will meet it properly in Part VIII: an owner is an object, and when that object reaches the end of its life — the closing brace of the block it lives in — it automatically gives back whatever it was holding. On every path out. Even if something went wrong halfway through.

The consequence is that "when does this get cleaned up?" always has a precise, readable answer in C++ code, rather than "eventually". That predictability is exactly what you need when a delay of a few milliseconds at the wrong moment would drop a frame or miss a trade.

4 Idea three

Abstractions that cost nothing ⚡

Idea three: you should not have to choose between comfortable code and fast code.

There is normally a bargain in programming: the nicer a feature is to use, the more it costs while running. Writing at a comfortable level means accepting some overhead; getting the last drop of speed means writing something tedious and error-prone.

C++ was built to refuse that bargain. The design goal has a name — zero-cost abstraction — and it means: the convenient way of writing something should compile down to the same machine instructions you would have written by hand.

An example you will write in Part V, in words only. There is a standard "sort these things" operation. You use it in one line. It is not a slow, general-purpose helper that limps along inspecting your data — the compiler stamps out a version specialised for your exact type, and the result is typically as fast as, or faster than, sorting code you would write yourself. One line, no penalty.

The full slogan is worth carrying around, because it has a second half:

"You don't pay for what you don't use — and what you do use, you couldn't hand-code any better."

The first half is the one that shapes the language's personality. Features you never touch cost you nothing at all: no start-up time, no memory, no slowdown. That is why C++ can be enormous — decades of accumulated features — and still be the language people choose when every microsecond matters. You are only ever carrying the parts you actually used.

The catch, and it is a real one: nothing is checked unless you asked for it. Read past the end of a list and C++ will not stop you, because stopping you would mean checking every access, and checking every access is a cost you did not ask to pay. Part XII is about the tools that put those checks back on while you are developing — and then take them off again for the copy you ship.

5 Putting it together

Three ideas and one price ⚖️

So: three ideas, and one price. Here they are together, with what each one buys you and what it asks in return.

The ideaWhat you getWhat it asks
Types, checked earlywhole categories of bug caught before the program runs; full speedsay what things are, and satisfy the compiler first
Ownershipcleanup happens at a moment you can point todecide who owns each thing you make
Zero-cost abstractionshigh-level code at hand-written speednothing is checked unless you ask for it

Everything ahead is a consequence of that table. When you meet const, that is types making a promise stronger. When you meet destructors and smart pointers, that is ownership made concrete. When you meet templates and the standard library, that is abstraction refusing to cost anything.

And one thing that is genuinely different about learning C++ in particular. The language is over forty years old and has changed enormously — the C++ people write today looks very little like the C++ of the 1990s, and a great deal of advice written back then is still sitting on the internet looking authoritative. This book teaches the modern way from the first lesson. The next lesson explains how the versions work, so you can tell which era anything you read comes from.

7 Quick check

One question 🎯

"You don't pay for what you don't use." What does that promise actually mean for a program you write?
Hint: it is a promise about the running program's speed and memory, not about money or about how much you have to learn.
8 Traps, practice, recap

Wrap up 🏆

Three traps to watch for 🚧

😤
Treating the compiler as the enemy Your first week will involve a lot of errors, and it is tempting to see them as the language being difficult. Every one of them is a bug found before your program was allowed to run. Read the message properly — the ones in this book are chosen to teach you how — and the relationship changes.
🕰️
Learning from very old material C++ changed profoundly in 2011, and a lot of the internet did not. Advice that tells you to manage memory by hand everywhere, or that never mentions the standard library, is teaching you a dialect nobody writes any more. The next lesson gives you a way to date what you read.
🎁
Assuming something is checked for you This is the flip side of the speed. Ask for the tenth item of a five-item list and C++ will happily give you whatever was in that memory, with no complaint. Nothing is checked unless you ask, and Part XII is about the tools that let you ask.

Think it through 💪

Easy Own something. Pick anything in the room that belongs to somebody — a borrowed charger, a library book, a shared kitchen pot. Write down, in one sentence each: who owns it, when it has to go back, and what goes wrong if two people both think they own it. You have just described the three most common memory bugs in C++.
Medium Find the trade-off. Think of another language you have heard of, and find out one thing it does automatically that C++ makes you do yourself. Then ask the harder question: what does it cost to do it automatically, and when would that cost matter? There is no single right answer — the point is to notice that it is a trade rather than a mistake.
Stretch Spot the priority. Pick three programs you use often — a game, a spreadsheet, a phone app, a website. For each, guess whether it was written in a language that prioritises the machine's time or the programmer's time, and say why you think so. Then look up what it is actually written in. You will guess right more often than you expect, and the misses are the interesting ones.

🎓 What to remember

  • C++ chose control. Where other languages decide things for you, C++ hands you the decision — and the responsibility.
  • Types are checked before the program runs, which catches a whole category of bug early and lets the compiler generate fast, specific machine code.
  • Everything made has an owner that cleans it up at a moment you can point to in the code. Leaks, double frees and use-after-free are all this question answered badly.
  • Zero-cost abstraction: the comfortable way to write something should compile to what you would have hand-written. "You don't pay for what you don't use."
  • The price is that nothing is checked unless you ask. Part XII is about asking.
